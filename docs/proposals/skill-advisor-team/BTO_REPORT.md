# BTO: skill-advisor team candidate

Preconditions: ALL_GREEN for the scoped deterministic checks and three gateway
interpretation probes. Native runtime integration of this redesigned team was not run.

Method: applied the shipped BTO skill at
`packages/skills-bto/templates/.claude/skills/bto/SKILL.md`, its benchmark module and
golden samples. This is a bounded BUILD → BENCHMARK → TEST → targeted OPTIMIZE
experiment, not the full three-judge/evolutionary search protocol. No full BTO score,
trust-tier promotion or production certification is claimed.

## Baseline and build

Earlier single-advisor consultations could pass native/structural checks while
making unsupported claims. A corrective editor removed some errors but introduced
another and expanded explanation characters by 13%, 62%, and 61% on three development
cases. The design now makes editing conditional and requires a fresh full-payload
review after one repair at most.

## Measured checks

- B0: actual golden-structure comparison and deviations in
  `benchmark-deterministic.json`. A reference-based protocol replaces module files;
  no artificial composite is inferred from ambiguous golden section counts.
- B1: six deterministic skill checks passed; native `dz list`/`info` found the skill.
- B2: three fresh stateless Haiku probes, nine interpretation checks each, 27/27
  matched expected policy. This measures interpretation consistency, not quality
  of recommendations or native agent spawning.
- B3: file sizes, section proportions, linked resources and explicit token-density
  proxies are recorded in the deterministic report. No measured tokenizer throughput.
- 34 local regression tests passed across catalog, review binding and orchestration.
- npm pack dry run includes all new skill support files; no npm publication.
- Independent cross-model challenge/code critique by gpt-6-astra: no confirmed
  blocking/high/medium findings after corrections. One critic, not a full panel.

## Live development trials and optimization

Used the three historical feature/research/Cloud.ru candidate-source sets with
fresh stateless Haiku gateway calls for every role. These are limited candidate
subsets, not live full-catalog or native E2B sessions. Sources are labelled excerpts.

1. `live-team-smoke.json`: 0/3 released; all failed selection validation. The adapter
   omitted exact output schema constraints and responses used fit=primary/complement
   and prose pipelines. Added explicit schema loading, enum and array instructions
   to the skill and adapter.
2. `live-team-smoke-v2.json`: selection advanced, but all failed at review. The
   experimental gateway responses returned non-stop (incomplete) completions under
   a configured 5,000-token output cap; their exact terminal reasons were not retained. Raw model reasoning was neither stored nor published.
3. `live-team-smoke-v3.json`: final bounded trial raised completion limit to 12,000.
   No response released: feature/Cloud.ru reviews contained unverified source quotes;
   research selection was structurally invalid. The exact quote gate remains intact.

These failures are not evidence that the team improves semantic accuracy. They show
that the host withholds invalid results. No additional unbounded retries were used.
Known Cloud.ru editor regression was also submitted separately; see regression
artifact and independent review for the result. The supplied cheap gateway adapter
still needs calibration and positive live acceptance before site integration.

## Decision

Deliver as a **draft PR**: executable host-bound candidate, documented skill protocol,
regression tests and reproducible evidence inputs. Remaining acceptance work: native
runtime adapters with actual fresh-session/cancellation handling, positive held-out
semantic cases, rejection of introduced false claims, observed latency and billing,
and trusted course-link integration. Preserve existing package versions/signatures
until canonical-source release. Do not advertise the advisor as production-ready.
