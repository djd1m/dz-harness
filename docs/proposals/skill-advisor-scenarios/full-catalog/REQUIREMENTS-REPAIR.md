# Requested requirements and documented details

The candidate now recognizes sequential parenthesized tasks and retains exact registered skills from the raw search even if package grouping drops them. Numbered negative constraints and response-format instructions stay in the original request without consuming action slots. Each covered action is shown with its chosen card. The selector can supply up to three short verbatim documentation excerpts. The host binds each excerpt to the selected record and action and checks it against the literal evidence presented to that selector. A retrieved atomic card outside the action's ranked hints can qualify with such a validated excerpt. Direct physical work remains outside action coverage.

Visible details are optional for compatibility. Older answers still display. The interface uses text nodes for excerpts, and links continue to come from the site mapping. The server records bounded rejection reasons without prompts, excerpts or provider responses. This contract verifies provenance. Semantic review still checks whether a valid excerpt actually supports the requested detail.

This is a small diagnostic trial, separate from [wide acceptance](WIDE-ACCEPTANCE.md). All modes use the same approved cards and 8,926-document snapshot. Dense-only and hybrid use the same saved BGE-M3 query vectors. Search counts require every exact curated skill or package in each task's retrieval labels. Semantic review also requires the requested details and scope to appear in the answer.
