# Кросс-семейное делегирование: Claude как ведущий, Codex как независимый ревьюер

Выжимка практики dz-harness на 14.09.2026. Всё ниже — не рекомендации из головы, а то, что измерено на живых прогонах (даты и цифры рядом). Документ самодостаточен: его можно перенести в любой проект без остального контекста.

## 1. Зачем две семьи моделей

**Кросс-семейное QE** — правило, по которому модель той семьи, что писала код, никогда сама его не проверяет. Причина измерена: самопроверка Codex дважды сказала «чисто» там, где независимый Claude нашёл 7 дыр (2 высокие); и наоборот — Codex на патче Claude находит по 5–9 дефектов за круг, из них 1–2 несущих. Семья определяется по модели, не по хосту: кодер Claude ⇒ ревьюер Codex, кодер Codex ⇒ ревьюер Claude.

## 2. Кто что делает (текущая раскладка)

| Роль | Модель | Почему именно она (измерено) |
|---|---|---|
| Ведущий: план, ADR, приёмка, тонкая дискриминация, steel-man | Claude Fable 5.1 (`claude-fable-5-1`) | самая сильная; дорогая — только там, где нужна |
| Кодер S/M-фич и фикс-раунд | Claude Sonnet 5 (`claude-sonnet-5`) | 0,3–0,5 M токенов на фичу, 25–55 мин; честно называет отклонения от брифа |
| Обёртки вокруг Codex, релизная рутина, файлинг бэклога | Claude Opus 5 (`claude-opus-5`) | дешевле Fable там, где не нужна дискриминация |
| Роутер тира, дешёвые писатели чекпоинтов | Claude Haiku 4.5 | effort-low агенты по 1–3 k токенов |
| Независимый ревьюер патча (QE) | Codex `gpt-5.6-sol`, effort `high` | 30–35 k токенов и 3–8 мин на scoped-круг; находит то, что автор не видит |
| Дизайн-критика, steel-man ADR | Codex `gpt-5.6-sol`, effort `xhigh` | глубже, дороже; только на развилках дизайна |
| Эко-режим ревью | Codex `gpt-5.6-terra`, `medium` | когда бюджет важнее глубины |
| Массовые дешёвые проверки | Codex `gpt-5.6-luna` | high-volume тир |
| Запасной | Codex `gpt-5.5` | если sol недоступен |

Важно: идентификаторы моделей Codex зависят от аккаунта и дрейфуют в обе стороны. Голый `gpt-5.6` на ChatGPT-аккаунте отвечает HTTP 400. Перед каждым прогоном — живая проба: `codex exec -m <id> "Reply with exactly: OK"`. Список «разрешённых» имён в конфиге — не проверка доступности.

## 3. Как правильно отдать задачу Codex

**3.1. Синхронно, а не через обёртку.** `codex exec` возвращает текст модели на stdout. Обёртка-субагент «codex-rescue» отдаёт заглушку сразу после диспатча — годится только для стадий, где результат — файл на диске за барьером «код приземлился», и никогда для ревью или роутинга (заглушка читается как «чистое ревью»).

**3.2. Область, а не таймаут.** Бюджет Codex уходит на разведку дерева, не на рассуждение. Один и тот же вопрос той же модели: без ограничения области — 280 с, обрыв по таймауту, вердикта нет; со словами «читай ТОЛЬКО этот патч, других файлов не открывай» — 41 с и вердикт. Поэтому патч кладётся прямо в промпт:

```bash
{ cat prompt-head.txt; echo;
  git diff -- <изменённые файлы>;
  git diff --no-index /dev/null <новый файл>; } > /tmp/prompt.txt
```
За ночь 14.09 промпты 25–93 КБ проходили за 3–8 минут.

**3.3. Для чисто рассудочных вопросов — запрет инструментов явно.** Префикс «Answer directly from this prompt text alone; no commands, no files, no tools» превращает 240-секундные зависания в ответы за 8–11 с.

**3.4. Вызов, который работает** (из нейтрального каталога вроде `/tmp`, stdin из `/dev/null` — иначе exec ждёт ввод):

```bash
cd /tmp && nohup codex exec --skip-git-repo-check --sandbox read-only \
  -c model=gpt-5.6-sol -c model_reasoning_effort=high \
  "$(cat /tmp/prompt.txt)" < /dev/null > /tmp/review.log 2>&1 &
echo $! > /tmp/review.pid
```
Модель задаётся через `-c model=…`; `codex review` не принимает `-m` и не принимает позиционный промпт вместе с флагами области (`--commit`, `--uncommitted`).

**3.5. Контракт вердикта.** В промпте: «закончи ровно одной строкой `Grade: <A-F>` и одной строкой `Verdict: MERGE | FIX-ROUND | REJECT`». Читать ответ после последней строки `^codex$` в логе — лог эхом повторяет промпт, поэтому `grep -c Grade` считает лишнее.

**3.6. Ждать по PID, не по фразе.** Сторож `while pgrep -f "<фраза промпта>"` находит собственный процесс и никогда не выходит (измерено: 26 минут ложного ожидания). Правильно: `while kill -0 $(cat /tmp/review.pid) 2>/dev/null; do sleep 15; done`.

**3.7. Скажи ревьюеру, чего он не видит.** Codex видит только патч. Если реестр защит, регенерированные хелперы или измерения не вошли в патч — он честно напишет «NOT FIXED» или «регенерации нет», и это будет ложью по построению. Перечисли исключённое во вводной. Отдельно перечисли **названные пределы** с формулировкой «do not re-raise», иначе они вернутся в каждом круге.

**3.8. Песочница Codex — только чтение, ресурсы вне рабочей копии недоступны.** Векторный стор под WAL в read-only монтировании не откроется; заземление из книг/памяти передаётся ДАННЫМИ в промпте, не поручением «запроси корпус».

## 4. Как отдать задачу Sonnet-кодеру

- **Бриф — файл, и он же контракт.** План с `EXPECTED_CODE_TARGETS`, задачи T1…Tn, поправки `AM-n … → test <имя> in <путь>`. Кодер читает только его и названные файлы.
- **Уроки — в текст брифа.** Кодер не видит вашего стора памяти; `dz recall "<тема>"` делает ведущий и вставляет найденное словами.
- **Жёсткие правила списком:** без `git stash/checkout --/restore/clean`, без `pkill`, без коммитов и публикаций, без полных наборов (их гоняет ведущий), гейты только штатной командой, красная база — дословно в манифест, а не «обошёл».
- **Красный-первым и квитанции.** Каждое число рядом с командой; «мутация легла» доказывается строкой гейта `PROVEN failing≥1`, не словами.
- **Один кодер за раз** на общем `dist/` — параллельные пересборки дают ложные вердикты в обе стороны.
- **Один фикс-раунд.** После второго круга ревью остатки правит ведущий или называет пределами с записью в бэклог.

## 5. Что ревью не заменяет: приёмка ведущего

1. Пересобрать `dist` (застоявшийся dist лжёт в обе стороны).
2. Целевые тесты, затем мутационный гейт по одной записи штатной командой (базу RED — разобрать по трём честным причинам: нет `observed`, храповик импортов, короткий таймаут).
3. **Живая проба на настоящем репозитории.** Три круга Codex не увидели ложный дрейф файла `LICENSE`, который подкладывает `pnpm pack`, — его показал только живой `dz publish --dry-run` (14.09). Ревью читает патч, приёмка гоняет команду.
4. Полные наборы отдельным процессом с квитанцией-файлом; пульс-таймер каждые 10 минут, пока есть незакрытая работа.
5. Урок — в стор (`dz teach`) в том же ходу, где назван; иначе он повторится.

## 6. Шпаргалка

```bash
# 1. проба модели
codex exec -m gpt-5.6-sol "Reply with exactly: OK"
# 2. промпт = вводная + патч
{ cat head.txt; echo; git diff -- a.ts b.test.ts; git diff --no-index /dev/null new.test.ts; } > /tmp/p.txt
# 3. запуск + PID
cd /tmp && nohup codex exec --skip-git-repo-check --sandbox read-only -c model=gpt-5.6-sol \
  -c model_reasoning_effort=high "$(cat /tmp/p.txt)" < /dev/null > /tmp/r.log 2>&1 & echo $! > /tmp/r.pid
# 4. ожидание по PID и вердикт
while kill -0 $(cat /tmp/r.pid) 2>/dev/null; do sleep 15; done
awk '/^codex$/{p=1;b=""} p{b=b $0 "\n"} END{printf "%s", b}' /tmp/r.log | grep -E "^Grade:|^Verdict:"
```
