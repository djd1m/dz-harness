# decision-mockups — контекст и ответ владельца

Помогите человеку понять задачу, последствия и нужный ответ. Формат зависит от вопроса:
простая локальная развилка может остаться коротким текстом; несколько связанных решений
удобно собрать в HTML. Для инженера сокращайте очевидные объяснения, сохраняя цену и основания.
Учебные случаи пакета синтетические; факты своей задачи проверяйте по источникам.

## Сначала содержание

До вариантов назовите задачу, сделанное и оставшееся, почему решение нужно сейчас,
ограничения, существенные риски/неизвестное и точный требуемый ответ. Пустые категории
допустимы: «не выявлено» лучше выдуманного риска. Критическое не прячьте в details;
дополнительные источники могут жить под осмысленным summary.

Различайте факт с источником, оценку с базой/диапазоном, допущение и неизвестное,
которое меняет выбор. Непроверенное помечайте «не проверено». Нет данных — можно
запросить их или отложить вопрос. Подробности языка: [language-guide](references/language-guide.md).

Оставьте минимум две жизнеспособные альтернативы: цена/последствие каждой, почему
рекомендуется одна и когда полезна другая. Если оснований недостаточно, явно скажите,
почему рекомендации пока нет. Доминируемую ветку уберите и объясните причину/допущения;
не рисуйте отказ без полезного исхода. Рекомендация никогда не предвыбирает ответ.
Карточка находки: что не так → чем грозит → как чиним.

## Выберите способ объяснения

| Что отличается | Формат |
|---|---|
| Экран, подпись, расположение | CSS-пара «как сейчас / после», одна заметная разница |
| Порядок взаимодействий/доставки | Семантическая HTML-схема последовательности или потока |
| Ответственность/граница | Схема компонентов с границей и поведением при отказе |
| Несколько критериев | Таблица |
| Простой локальный выбор | Компактный текст |

У схемы рядом есть текст, объясняющий порядок, направление, границу и существенный
отказ/условие. Имена компонентов совпадают с контекстом/экспортом. Никакого внешнего
рендерера или сетевых ресурсов. Рецепты: [mockup-kit](references/mockup-kit.md),
[product/backend/compact cases](examples/context-cases.md).

## Компактный ответ и v2

Для ответов, связанных с версией условий, прочитайте [answer-contract](references/answer-contract.md).
Он задаёт закрытую схему, подготовку, отдельный JSON ответов и границы приёма.
В манифест входят все существенные основания/стоимости/исключения; изменение их меняет revision.
Автор запускает `check_answer.py --prepare`; получатель проверяет свой текущий манифест
и весь отдельный документ ответов. Приём не чинит хеш и не принимает манифест отправителя
как текущий. Устаревший ответ требует повторного подтверждения всей страницы.

В коротком тексте покажите контекст, полные названия вопросов/вариантов, состояния,
pageId/revision и инструкцию из answer-contract. Человек отвечает названиями, не пишет
JSON и не копирует хеш. Агент составляет envelope только по однозначному явному ответу,
связанному с записанной показанной версией. A/«да»/«рекомендация», повторяющиеся названия
или неясная привязка требуют уточнения. Пропущенное остаётся unanswered. Без доверенного
текущего манифеста проверка ожидает. Выбор не означает выполнение.

Компактная ветка не требует HTML, artifact-design, CSS, сводных метрик/S/M/L или HTML gate.
Используйте подготовку/приём JSON и смысловой список: полнота контекста, основания,
настоящие альтернативы, понятная инструкция. Это не автоматическое понимание языка.

## HTML из существующего шаблона

Для полной страницы загрузите доступный `artifact-design`, чтобы подобрать оформление.
Если его нет, используйте существующий шаблон и назовите этот запасной путь; установка
нового навыка не нужна. Заполняйте [page-skeleton](templates/page-skeleton.html) по секциям,
сохраняя палитру/темы/панель. Полная страница может включать сводку важности и размера
по известным оценкам; не выдумывайте срок/метрику ради шаблона. Все заглушки заменяются.
Страница — HTML-фрагмент с title; оболочку добавляет хост.

V2 включается единственным инертным `decision-manifest` с подготовленным JSON. Группы
и варианты используют стабильные ID и видимые label-узлы, три отдельные кнопки состояния
дают deferred/needs-data/unanswered. Точные маркеры и пример — в answer-contract/context-cases.
Не вкладывайте группы/контролы; произвольные ID остаются данными, без динамических селекторов.
Панель считает только selected; отложенный вопрос/запрос данных тоже можно экспортировать.
Текст содержит существенный контекст; readonly JSON поле — полный машинный документ.
Не извлекайте candidate JSON из подписей, цитат и ограждений.

Без манифеста действует прежний режим: `data-group`/`data-label`, кнопки `data-val`,
свой ключ хранения, тема/дата, частичный текст с «Без ответа». Его примеры и байты экспорта
сохраняются в [examples/README](examples/README.md). Старые ответы не доказывают версию;
переход в v2 требует явного подтверждения. V2 хранение отдельно и не мигрирует старые строки.

## Проверка и передача

- HTML: обязательно запустите `python3 references/check_page.py page.html` на точном
  конечном файле перед передачей/использованием и после последней правки. 0 зелёный, 1 отказ, 2 ошибка вызова.
  [quality-checklist](references/quality-checklist.md) объясняет проверки. Ноль групп по-прежнему
  даёт G6a; не выдумывайте выбор ради зелёного статуса страницы-объяснения.
- V2 JSON: prepare, затем реальный `check_answer.py current-manifest.json answer.json`.
- В браузере: Tab/Shift+Tab/Enter/Space, повторный выбор, все состояния, сброс/фокус,
  сохранение/отказ хранения, обе темы и узкая ширина, disclosure, доступные имена,
  контраст, видимость существенного текста/его вложенных частей и отсутствие попыток внешних запросов.
  Активный пикер не доказывает проверку исходного HTML: браузер стирает повторные атрибуты.
  Пикер отдельно проверяет наблюдаемый DOM, JSON и показанный контекст, повторяя проверку
  перед выбором/экспортом. CSS-видимость требует браузера; DOM-адаптер не доказывает хост/AT.
- Независимое чтение: настоящие альтернативы, честные источники/оценки и неизвестное;
  текстовый экспорт понятен без HTML. Скрипт проверяет структуру, не истинность/пользу.

Передайте согласованный артефакт/текст, краткую инструкцию ответа и объяснение убранных
мнимых развилок. При обновлении сохраняйте путь/идентичность страницы; публикуйте в
запрошенном доступном хосте. Изменения рекомендаций сами по себе не утверждают действие.
Поведенческие задания: [eval-cases](evals/eval-cases.md). Человеческий эффект требует пилота,
его нельзя выводить из числа зелёных тестов.
