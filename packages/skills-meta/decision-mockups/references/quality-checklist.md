# Чек-лист перед публикацией страницы решений

Детерминированная самопроверка. Запускается **до** вызова `Artifact`, на готовом HTML-файле.

Принцип — «лестница стоимости обнаружения»: каждая проверка живёт на самом сильном слое,
который способен её выразить. Всё, что можно посчитать `grep`'ом или регуляркой, **обязано**
проверяться скриптом, а не «ревьюер заметит». Ревьюеру остаётся только то, что машина
принципиально не выражает: тон, метафора, честность формулировки.

| Слой | Что здесь проверяется | Кто исполняет |
|------|----------------------|---------------|
| 1. Скрипт (блокирующий) | баланс тегов, токены, темы, CSP, развилки, экспорт | `check_page.py`, код возврата 1 |
| 2. Скрипт (мягкий) | цена варианта, ширина, число токенов | `WARN` — прочитать глазами |
| 3. Человек | простой русский, метафора, «частично», рекомендация | автор перед публикацией |

## Как запускать

```bash
python3 <путь-до-скилла>/references/check_page.py путь/к/странице.html
# 0 — можно публиковать
# 1 — блокирующее падение, публикация запрещена
# 2 — ошибка вызова (нет аргумента / файла): исправить команду и повторить
```

Путь к скрипту — от корня скилла, не от директории проекта; из чужой директории зовите
абсолютным путём. Зависимостей нет, только стандартная библиотека Python 3.

**Источник правды — сам файл `references/check_page.py`.** Ниже разобрано, что проверяет
каждое из ворот и почему; кода здесь нет намеренно. Полная копия скрипта в этом документе
жила ровно до первой правки скрипта — после неё документ начинал уверенно описывать ворота,
которых уже нет, и был при этом единственным местом, куда заглядывают.

**Комментарии не считаются разметкой.** Перед проверкой скрипт вырезает HTML-комментарии
(`<!-- … -->`) и блочные комментарии JS/CSS (`/* … */`). Иначе примеры разметки, которые
шаблон и `picker.js` носят в комментариях (`data-group="…"`), считались бы настоящими
развилками и давали фантомные падения G6b/G9. Строчные `//` не трогаются: под них попали бы
протокол-относительные URL, которые обязан ловить G5.

**Форматирование CSS не проверяется.** `:root{` и `:root {` равноправны, кавычки в
`[data-theme="dark"]` — любые. Ворота ловят отсутствующую тему, а не стиль отступов.

## Блокирующие ворота

Ни одно из них нельзя «объяснить»: красное — значит не публикуем.

### G1 · Баланс `<div>`

Самая частая поломка при инкрементальной сборке: один незакрытый `div` съезжает всю сетку
вниз по странице, и мокапы уезжают внутрь карточек находок.

```bash
python3 -c "import re,sys;s=open(sys.argv[1],encoding='utf-8').read();print(len(re.findall(r'<div\b',s)),len(re.findall(r'</div\s*>',s)))" page.html
# два числа должны совпасть
```

Мягко (`WARN`) то же самое считается для `section`, `figure`, `aside`, `ul`, `li`, `p` —
там несовпадение бывает законным (`<p>` без закрытия валиден в HTML).

### G2 · Ноль цветовых литералов вне токенов

Классический баг нечитаемого артефакта: компонент получил `#fff` напрямую, в тёмной теме
белое осталось белым. Правило: **литерал цвета допустим только внутри блока объявления
токенов**; всё остальное читает `var(--…)`.

```bash
python3 -c "
import re,sys
st=re.search(r'<style>(.*?)</style>',open(sys.argv[1],encoding='utf-8').read(),re.S).group(1)
rest=re.sub(r':root[^{]*\{.*?\}','',st,flags=re.S)
print(sorted(set(re.findall(r'#[0-9a-fA-F]{3,8}\b|\brgba?\(|\bhsla?\(',rest))) or 'OK')
" page.html
```

Вырезаются **только три легальных селектора темы** (`:root{`, `:root:not([data-theme="…"]){`,
`:root[data-theme="…"]{`), нежадно до первой закрывающей скобки — вложенных скобок внутри них
нет. Широкая маска `:root[^{]*\{` была дырой: под неё подходил и обычный селектор-потомка
`:root .browser { background:#ffffff }`, то есть любой компонент мог объявить себя «блоком
токенов» и унести свои литералы из-под G2.

Разбираются **все** блоки `<style>`, а не первый: палитра во втором блоке была невидима
для G2 и G3 целиком.

**G2b — литералы в `style="…"`.** Инлайновый атрибут — тот же цвет мимо токена, только
мимо `<style>` вообще. Путь живой: инлайновые отступы на странице уже есть, цвет
дописывается рядом одной правкой.

```bash
grep -o 'style="[^"]*"' page.html | grep -E '#[0-9a-fA-F]{3,8}|rgba?\(|hsla?\(' || echo OK
```

### G3 · Все три темовых блока и одинаковый набор токенов

Обязательны ровно три объявления одного и того же набора имён:

1. `:root{…}` — полная светлая палитра, на голом селекторе;
2. `@media (prefers-color-scheme: dark){ :root:not([data-theme="light"]){…} }` — системная тема;
3. `:root[data-theme="dark"]{…}` — явный переключатель.

```bash
grep -cE '^:root *\{'                    page.html
grep -c  'prefers-color-scheme'          page.html
grep -cE ':root\[data-theme="dark"\] *\{' page.html   # каждая строка должна дать 1
```

Скрипт дополнительно сверяет **паритет имён**: множество `--token` в трёх блоках обязано
совпадать. Токен, объявленный только в светлом блоке, — это и есть будущая «невидимая
надпись в тёмной теме».

Отдельным воротом (**G3d0**) проверяется, что светлый блок вообще содержит хоть один
`--token`. Без него сравнение трёх пустых множеств формально сходится, и страница совсем
без палитры проезжала бы паритет с сообщением «наборы не совпадают; разница: `[]`» —
текстом, который ничего не сообщает.

**G3g / G3h — значения, а не только имена.** Паритет имён (G3d/G3e) ничего не говорит
о цветах. Самая вероятная ошибка сборки — «скопировал блок, поменять цвета забыл»: имена
совпадают идеально, а тёмная тема светлая. Скрипт требует, чтобы в каждом тёмном блоке
отличалось значение хотя бы одного базового токена (`--bg`, `--ink`, `--surface`, `--border`
и синонимы); если базовых имён нет — чтобы отличалась хотя бы четверть набора.

```bash
python3 references/check_page.py page.html | grep -E 'G3g|G3h'   # пусто = тёмная тема настоящая
```

### G4 · У `body` явный фон-токен

```bash
python3 -c "import re,sys;m=re.search(r'\bbody\s*\{([^}]*)\}',open(sys.argv[1],encoding='utf-8').read(),re.S);print('OK' if m and re.search(r'background(-color)?\s*:\s*var\(--',m.group(1)) else 'FAIL')" page.html
```

Прозрачный `body` берёт фон хоста — страница в тёмной теме получит светлый текст на светлом.

### G5 · Ноль внешних ресурсов

CSP артефакта режет любой внешний хост. Запрещено: `src`/`href` на `http(s)://` или `//`,
`@import`, `url(http…)`, `@font-face`, а также сами теги `img`/`iframe`/`video`/`audio`/
`link`/`object`/`embed`. Мокапы — чистые HTML+CSS, иконки — символы или CSS-фигуры.

```bash
grep -nE '(src|href)="(https?:)?//|@import|url\(["'"'"']?https?:|@font-face|<(img|iframe|video|audio|link|object|embed)\b' page.html || echo OK
```

Внимание: текст вида `copilot.cloud.ru/mgr-insights` внутри `<span class="url">` мокапа —
это **надпись**, а не ресурс. Проверять надо атрибуты, а не любое вхождение домена.

### G6 · Уникальность `data-group`, непустой `data-label`

Дубль идентификатора — это две развилки, которые молча перетирают ответ друг друга
в `localStorage`; в экспорте одна из них исчезает.

```bash
grep -o 'data-group="[^"]*"' page.html | sort | uniq -d   # пусто = OK
grep -c 'data-label=""' page.html                          # 0 = OK
```

### G7 · Каждый `data-val` непустой, короткий, уникальный внутри группы

`data-val` попадает в экспорт дословно — это готовая строка ответа, а не описание.
Порог: до 120 символов. Плюс каждый вариант обязан быть клавиатурным:
`role="button"` **и** `tabindex="0"`.

```bash
python3 -c "
import re,sys
s=open(sys.argv[1],encoding='utf-8').read()
print([v for v in re.findall(r'data-val=\"([^\"]*)\"',s) if not v.strip() or len(v)>120] or 'OK')
print([t[:70] for t in re.findall(r'<[^>]*data-val=\"[^\"]*\"[^>]*>',s) if 'tabindex=\"0\"' not in t or 'role=\"button\"' not in t] or 'OK')
" page.html
```

### G8 · Счётчик развилок берётся из DOM

Число «из M» **нельзя** писать руками. Требуется: (**G8a**) на странице есть слот счётчика
(`#pb-total` или настроенный `totalId`) и (**G8**) этому слоту присваивается ДЛИНА коллекции
узлов. Обе формы засчитываются:

```js
document.getElementById('pb-total').textContent = String(groups.length);  // инлайн-скрипт
totalEl.textContent = String(groups.length);                              // templates/picker.js
```

```bash
grep -cE '\.textContent *= *(String\()?[A-Za-z_$][\w$.]*\.length' page.html   # >=1 = OK
```

Проверяется **намерение**, а не одна строчка кода: имя переменной и форма обёртки не важны.
Но присваивание обязано быть привязано **к слоту счётчика**. Формулировка «где-то на странице
встречается `…textContent = ….length`» была непровальной: достаточно зашить `= '17'` в сам слот
и оставить любой посторонний `.length` рядом — и ворота зеленели на выдуманной цифре.

```bash
grep -nE "(getElementById\(['\"]pb-total['\"]\)|totalEl)\.textContent *= *[^;]*\.length" page.html
# >= 1 = OK; ноль при наличии слота = FAIL
```

**G8b (мягкое) — статическая цифра в разметке слота.** JS её перетрёт, но до запуска JS
читатель видит написанное руками число. В эталонной странице зашито
`<span id="pb-total">16</span>`, а развилок **17**: ручной счёт разошёлся с реальностью,
и спасло ровно то, что JS успевает переписать цифру. В слот ставится `0`.

### G9 · У каждой развилки не меньше двух живых вариантов

Развилка с одним вариантом — **мнимая**. Это не выбор, а уже принятое решение,
которому пририсовали кнопку. Её надо убрать из пикера и оставить как рекомендацию
в тексте: пользователь не должен «выбирать» там, где выбора нет.

```bash
python3 references/check_page.py page.html | grep G9   # пусто = мнимых развилок нет
```

**Тело развилки считается по вложенности, а не по позиции в тексте.** Раньше телом считался
кусок «от `data-group=` до следующего `data-group=`», и это была дыра ровно в тех воротах,
которые скилл продаёт громче всего: любой декоративный элемент с `data-val`, стоявший НИЖЕ
развилки, засчитывался ей в варианты — одноопционная развилка с посторонним чипом после неё
проходила G9 зелёной. Тело последней развилки при этом тянулось до конца файла вместе со
скриптом. Теперь берётся настоящее поддерево элемента: от открывающего тега до парного
закрывающего, с подсчётом вложенности.

**G6a не зависит от порядка атрибутов.** `data-label` перед `data-group` — валидная разметка;
прежняя маска на ней сообщала «на странице нет ни одной развилки» при живых развилках, а
остальные ворота ту же развилку видели. Развилка ищется как элемент, метка достаётся из тега.

**G7e (мягкое) — `data-val` вне развилок.** Такой элемент выглядит вариантом, но пикер его
не видит: клик мёртвый. Он же — самый дешёвый способ замаскировать мнимую развилку.

### G10 · Каждый вариант называет свою цену

Вариант, который прячет стоимость или переделку, — реклама, а не выбор.
Проверка разложена на три уровня:

* **G10a (детерминированно)** — развёрнутый вариант в `.opts.pickable` обязан открываться
  жирным вердиктом: `<b>Вариант A — рекомендуем.</b>`, `<b>Альтернатива — доделать.</b>`,
  `<b>Вариант B — отклонён.</b>`. Регулярка: `^\s*<b>[^<]{3,70}</b>`.
* **G10b (детерминированно)** — у чип-развилки `.picks` цена живёт не в чипе (он короткий),
  а в `<p class="rec">` той же карточки. Скрипт требует наличия `.rec` в каждой `.qcard`
  с чип-развилкой.
* **G10c (глазами)** — список вариантов, в тексте которых нет ни одного слова о цене,
  сроке, риске или потере. Скрипт печатает их как `WARN`; автор читает и решает.
  Слова `рекоменд` и `отклон` из словаря цены **убраны**: это ярлыки варианта, а не его цена,
  а шаг 4 сам предписывает писать «рекомендуем» — с ними ворота были непровальными, любой
  собранный по инструкции вариант зеленел, ничего не сказав о стоимости. Стемы правились
  под живые формы («дороже», «требуется»): `дорог` не матчит «дорож`е», `потребует` не матчит
  «требуется» — оба давали ложный `WARN` на вариантах, которые цену называли прямо.
* **G10d (детерминированно, покрытие)** — каждая развилка обязана быть покрыта хотя бы
  одним из первых двух способов.

Класс варианта читается **по токенам**, а не префиксом: `class="suggest opt"` — тот же `.opt`,
а маска `class="opt[^"]*"` его не видела и молча выпускала из проверки цены. Текст варианта
берётся целым поддеревом: обрезка «до первого `</div>`» теряла всё, что стояло после вложенного
элемента, — вместе с ценой, если она там.

G10d существует потому, что G10a и G10b **условны**: первый смотрит только на `div.opt`,
второй — только внутрь `div.qcard`. Развилка любой другой формы не проваливала ни одну из
них — она просто выпадала из проверки, и ворота «каждый вариант называет цену» молча
зеленели. Проверка, которая не может покраснеть, — это шум; G10d возвращает ей зубы:

```bash
python3 references/check_page.py page.html | grep G10d   # пусто = все развилки покрыты
```

На эталонной странице покрытие полное и без G10d — 13 развилок через `.rec`, 4 через
`div.opt`, 17 из 17. Это совпадение формы одной страницы, а не свойство ворот.

### G11 · Экспорт самодостаточен

Вставленный в свежий чат текст обязан объясняться сам. Требуется:

| Требование | Проверка |
|-----------|----------|
| первая строка называет тему и дату | литерал `'Решения по …(` в сборке экспорта |
| ответы подписаны человеческими метками | используется `getAttribute('data-label')` |
| перечислены неотвеченные развилки | строка `Без ответа: …` |
| буфер обмена с фолбэком | `navigator.clipboard` **и** `execCommand` |
| подтверждение копирования | текст `Скопировано ✓`, возврат через 2 с |

**G11b проверяет намерение, а не имя переменной.** Прежняя маска требовала дословного
`lines = ['Решения по …(` — конкретное имя переменной, одинарные кавычки, — и краснела на том
же коде, переписанном на шаблонную строку с тем же выводом. Это ровно та ошибка, за исправление
которой хвалит себя G8 сорока строками выше. Теперь достаточно строкового литерала
`Решения по …(` в любых кавычках. Русские литералы намеренны: скилл русскоязычный, и ворота
G11b/G11d/G11f это фиксируют.

Проверять надо каждую строку отдельно: суммарный `grep -c` по пяти шаблонам даёт число
без порога — такую «проверку» нельзя провалить, и она не значит ничего.

```bash
for pat in exportText 'Без ответа' navigator.clipboard execCommand Скопировано; do
  printf '%-22s %s\n' "$pat" "$(grep -c -- "$pat" page.html)"
done   # каждая строка должна дать >= 1; ноль хотя бы в одной = FAIL
```

### G13 · В странице не осталось заглушек шаблона

`ЗАМЕНИТЬ`, `<тема>`, `<дата>`, `TODO`, `Lorem ipsum` — самый вероятный и самый дорогой
по репутации провал заполняемого шаблона: одна такая строка обесценивает всю страницу
в глазах владельца. Это одна регулярка, и держать её на внимательности агента — держать
на самом слабом слое лестницы.

```bash
grep -nE 'ЗАМЕНИТЬ|<тема>|<дата>|TODO|Lorem ipsum' page.html || echo OK
```

Сюда же попадает дефолтный ключ `localStorage` из `templates/picker.js`
(`ЗАМЕНИТЬ-picks`): общий ключ означает, что вторая страница решений у того же читателя
подхватит ответы первой, а экспорт увезёт ответы на вопросы, которых на странице нет.
Ключ обязан быть своим — и заглушка не даст об этом забыть.

**`templates/page-skeleton.html` намеренно проваливает G13.** Незаполненный шаблон
не должен считаться публикуемым; это встроенный отрицательный контроль ворот.

### G14 · Никакой оболочки документа, но есть `<title>`

`Artifact` оборачивает файл в `<!doctype><html><head>…<body>` сам. Своя оболочка даёт
документ внутри документа. Из этой же конструкции следует и весь запрет внешних ресурсов:
страница живёт под CSP артефакта. `<title>` наоборот обязателен — им называется вкладка
и карточка в галерее.

```bash
grep -niE '<!doctype|<html|<head[ >]|<body' page.html || echo OK
grep -c '<title>' page.html   # 1 = OK
```

### G15 · Ни одной технической кальки в тексте страницы

Технические кальки протекают из внутренних артефактов (сводок, отчётов QE, логов) в текст
для владельца и убивают ровно то понимание, ради которого страница делается. Правило:
**если слово существует только внутри нашего инструментария — на этой странице его нет.**

Ворота смотрят только то, что владелец **читает**: `<style>`, `<script>`, HTML-комментарии
и сами теги забиваются пробелами той же длины, поэтому строка и позиция в сообщении
совпадают с исходным файлом. Находка называет позицию, слово и простую замену:

```
FAIL  G15 строка 342, поз. 115: калька «раны» — скажите «запуски»
```

Словарь — таблица `CALQUES` в самом верху `check_page.py`: одна строка = один паттерн плюс
его простая замена. Завтрашняя калька добавляется **одной строкой**, кода это не касается.
Первые три записи — кальки, пойманные владельцем на живой странице: «раны» (от *runs*),
«рантаймами», «креденшалы».

**Чего в словаре нет — сознательно.** «Коммит» и «фича» прогнаны по реальной странице и
дали бы ложное красное: у владельца это уже свои слова. «Воркер» не в словаре потому, что
`language-guide.md` прямо разрешает ввести его в кавычках ПОСЛЕ аналогии («фоновый сборщик
(„воркер“)»), а ворота, краснеющие на образцовом тексте самого скилла, — сломанные ворота.

**Оговорка — `calque: <причина>` (G15b).** Конвенция взята у правила `no-stubs` из
`dz guard`: токен в HTML-комментарии освобождает **всю свою строку**, а оговорка **без
причины** отклоняется и сама становится находкой — освобождение, которое нельзя
объяснить, это молчаливый allowlist.

```html
<p>Обработка раны занимает…</p> <!-- calque: страница про ожоговое отделение, «раны» буквальные -->
```

```
FAIL  G15b строка 342: оговорка «calque:» без причины — отклонена, она не освобождает ничего
```

**Что закрыл кросс-семейный ревьюер (gpt-5.6-sol, 2026-08-20, три находки — все настоящие):**

1. **Склонения.** `фикс(?:ы|ов|ам|ах)` не ловил «после фикса», а `ран(?:ы|…)` — «после рана».
   Расширены падежные окончания обоих, добавлен «апрув».
2. **Оговорка засчитывалась где угодно.** Токен искался по всей строке, поэтому
   `<div data-x="calque: x">деплой билд</div>` молча снимал строку целиком — а на
   однострочном (минифицированном) документе снял бы всю страницу. Теперь токен
   засчитывается ТОЛЬКО внутри `<!-- … -->` и ТОЛЬКО с причиной от 3 буквенно-цифровых
   знаков.
3. **Координаты врали на редких разделителях строк.** `_blank` сохраняет только `\n`,
   а `str.splitlines()` дробит ещё и по U+2028/U+2029/`\x0b`/`\x0c`/`\x85` — при таком
   символе внутри `<style>` `raw` и `visible` расходились на строку, и `zip()` молча
   сопрягал не те строки (а значит, и оговорка снимала не ту). MEASURED на пробе с одним
   U+2028: под `splitlines()` строка 451 сопрягалась с чужим `sec-intro`, под `split('\n')`
   — со своей. Обе стороны теперь режутся по `\n`, равенство длин утверждается assert'ом.

**Известные пределы** (названы, а не заметены): токен освобождает строку целиком — защита
здесь в аудируемости, «calque:» находится одним grep; качество причины ворота не судят,
это работа ревью-плоскости, а не регулярки. Калька, разорванная тегом
(`де<span>п</span>лой`), не ловится — это уже сознательный обход автором собственных ворот,
а не та ошибка, ради которой они стоят.

## Ручные ворота

Скрипт их не выражает. Читаются автором подряд, один раз, перед публикацией.

### H1 · Простой русский

Читатель — руководитель, не инженер. Внутренние имена (файлы, ветки, поля БД, коды ошибок)
допустимы **только в скобках как ссылка**, никогда как носитель смысла.

* Плохо: «`nightly_worker` падает на `IntegrityError` при апсерте `report_snapshot`».
* Хорошо: «ночная сборка не может записать отчёт, если вчерашний ещё не убран
  (в коде — `report_snapshot`)».

Быстрый самотест: прочитать любой абзац вслух человеку, который не видел код.
Если он переспросил термин — абзац переписывается.

### H2 · Одна бытовая метафора на понятие, **до** термина

Метафора вводится один раз, в интро кластера, **перед** первым употреблением термина, и
дальше не меняется. Разные метафоры на одно понятие в разных абзацах — хуже, чем никакой.

Работавшие образцы: книга-закладка-должок (транзакция), багаж на ленте досмотра (очередь
обработки), общежитие без договора (общий ресурс без контракта), бронь переговорки (аренда
блокировки).

### H3 · Каждая находка отвечает ровно на три вопроса

Сетка «Что не так / Чем грозит / Как чиним» — не оформление, а обязательство. Ни одной
строки лишней, ни одной пропущенной. Если «Чем грозит» пустое — находки нет, есть придирка.

### H4 · Явная пометка рекомендации

Ровно один вариант в развилке помечен как рекомендуемый (`.suggest` до выбора,
слово «рекомендуем» в тексте). Развилка без рекомендации перекладывает работу на читателя;
две рекомендации — это не рекомендация.

### H5 · «Частично» говорит, **что именно** было неточно

Вердикт «подтверждено частично» без указания неточной части — это скрытая ошибка автора.
Формулировка обязана назвать: что подтвердилось, что нет, и почему исходная оценка разошлась.

### H6 · Мокап показывает разницу, а не красоту

Две фигуры, «Как сейчас» (красная подпись) и «После починки» (бирюзовая). В `.mock-note`
под каждой — на что смотреть. Если разницу нельзя описать одной фразой, мокап не нужен:
находка не UI-видимая, и пара картинок только разбавит страницу.

### H7 · Экспорт читается человеком, который не открывал страницу

Скопировать собственный экспорт, вставить в пустой чат, прочитать. Если непонятно, о чём
речь, — метки `data-label` слишком короткие.

## Чем этот скрипт проверен

Эталонная страница — `findings-review.html` (1424 строки, 37 находок, 17 развилок,
41 токен). Ниже — **фактический прогон текущей версии скрипта**, как есть:

```
$ python3 references/check_page.py findings-review.html
развилок: 17   вариантов: 38   токенов: 41
  WARN  G8b в разметке #pb-total стоит «16» — ручная цифра; ставьте 0, счётчик заполнит JS
  WARN  G10c глазами прочитать 3 развёрнутых вариант(ов) без слова о цене:
        ['Вариант A — рекомендуем. Слить первую ветку как есть, затем ',
         'Вариант A — рекомендуем. Переписать обработчик как обычный, ',
         'Рекомендуем — удалить все четыре. Каждое удаление подтвержда']

RESULT: GREEN   (код возврата 0)
```

Оба предупреждения — **настоящие**, и оба стоит держать перед глазами как образец того,
что мягкие ворота обязаны находить:

- **G8b.** В разметке зашито `<span id="pb-total">16</span>`, а развилок в DOM **17**.
  Ручной счёт разошёлся с реальностью; спасает только то, что JS перетирает цифру
  значением `groups.length`. Это довод в пользу запрета на ручной счёт, а не мелочь.
- **G10c, три варианта.** Ни один из трёх не называет ни дней, ни объёма переделки, ни
  последствия — только что сделать. Раньше они зеленели, потому что слово `рекоменд`
  стояло в словаре цены: ворота, которые невозможно провалить, ничего не измеряют.

**История: как G9 поймал мнимую развилку.** В первой сборке страницы развилка `q10`
(«Confluence в заявлении плана») содержала ровно один вариант — «Просто выполнить:
привести формулировку в соответствие». Решать там нечего: рекомендация с пририсованной
кнопкой. Скрипт дал `FAIL G9 развилка q10: живых вариантов 1`.

Инвариант допускает два выхода: убрать развилку или сделать её настоящей. В отгруженной
странице выбран **второй** — у `q10` появился второй живой вариант, поэтому в текущем
прогоне 17 развилок и 38 вариантов, а не 16/36. Ворота при этом остаются падающими:
достаточно вернуть одноопционную развилку, чтобы G9 снова покраснел (проверено
на мутанте, см. таблицу ниже).

**Что осталось нерешённым на эталоне.** На карточке `q10` рядом с достроенной развилкой
живёт чип «просто выполнить» — то есть карточка одновременно говорит «решать нечего»
и предлагает решать. Скрипт этого противоречия не выражает: `.qcard` с `[data-group]`
и с чипом `doit` для него законна. Кандидат в ворота записан в открытые вопросы —
он меняет содержание эталонной страницы, поэтому не вводится молча.
