# @dzhechkov/skills-package-story-page

An evidence-first skill for turning one existing package into a short story page ordinary people can
understand. It shows a concrete input → process → inspectable output scenario before architecture,
installation, cost, security, or FAQ copy.

## What ships

- `package-story-page/SKILL.md` — portable Codex/Claude workflow;
- a bilingual routing evaluation, pinned Opus receipt, and isolated runner that separate a short story
  page from the full tutorial-course sibling;
- three compact contracts for evidence, story, and visual direction;
- zero-runtime-dependency local extraction and rendering scripts plus a pinned, reproducibly built
  parse5 semantic verifier whose bundle, provenance, and upstream licence texts ship inside the skill;
- one self-contained HTML output with no remote fonts, images, scripts, or runtime fetch;
- deterministic mutation and injection tests, including seventy-four live production mutants for the parse5
  subset, item copy/bindings, disclosure ownership, raw-source CSS digest, pre-import integrity gate,
  raw-slice authority, semantic input boundary, browser request verdict, and orphan-marker guard. The
  checked-in mutation runner verifies a gate-owned scratch, copies it to a private ephemeral execution
  root, and rebinds hashes only in that disposable copy. Every clean baseline executes both the live-
  Firefox and unit-only lanes; browser-verifier mutations execute live Firefox. The retired 26-mutant hand-scanner set has an
  explicit disposition ledger alongside 29 checkpoint-check rows (55 disposition rows total), instead
  of pretending those dead guards still protect the product. Historical 27/30 live-registry checkpoints
  are not disposition counts; the current live registry contains 74 guards.

## Run directly

```bash
SKILL_ROOT=./package-story-page
node "$SKILL_ROOT/scripts/extract-package-evidence.mjs" --pkg <package> --json /tmp/evidence.json
# Author package-story-brief/1 from the evidence, then:
node "$SKILL_ROOT/scripts/render-story-page.mjs" --brief /tmp/brief.json --out /tmp/site/index.html
node "$SKILL_ROOT/scripts/verify-story-page.mjs" --brief /tmp/brief.json --site /tmp/site/index.html --evidence /tmp/evidence.json --pkg <package>
# Release gate when Firefox + geckodriver are installed:
node "$SKILL_ROOT/scripts/verify-story-page-browser.mjs" --site /tmp/site/index.html
```

The static verifier is for output generated by this factory. It parses a deliberately closed HTML subset
with the shipped parse5 bundle, verifies exact semantic-module and bundle hashes before importing it, and never executes page
JavaScript. It is not a general security scanner for arbitrary third-party HTML. The separate Firefox gate
uses loopback servers and an observing proxy: a required second-origin probe must be seen and rejected before
zero cross-origin requests from the canonical page can count as evidence. Canonical measurements accept
only the module-issued opaque receipt for that observation; a structurally identical object cannot forge it.
The recording proxy reads the exact module-issued probe target and its live hit count itself, so the call
site cannot substitute `true, 0` for the observation.
Its bounded RU and EN lane
uses real Enter/Space input, checks stable accessible names before and after activation, and measures
the declared 320/390/768/1440 viewports after a clean completed navigation.

Before any local ESM module evaluates, the wrapper reads and SHA-pins all five loaded local inputs:
semantic verifier, parse5 bundle, evidence extractor, renderer, and shared schema. The static import-graph gate asks Node's `SourceTextModule` parser for module requests and permits only
contained relative `.mjs` edges plus exact `node:crypto`; it rejects renderer, package, URL, bare, and
other-builtin resolution. The separate lexical capability diagnostic owns only its bounded named corpus.
If that isolated parser cannot be launched or returns an empty, incompatible, signalled, non-syntax, or
untyped result, the graph gate fails closed with a named parser-unavailable reason. A typed syntax/source
rejection remains hard even with a nonzero exit; the bounded lexer never substitutes for graph authority.
The child receives a copied environment with caller `NODE_OPTIONS` removed so launch preloads cannot
silently downgrade a valid parse; the parent runtime itself remains inside the trusted local preflight boundary.
Neither mechanism claims to confine arbitrary or deliberately re-authorised JavaScript. The reviewed
exact-byte hashes and caller-side signed artifact preflight remain the executable authority.

For repository routing maintenance, run `package-story-page/evals/run-pair-routing.mjs` with `--out`.
An installed standalone copy can pass the sibling's `SKILL.md` through `--sibling-skill`; expected owners
never enter the judge prompt.

## Honest scope

Static checks prove current-file SHA and bounded line-range provenance, exact numeric token/non-self context support
on one cited line, explicit synthetic-example labelling, package identity, exact authored-field placement,
source-id closure, per-item evidence/status ownership with no hidden, orphan, or unexpected owners, exact
field-owner cardinality, and no extra non-whitespace visible prose after an independently enumerated
exact-value renderer-chrome multiset is consumed. Classes, navigation placement and status attributes never
grant a chrome exemption. It also proves exact
direct-main section topology, brief-ordered item placement/containers, a brief-derived exact tag multiset,
exact class/ID/category ownership, first-mechanism-only initial-open state, and non-nested direct-child
native disclosures. The shipped parse5 authority rejects parse
errors or browser repairs, synthesized or unlocated nodes, foreign namespaces, comments, and every element
or attribute outside the emitted closed subset. Source links must be brief-declared absolute HTTPS anchors
with `rel="noreferrer"` inside the source disclosure. The sole `<style>` element is accepted only when the
SHA-256 of its exact parse5-bounded source bytes matches the verifier-owned digest. Separate bounded checks
cover focus outlines, universal reduced-motion suppression, responsive one-column reflow without
`overflow: hidden|clip`, safe wrapping, synthetic labels, and visual directions. The four CSS policy
predicates are tested independently from the exact stylesheet digest; overall verification still requires
both the digest authority and every policy receipt. They do not prove that a claim is true outside the
package, that a page is beautiful, that it converts, or that it fully conforms to WCAG. Those remain
content/visual review responsibilities. Local package documentation can itself contain false claims:
its SHA proves which package bytes made the statement, not that the statement is independently true.
Evidence files are read as fatal UTF-8 through non-symlink descriptors, with a 1 MiB per-file and
8 MiB aggregate provenance ceiling. Brief and evidence object graphs deeper than 64 levels fail closed
before schema or canonical traversal. These are resource and decoding boundaries, not truth guarantees.
The decimal-token gate recognizes Unicode numerals; spelled-out number words remain semantic review.
A local external receipt must contain its exact URL and check
date, but that still does not prove a fetch or remote truth. The separate Firefox gate measures
horizontal and internal scroll-container overflow at exact 320, 390, 768, and 1440 px content widths
and checks rendered focus on every link/disclosure plus field, disclosure-label, and dark-surface
evidence/status/kicker contrast; it requires
system browser binaries but no npm runtime dependency. `npm test` runs this browser gate by default;
`PACKAGE_STORY_SKIP_BROWSER=1 npm test` is an explicitly weaker unit-only lane.

`package-tutorial-factory` is the right tool for a full course with exercises and a final test. This
package deliberately produces the shorter story/landing artifact.

Only the root signed manifest and root generated SBOM are self-excluded from the manifest file list to avoid
recursive self-hashes. Same-named files below nested directories are ordinary signed content. `dz verify-pack`
first authenticates the manifest, then derives the one canonical CycloneDX
document from those signed entries and requires `sbom.json` to match it byte-for-byte. A missing, malformed,
duplicated, renamed, re-hashed, or metadata-modified component therefore fails consumer verification too,
not only CI. Delivery tests run that gate on both the source package and the unpacked npm tarball, and the
tarball preflight completes before its tests, adapters, or pipeline execute. Direct unverified execution or
same-user/concurrent mutation after that preflight is outside this local/offline authenticity boundary.
Byte-stable files carry ordinary raw SHA-256 entries. The packer-rewritten `package.json` component does
not present its canonical JSON verification digest as a raw file hash: it uses explicit
`dz:canonical-json-sha256-v2` and `dz:digest-basis=package-json-ordered-conditions-v2` properties.
Ordinary metadata keys are sorted, while `exports`, `imports`, and `typesVersions` descendant key order
is preserved so first-match entry-point semantics remain authenticated. Unsigned state is role-classified:
`.git` entries of any type and directory/symlink `node_modules`, `.agentic-qe`, or `.dz`; same-named
ordinary files other than `.git` remain signed. The exact npm tarball contains none of those state entries.
MEASURED by the 64-case `harness-core/test/sign.test.ts` lane plus the 7 canonical and 9 differential
hash cases: malformed, duplicate-key, or precision-losing root `package.json` JSON is refused before
current/v3 signing and fails current/v3 verification; it is never raw-hashed under that canonical label.
This package is signed with manifest/SBOM format v3. Existing v1/v2 packs remain readable through
compatibility verification; current SBOM output never emits the historical non-standard hash label.
For authenticated use this is a caller-side precondition: run `dz verify-pack` successfully before
projection or execution; `dz init --skills-dir` does not authenticate a source tree by itself.

The signed consumer object is the unpacked pnpm tarball. pnpm removes the repository-only
`prepublishOnly` lifecycle hook from the published `package.json`, so running `dz verify-pack` directly
against this authoring directory is expected to fail on `package.json`; the delivery gate proves that
single removal is the complete metadata delta and verifies the exact unpacked artifact instead.
