Тип: heuristic

Применимость: При чтении или переработке длинной функции с несколькими понятиями.

Ограничения: Число 20 — практическая рекомендация, а не доказанный универсальный предел.

## clean-code-ch03-p61-ku03 — Проверка функции на одну операцию

Тип: methodology

Проблема: Как лучше решить, выполняет ли функция одну операцию, а не набор несвязанных действий.

Содержание: Считайте действия одной операцией, когда они расположены на одном уровне под именем функции. Попробуйте извлечь часть: если новая функция лишь повторяет реализацию другими словами, уровень не изменился; если появляется самостоятельная концепция, исходная функция делала больше одной операции.

Применимость: При разделении крупной функции на меньшие части.

Ограничения: Несколько строк сами по себе не доказывают единственность операции; важен уровень абстракции.

Источник: Чистый код: создание, анализ и рефакторинг; ISBN 978-5-49807-381-1; глава 3; физические страницы PDF 61–61.

## clean-code-ch03-p65-ku08 — Сокращение числа аргументов

Тип: heuristic

Проблема: Как лучше выбрать приемлемую сигнатуру функции.

Содержание: Предпочитайте ноль аргументов, затем один и два. Тернарных функций по возможности избегайте; большее число аргументов требует очень веских доводов, но и тогда такие функции лучше не использовать. Каждый аргумент усложняет чтение и увеличивает число комбинаций, которые нужно проверить тестами.

Применимость: При проектировании сигнатуры функции.

Ограничения: Если без аргументов не обойтись, один входной аргумент обычно легче всего понять.

## clean-code-ch03-p67-ku10 — Преобразование многоместной сигнатуры

Тип: decision-framework

Проблема: Как лучше снизить сложность бинарных, тернарных и вариативных вызовов.

Ограничения: Два аргумента уместны для естественно упорядоченных компонентов одного значения; тернарные вызовы требуют особенно веской причины.

## clean-code-ch03-p71-ku14 — Разделение команд и запросов

Тип: methodology

Проблема: Как лучше устранить неоднозначность вызова, который и меняет состояние, и сообщает результат.

## clean-code-ch03-p72-ku15 — Исключения и изоляция обработки ошибок

Тип: methodology

Проблема: Как лучше отделить нормальный путь выполнения от реакции на ошибку.

Применимость: При последовательности операций, где код ошибки заставляет строить вложенные проверки.

Ограничения: Требование одной операции относится и к обработке ошибок: после catch/finally в такой функции не размещают другую работу.

Проблема: После извлечения одна операция возвращает значение, а другая меняет состояние, хотя вызывающий метод использует оба результата.

Содержание: Проверьте контракт выделенных операций: если часть отдаёт результат, а часть меняет поля, сведите их к одной модели. В кейсе поиск общего префикса и суффикса стал выдавать значения, затем явно присваиваемые перед созданием сжатых строк.

## clean-code-ch15-p297-ku06 — Убирайте скрытый порядок вызовов структурой координации

Тип: heuristic

Проблема: Один расчёт тайно зависит от другого, и неверный порядок породит трудную для поиска ошибку.

Содержание: Сделайте зависимость видимой, но не останавливайтесь на параметре, когда причина порядка остаётся неясной. Соберите связанные вычисления в координирующую операцию, которая сама сначала получает префикс, затем суффикс. Тогда порядок становится частью устройства, а не знанием вызывающего кода.

Применимость: Используйте для последовательных расчётов, где второй шаг берёт состояние или результат первого.

Ограничения: Объединение оправдано реальной неразделимостью шагов; независимые операции не надо связывать только ради внешнего порядка.
