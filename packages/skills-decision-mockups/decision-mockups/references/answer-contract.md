# Версия контекста и ответы

Для новой страницы включайте v2 явно. Старые страницы без `decision-manifest` сохраняют
прежний текстовый экспорт. Старый ответ требует явного подтверждения перед переходом на v2.
Выбор, рекомендация и проверка документа сами по себе не запускают действие.

## Автор и получатель

1. Автор сохраняет все существенные основания в манифесте: задачу, сделанное/оставшееся,
   почему сейчас, ограничения, риски, неизвестное, вопросы, варианты, цену и обоснование.
2. `python3 references/check_answer.py --prepare manifest.json > current-manifest.json`
   проверяет схему и вычисляет revision. Только этот явный режим может заменить прежний хеш.
3. HTML включает подготовленный документ в единственный
   `<script id="decision-manifest" type="application/json">`. При вставке JSON замените
   символ `<` на `\u003c`, чтобы текст не закрыл script. Компактный текст хранит тот же манифест.
4. Получатель проверяет **свой текущий** манифест и отдельный полный JSON ответов:
   `python3 references/check_answer.py current-manifest.json answer.json`.
   Код 0 означает текущий допустимый ответ; 1 — неверный/устаревший ответ или контекст;
   2 — ошибка вызова/чтения. Отсутствующие строки становятся `unanswered`.

Проверка пересчитывает хеш и ничего не исправляет. Ответ со старой revision требует
повторного подтверждения всей страницы, даже если ID вариантов остались прежними.
Хеш не подтверждает истинность источника, личность отвечающего или факт человеческого клика.
Без доверенного текущего манифеста контекст можно читать, но проверка версии остаётся ожидающей.

## Закрытая схема

Все поля обязательны, кроме явно перечисленных. Неизвестные поля запрещены на любой глубине;
необязательное поле можно опустить, но нельзя заменить `null`. Текст — непустая после
проверки пробелов строка Unicode без одиночных суррогатов; исходное значение сохраняется.
ID — такой же точный текст, без нормализации и запрета кавычек/скобок/имён прототипа.

| Объект | Поля | Необязательные поля |
|---|---|---|
| Manifest | schemaVersion, pageId, revision, topic, date, context, grounds[], decisions[] | components[] |
| Context | task, whyNow, requestedAnswer — текст; done[], remaining[], constraints[], risks[], unknowns[] — текстовые массивы | — |
| Ground | id, kind, claim, source — текст | basis, observedAt, commit — текст; basis обязателен для estimate |
| Decision | id, label, rationale — текст; recommendedOptionId — ID своего варианта либо null; options[] — минимум два | excludedAlternatives[] |
| Option | id, label, cost, whenUseful — текст | — |
| Excluded | label, reason — текст; assumptions[] — текстовый массив | — |
| Component | id, label — текст | — |
| Answer | schemaVersion, pageId, revision, answers[] | — |
| AnswerRow | decisionId, status | optionId — только и обязательно при selected; note — текст только при deferred/needs-data |

`schemaVersion` — конечное JSON число, равное 2; 2.0/2e0 принимаются и нормализуются в 2,
строка/boolean не принимаются. `revision` — `sha256:` и 64 строчных шестнадцатеричных знака.
Авторский prepare допускает отсутствие revision или прежнюю синтаксически правильную revision.
`kind` — fact/estimate/assumption/unknown; source может быть «не проверено».
`status` — selected/deferred/needs-data/unanswered. ID решений, оснований, компонентов уникальны
в своих массивах; ID вариантов — внутри решения; строки ответа уникальны по decisionId.
Пустые списки сделанного/оставшегося/ограничений/рисков/неизвестного/оснований/компонентов
допустимы; список решений непуст. Семантическая проверка выявляет пропущенное существенное.

Весь материал, включая необязательные поля, хешируется, кроме верхнего revision:
`json.dumps(normalized, sort_keys=True, separators=(',', ':'), ensure_ascii=True, allow_nan=False)`
в UTF-8. Порядок ключей не влияет; порядок массивов и точные строки влияют.
Все пути v2 сначала отвергают повторные JSON ключи, включая эквивалентные после декодирования,
NaN/Infinity/-Infinity и переполнение чисел (1e400). JSON.parse с reviver недостаточен.

## HTML и передача

Группа имеет `data-group` и `data-label`, равные ID/label решения, и один видимый узел
`data-decision-label`. Каждый настоящий вариант имеет `data-option-id`, `data-val` (label),
один видимый `data-option-label` и доступное управление кнопкой. Три отдельные кнопки
`data-answer-state="deferred|needs-data|unanswered"` задают состояния; они не варианты.
Контекст помечается `data-context="имяПоля"`, основания — `data-ground-id`, `data-evidence-kind`
и `data-source`, компоненты — `data-component-id`. Диаграмма `data-diagram` связывается
через `aria-describedby` с соседним текстом `data-diagram-text`.
Перед передачей и использованием обязательно проверяйте **точный конечный HTML** через
check_page.py и повторяйте после последней правки. Он разбирает настоящий инертный узел
и ближайшую группу, не строки, похожие на теги в JSON/комментариях/script/textarea/title.
Повторные исходные атрибуты и разметку, требующую починки браузером, отвергает этот gate.
Браузер уже мог стереть повторный атрибут: активный пикер/экспорт не подтверждает проверку
исходного файла. Пикер отдельно проверяет наблюдаемые маркеры/DOM, строгий JSON, ID и состояния.

Существенные контекст, основания, подписи, обоснование и последствия должны быть видимы.
Gate не считает текст явно скрытых потомков. Пикер проверяет корни и потомков по вычисленным
стилям, повторно перед ответом/экспортом; скрытое не восстанавливается из JSON как показанное.
При отказе нет выбранного машинного экспорта. Видимая вложенная разметка допустима;
дополнительные сведения могут оставаться в отдельном details. Gate не исполняет CSS:
видимость через таблицу стилей, произвольная читаемость и AT требуют отдельного наблюдения.

Текстовый экспорт сохраняет существенный контекст, основания/источники, неопределённость,
все состояния, pageId/revision. Отдельное readonly поле/API `exportJSON()` содержит полный
машинный документ. Получатель принимает весь этот документ, не ищет JSON среди цитат,
ограждений и подписей. При неоднозначной смешанной вставке запросите исходный JSON заново.
Восстановление хранится отдельно под `decision-mockups:v2:<pageId>`; неверный ответ не
показывается выбранным. Отказ хранения не мешает текущему выбору и экспорту.

## Компактный ответ человека

Покажите короткий контекст, полные названия вопросов/вариантов, pageId/revision и инструкцию:

> Ответьте названием вопроса и полным названием варианта; либо напишите «Отложить»,
> «Нужны данные: [вопрос]» или «Нет ответа» для указанного вопроса.

Человек не пишет JSON и не копирует хеш. Агент связывает только однозначный явный ответ
с сохранённой **показанной** pageId/revision и составляет envelope. Полное название вопроса
и варианта/состояния должно определять один ответ. A/yes/«рекомендация», повторяющиеся названия,
неясный контекст требуют уточнения. Сохраните показанную revision, не обновляйте до текущей.
Пропущенные вопросы остаются unanswered; заметку «нужны данные» копируйте без выдумывания.
Проверка составленного ответа использует настоящий текущий манифест получателя.
Это инструкция и предмет независимой проверки, не автоматический распознаватель языка.


V2 nonblank text uses one explicit set in Python and both pickers: U+0009–000D, U+001C–0020, U+0085, U+00A0, U+1680, U+2000–200A, U+2028, U+2029, U+202F, U+205F, U+3000 and U+FEFF. Blank-only values fail; U+200B is outside the set. Accepted IDs, notes and manifest strings remain exact, including hashing. Only visible material comparison collapses this set to ASCII space and removes boundary runs. In HTML, encode carriage return as `&#13;` when its exact attribute value must survive source and browser newline handling. Legacy rules stay unchanged.
