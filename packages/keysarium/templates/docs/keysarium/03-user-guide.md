> **`/bto*` commands are NOT part of @dzhechkov/keysarium.** The BTO evaluator
> (Build-Benchmark-Test-Optimize) ships as a SEPARATE npm package. Install it first —
> `npx @dzhechkov/skills-bto init` — otherwise every `/bto…` command referenced below will
> not resolve in your project.

## 1. Быстрый старт (5 минут)

### Шаг 1: Запустите полный пайплайн

Откройте Claude Code в директории проекта и введите:

```
/casarium Автоматизация контакт-центра Альфа-Банка с использованием AI:
снизить нагрузку на операторов на 40%, сократить время обработки типовых
обращений с 8 минут до 2 минут. Ограничения: on-premise, ФЗ-152, бюджет 50 млн руб.
```

Вот и всё. Система запустит последовательный пайплайн из 7 фаз и будет создавать артефакты автоматически.

### Шаг 2: Отвечайте на checkpoint-ы

После каждой фазы вы увидите checkpoint:

```
═══════════════════════════════════════════════════════
CHECKPOINT 0: Product Discovery Complete
Проведён анализ JTBD, конкурентов, ROI. Определены 4 сегмента
пользователей, 5 конкурентных решений, предварительный ROI 280%.
Файл: 00_product_discovery.md
• "ок" — следующая фаза
• "углуби [раздел]" — доработать
═══════════════════════════════════════════════════════
```

Введите `ок`, чтобы перейти к следующей фазе. Подробнее о вариантах ответа -- в разделе [Работа с checkpoint-ами](#3-работа-с-checkpoint-ами).

### Шаг 3: Получите результат

По завершении всех фаз в директории `researches/<название-кейса>/` появится полный набор артефактов:

```
researches/bank_kc_automation/
├── 00_product_discovery.md         ← Анализ продукта и рынка
├── 01_case_brief.md                ← Структурированный бриф кейса
├── 02_research_findings.md         ← Бенчмарки, аналоги, технологии
├── 02.5_trend_brief.md             ← Анализ трендов для CJM
├── 03_solution_strategy.md         ← Стратегия решения
├── 04_architecture.md              ← Техническая архитектура
├── 05_presentation_content.md      ← Контент презентации (10-12 слайдов)
├── 06_speaker_script.md            ← Скрипт для спикера
├── 07_qa_preparation.md            ← Подготовка к Q&A (7+ вопросов)
├── 08_executive_summary.md         ← Executive Summary (1 страница)
├── prototype/
│   └── cjm-prototype.jsx          ← Кликабельный прототип CJM
├── diagrams/
│   ├── architecture-c4.mermaid    ← C4 архитектура
│   ├── sequence-main-flow.mermaid ← Sequence diagram
│   ├── process-as-is.mermaid      ← Процесс "как есть"
│   └── process-to-be.mermaid      ← Процесс "как будет"
└── README.md                       ← Сводка исследования
```

### Что происходит на каждой фазе

| Фаза | Название | Время | Что делает | Артефакт |
|------|---------|-------|-----------|----------|
| Phase 0 | Discovery | 15% | Анализ продукта: JTBD, конкуренты, ROI, Why AI | `00_product_discovery.md` |
| Phase 1 | Explore | 5% | Глубокое понимание: 5 Whys, ограничения, критерии успеха | `01_case_brief.md` |
| Phase 2 | Research | 15% | Бенчмарки, аналоги, технологии, регуляторика | `02_research_findings.md` |
| Phase 2.5 | CJM Prototype | 10% | 4 варианта CJM + кликабельный прототип + тренды | `02.5_trend_brief.md`, `prototype/cjm-prototype.jsx` |
| Phase 3 | Solve | 15% | Стратегия решения: SCQA, Process Design, HITL, метрики | `03_solution_strategy.md`, diagrams |
| Phase 4 | Architecture | 15% | Техническая архитектура: C4, компоненты, data, security | `04_architecture.md`, diagrams |
| Phase 5 | Presentation | 20% | Презентация, скрипт, Q&A, Executive Summary | `05-08_*.md` |
| Phase 6 | Packaging | 5% | Финальная сборка, README | `README.md` |

## 2. Основные команды

### 2.1. /casarium -- полный пайплайн

Запускает полный цикл из 7 фаз для одного кейса.

```
/casarium [текст кейса]
```

**Примеры:**

```
/casarium Автоматизация КЦ Альфа-Банка: снизить нагрузку на операторов
на 40% с помощью AI. On-premise, ФЗ-152.

/casarium Персонализация рекомендаций для маркетплейса Ozon:
увеличить конверсию на 15%. Real-time latency < 200ms.

/casarium Оптимизация HR-процессов для Сбера: автоматизация
скрининга резюме и первичного интервью. 1000+ вакансий/месяц.
```

Если вызвать без аргументов, система спросит текст кейса, тайминг и домен:

```
/casarium
```

### 2.2. /new-research -- создать исследование

Создаёт изолированную директорию для нового исследования без запуска пайплайна.

```
/new-research [название кейса]
```

**Пример:**

```
/new-research Автоматизация КЦ банка
```

Результат:

```
═══════════════════════════════════════════════════════
Исследование создано: researches/bank_kc_automation/

Для запуска полного пайплайна:
  /casarium [текст кейса]

Для запуска отдельных фаз:
  /discovery, /explore-case, /research, /cjm-prototype,
  /solve, /architecture-phase, /presentation
═══════════════════════════════════════════════════════
```

### 2.3. /parallel-research -- несколько кейсов

Запускает Phase 0 (Product Discovery) для нескольких кейсов параллельно.

```
/parallel-research кейс1: [описание] | кейс2: [описание] | кейс3: [описание]
```

**Пример:**

```
/parallel-research банк: Автоматизация КЦ с AI | ритейл: Персонализация рекомендаций | hr: Скрининг резюме с LLM
```

Результат -- таблица со статусами и инструкциями для продолжения каждого исследования.

### 2.4. Команды отдельных фаз

Каждую фазу можно запустить отдельно, передав путь к директории исследования:

| Команда | Фаза | Пример |
|---------|------|--------|
| `/discovery` | Phase 0 | `/discovery researches/bank_kc_automation/` |
| `/explore-case` | Phase 1 | `/explore-case researches/bank_kc_automation/` |
| `/research` | Phase 2 | `/research researches/bank_kc_automation/` |
| `/cjm-prototype` | Phase 2.5 | `/cjm-prototype researches/bank_kc_automation/` |
| `/solve` | Phase 3 | `/solve researches/bank_kc_automation/` |
| `/architecture-phase` | Phase 4 | `/architecture-phase researches/bank_kc_automation/` |
| `/presentation` | Phase 5 | `/presentation researches/bank_kc_automation/` |

Это полезно, когда:
- Нужно перезапустить конкретную фазу
- Работаете над фазами по одной (с перерывами)
- Хотите повторить фазу с другими параметрами

### 2.5. /harvest -- извлечение знаний

Запускает ритуал извлечения знаний после завершения исследования.

```
/harvest researches/bank_kc_automation/
```

Для обработки всех исследований:

```
/harvest all
```

Harvest находит универсальные паттерны, шаблоны и уроки, которые можно переиспользовать в будущих исследованиях.

### 2.6. /brain-export и /brain-import -- портативные знания

Экспорт и импорт накопленных знаний между проектами.

```
/brain-export [путь или "all"]   — Экспорт знаний в portable JSON
/brain-import [файл.json]        — Импорт знаний из другого проекта
```

**Экспорт:**

```
/brain-export researches/bank_kc_automation/
/brain-export all
```

Brain-контейнер включает: метаданные скиллов, паттерны по доменам, резюме исследований, паттерны из harvest, метрики пайплайна. Файл сохраняется в `.keysarium/exports/`.

**Импорт:**

```
/brain-import .keysarium/exports/keysarium-brain-2026-03-01.json
```

Импорт использует стратегию merge-not-overwrite: существующие знания не перезаписываются, новые добавляются. Удобно для переноса накопленного опыта в новый проект или передачи коллеге.

### 2.7. /init-platform -- мульти-платформенная поддержка

Генерирует конфигурации для других AI-платформ, адаптируя скиллы и правила Keysarium к целевому формату.

```
/init-platform --platform cursor     — Cursor (.cursorrules)
/init-platform --platform opencode   — OpenCode (.opencode/)
/init-platform --platform copilot    — GitHub Copilot (.github/copilot-instructions.md)
```

**Пример:**

```
/init-platform --platform cursor
```

После выполнения в корне проекта появится файл `.cursorrules`, содержащий адаптированные инструкции для Cursor. Аналогично для других платформ.

### 2.8. /workers -- фоновые воркеры

Управление фоновыми воркерами для неблокирующих операций.

```
/workers start <type>   — Запуск воркера (consolidate, export-brain, health-check, dream-cycle)
/workers status          — Статус активных воркеров
/workers stop <id>       — Остановка воркера
/workers list            — Список доступных типов
```

**Типы воркеров:**

| Тип | Назначение | Модель |
|-----|-----------|--------|
| `consolidate` | Консолидация паттернов из завершённых исследований | sonnet |
| `export-brain` | Фоновый экспорт brain в JSON | haiku |
| `health-check` | Проверка здоровья системы | haiku |
| `dream-cycle` | Анализ паттернов (concept graph + insights) | sonnet |

**Пример запуска:**

```
/workers start consolidate
/workers status
/workers stop wkr-20260301-143022-consolidate
```

Воркеры работают в изоляции (`.keysarium/workers/`), не изменяют файлы в `researches/` и `features/`. Максимум 3 воркера одновременно.

### 2.9. /dream -- Dream Cycles

Анализ накопленных паттернов через несколько сессий.

```
/dream run       — Запуск dream cycle (concept graph + insights)
/dream insights  — Показать последние инсайты
/dream status    — Состояние триггеров
/dream clear     — Очистить старые инсайты (оставить 10)
```

Dream cycle анализирует паттерны из истории исследований, например:
- «Банковские кейсы требуют вдвое больше времени на Phase 2»
- «TRIZ работает лучше Game Theory для ритейла»
- «CJM Variant B выигрывает в 70% enterprise-кейсов»

Инсайты автоматически применяются при запуске следующего `/casarium` -- система предложит учесть найденные паттерны. Запуск dream cycle предлагается системой в качестве рекомендации, когда накапливается достаточно данных (триггеры настраиваются).

```
/dream run
/dream insights
```

Результаты хранятся в `.keysarium/insights/`. Максимум 10 файлов результатов.

### 2.10. /learning-stats -- аналитика обучения

```
/learning-stats [--domain X] [--phase N]   — Reward learning статистика
```

Показывает статистику на основе reward-оценок (0.0--1.0), которые назначаются автоматически по ответам пользователя на checkpoint-ах:

| Ответ на checkpoint | Reward | Метка |
|--------------------|--------|-------|
| `ок`, `next` (без правок) | 1.0 | excellent |
| Правка 1 раздела | 0.7 | good |
| Правки 3+ разделов | 0.3 | needs_work |
| `начни заново` | 0.0 | failed |

**Примеры:**

```
/learning-stats                   — Общая статистика по всем доменам и фазам
/learning-stats --domain banking  — Статистика для банковского домена
/learning-stats --phase 2         — Статистика для Phase 2 (Research)
```

Вывод включает: средние оценки по фазам, паттерны по доменам, эффективность скиллов. Помогает понять, какие фазы и домены требуют повышенного внимания.

### 2.11. /verify-chain -- верификация цепочки

```
/verify-chain [путь к директории исследования]
```

Проверяет целостность SHA-256 цепочки свидетелей (witness chain) для артефактов исследования.

**Пример:**

```
/verify-chain researches/bank_kc_automation/
```

Каждая фаза создаёт запись с хешем артефакта, связанную с предыдущей записью (hash chain). Это гарантирует, что артефакты не были изменены после создания. Цепочка хранится в `researches/<slug>/.witness-chain.json`.

Особенно важно для банковского домена (требования ФЗ-152 к аудит-треилу). Рекомендуется запускать после завершения полного пайплайна как финальную проверку целостности.

### 2.12. /feature-adr -- адаптивная разработка фич

9-шаговый пайплайн для реализации программных фич с Complexity Router (S/M/L/XL).

```
/feature-adr [описание фичи]
```

**Пример:**

```
/feature-adr Добавить авторизацию через OAuth 2.0 с поддержкой Google и GitHub
```

**Шаги пайплайна:**

| Шаг | Название | Назначение |
|-----|---------|-----------|
| 0 | Complexity Router | Определение уровня сложности (S/M/L/XL) |
| 1 | Requirements | Структурированные требования |
| 2 | Research | Исследование решений (только L/XL) |
| 3 | ADR | Architecture Decision Record (только M+) |
| 4 | DDD | Domain модель (только L/XL) |
| 5 | Architecture | Архитектура (только M+) |
| 6 | Implementation Plan | План реализации |
| 7 | Code | Реализация кода |
| 8 | QE | Проверка качества |

**Уровни сложности:**

| Tier | Scope | Активные шаги |
|------|-------|--------------|
| S | 1--3 файла | 0→1→6→7→8 |
| M | 4--10 файлов | 0→1→3→5→6→7→8 |
| L | 11--30 файлов | Полный пайплайн |
| XL | 30+ файлов | Полный DAG + multi-agent |

Артефакты сохраняются в `features/<feature-slug>/` (не в `researches/`). Уровень сложности определяется автоматически на шаге 0, но может быть скорректирован вами на первом checkpoint-е.

### 2.13. /bto -- Build-Test-Optimize

Система мульти-агентной оценки и оптимизации скиллов и команд.

```
/bto [путь]            — Полный цикл: BUILD → TEST → OPTIMIZE
/bto-build [описание]  — Генерация нового скилла/команды
/bto-test [путь]       — Мульти-агентная оценка (Layer 0→1→2)
/bto-optimize [путь]   — Эволюционная оптимизация за 3 раунда
```

**Примеры:**

```
/bto-test .claude/skills/explore/
/bto-optimize .claude/skills/problem-solver-enhanced/
/bto-build Новый скилл для анализа конкурентов в телекоме
```

**Архитектура оценки (TEST):**

| Layer | Роль | Модель | Назначение |
|-------|------|--------|-----------|
| Layer 0 | Структурные проверки | haiku | 71 детерминистическая проверка: структура, плейсхолдеры, кодировка |
| Layer 1 | Семантическая базовая оценка | haiku | Быстрая проверка связности и релевантности |
| Layer 2 | Полная панель 3 судей | sonnet | Domain Expert + Critic + Completeness Auditor |
| Meta | Разрешение разногласий | sonnet | Срабатывает, если разброс оценок > 3 пункта |

Результат Layer 2: взвешенная оценка 0--10 (Domain Expert 40% / Critic 30% / Auditor 30%). Оценка ≥ 7.0 переводит скилл в Tier 2 (Validated), ≥ 8.5 при наличии тест-суитов -- в Tier 3 (Verified).

## 3. Работа с checkpoint-ами

После каждой фазы система показывает checkpoint и ожидает вашей реакции. Вы управляете процессом через простые текстовые команды.

### 3.1. Доступные команды на checkpoint-е

| Команда | Действие | Когда использовать |
|---------|----------|-------------------|
| `ок` | Перейти к следующей фазе | Результат устраивает |
| `углуби [раздел]` | Доработать конкретный раздел | Нужно больше деталей |
| `ускорь` | Включить Quick Mode | Мало времени |
| `wow` | Добавить нестандартный элемент | Хотите удивить жюри |
| `превью [X]` | Посмотреть документ | Проверить артефакт |
| `время [N]` | Установить тайминг (часов) | Уточнить тайминг |
| `выбираю A/B/C/D` | Зафиксировать CJM | Только на Phase 2.5 |
| `объедини A+D` | Создать гибрид CJM | Только на Phase 2.5 |

### 3.2. Примеры использования

**Простое продвижение:**

```
CHECKPOINT 0: Product Discovery Complete
...
> ок
```

**Углубление конкретного раздела:**

```
CHECKPOINT 2: Research Complete
...
> углуби конкурентный анализ
```

Система доработает раздел конкурентного анализа и покажет обновлённый checkpoint.

**Переключение в быстрый режим:**

```
CHECKPOINT 1: Explore Complete
...
> ускорь
```

Оставшиеся фазы будут выполнены в сокращённом формате (Quick Mode).

**Добавление вау-эффекта:**

```
CHECKPOINT 4: Architecture Complete
...
> wow
```

Система добавит нестандартный элемент в текущую или следующую фазу -- например, неожиданный аналог, провокационный инсайт или нестандартную визуализацию.

**Просмотр артефакта:**

```
> превью 03_solution_strategy.md
```

**Установка тайминга:**

```
> время 2
```

Устанавливает 2 часа на весь кейс. Система пересчитает бюджет времени по фазам.

### 3.3. Что нельзя делать

- Не пропускайте checkpoint-ы молча -- система ждёт вашего ответа
- Не пытайтесь перескочить фазы -- они зависят друг от друга
- Не удаляйте артефакты вручную посреди пайплайна -- это нарушит зависимости

## 4. Работа с CJM прототипом (Phase 2.5)

Phase 2.5 -- ключевая фаза, которая никогда не пропускается. Здесь создаётся Customer Journey Map (CJM) в 4 вариантах и кликабельный React-прототип.

### 4.1. Что вы получите

После Phase 2.5 у вас будет:

1. **4 варианта CJM:**
   - **Variant A** -- первый подход к точке входа пользователя
   - **Variant B** -- альтернативный подход
   - **Variant C** -- третий вариант
   - **Variant D** -- Future-Ready CJM, основанный на анализе трендов

2. **Trend Brief** (`02.5_trend_brief.md`) -- исследование 5 категорий трендов

3. **React-прототип** (`prototype/cjm-prototype.jsx`) -- кликабельный интерфейс с вкладками для каждого варианта

### 4.2. Выбор варианта

На checkpoint-е Phase 2.5 вам будут представлены 4 варианта CJM. Ваши опции:

**Выбрать один вариант:**

```
> выбираю A
```

или

```
> выбираю D
```

Выбранный вариант станет `{CHOSEN_CJM}` и будет использоваться во всех последующих фазах (Phase 3-5).

**Создать гибрид:**

```
> объедини A+D
```

Система создаст гибрид из выбранных вариантов. Полезно, когда хотите взять основу одного варианта и дополнить элементами другого.

Можно комбинировать любые варианты:

```
> объедини B+C
> объедини A+B+D
```

**Запросить объяснение трендов:**

```
> объясни тренды D
```

Система подробно расскажет, какие тренды легли в основу Variant D и почему они релевантны вашему кейсу.

### 4.3. Рекомендации по выбору

| Ситуация | Рекомендация |
|----------|-------------|
| Кейсариум на 4 часа (стандарт) | Выберите один сильный вариант (часто A или D) |
| Хакатон на 8 часов | Создайте гибрид A+D для максимального эффекта |
| Банковский домен | Обратите внимание на Variant A/B (консервативнее) |
| Ритейл | Variant D часто сильнее (тренды в e-commerce быстро меняются) |
| Хотите удивить жюри | Variant D или гибрид с D (Future-Ready) |

### 4.4. Что происходит после выбора

1. `{CHOSEN_CJM}` фиксируется и передаётся в Phase 3-5
2. Phase 3 (Solve) проектирует решение на основе выбранного CJM
3. Phase 4 (Architecture) строит архитектуру под выбранный user flow
4. Phase 5 (Presentation) включает CJM в контент презентации (слайд 5)

## 8. FAQ и troubleshooting

### Общие вопросы

**Q: Можно ли пропустить Phase 2.5 (CJM Prototype)?**

A: Нет. Phase 2.5 является обязательной. При нехватке времени она упрощается (2 варианта вместо 4), но не пропускается. CJM прототип -- критически важный артефакт, который определяет direction для Phase 3-5.

---

**Q: Что делать, если не понимаю, какой вариант CJM выбрать?**

A: Используйте следующие подсказки:
- `объясни тренды D` -- узнайте, что стоит за Variant D
- Спросите: "Сравни варианты A и D по критериям [ваши критерии]"
- Если сомневаетесь -- `объедини A+D` (гибрид обычно сильный выбор)

---

**Q: Можно ли запустить отдельную фазу без предыдущих?**

A: Технически можно, но не рекомендуется. Каждая фаза читает артефакты предыдущих фаз для контекста. Если артефактов нет, результат будет неполным. Исключение -- Phase 0 (`/discovery`), которая может работать с текстом кейса напрямую.

---

**Q: Как указать домен (банк, ритейл, enterprise)?**

A: Домен определяется автоматически по ключевым словам в тексте кейса. Для явного указания добавьте в текст:

```
/casarium [текст кейса]. Домен: банк.
```

Доступные домены: банк/fintech, ритейл/e-commerce, enterprise/B2B, healthcare.

---

**Q: Что такое PARANOID mode в research?**

A: Это режим повышенной верификации данных. Каждое фактическое утверждение должно иметь проверяемый источник. Утверждения без источников помечаются как `[UNVERIFIED]`. Это защищает от галлюцинаций AI и обеспечивает доверие жюри.

---

**Q: Можно ли редактировать артефакты вручную?**

A: Да. Файлы -- это обычные markdown/jsx файлы. Вы можете редактировать их в любом текстовом редакторе. Но учтите, что последующие фазы читают эти файлы, поэтому сохраняйте структуру.

---

**Q: Как получить презентацию в PowerPoint/Google Slides?**

A: Файл `05_presentation_content.md` содержит контент для каждого слайда с указанием визуальных элементов. Перенесите контент в PowerPoint/Google Slides вручную, используя описания слайдов как руководство. Mermaid-диаграммы экспортируйте через mermaid.live.
