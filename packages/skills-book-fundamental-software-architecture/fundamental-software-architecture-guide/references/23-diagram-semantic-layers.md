# Смысловые слои и аудитория архитектурной диаграммы

## Решающий момент

Применяйте маршрут до отрисовки или публикации схемы, когда нужно выбрать аудиторию, масштаб, нотацию и смысловые слои, а затем проверить, что переходы между представлениями и визуальные знаки читаются однозначно.

**NOT:** маршрут не создаёт полный C4 model, не пишет ADR и не исследует stakeholder power/interest. Детальную модель и соседние артефакты передавайте `c4-architecture`, `architecture-decision-records` и `stakeholder-map`.

## Протокол

1. **Сформулируйте вопрос аудитории.** Назовите читателя и решение, которое схема должна поддержать. Начинайте с самого общего масштаба, достаточного для этого вопроса.
2. **Соберите трёхступенчатый рассказ.** Покажите систему целиком, затем выбранную область с её окружением, затем внутреннее устройство. Перед сменой масштаба сохраняйте видимый мост к предыдущему виду.
3. **Положите топологию в основание.** Контейнеры, хранилища, broker и зависимости описывайте архитектурной семантикой вроде `синхронно`, а не названием продукта.
4. **Разведите смысл по слоям.** В отдельные слои вынесите протоколы и типы БД, доменные границы, транзакционный охват и другие срезы. Для конкретной аудитории включайте только нужные слои; один слой несёт один смысл.
5. **Выберите язык по задаче.** UML полезен для структуры классов или последовательности; C4 — для связанного многомасштабного рассказа; ArchiMate — для лаконичного enterprise-вида внутри и между бизнес-областями. Знакомость читателя важнее полноты стандарта.
6. **Если выбран C4, настройте zoom.** Context показывает систему, роли и внешние зависимости; Container — границы развёртывания для разговора с эксплуатацией; Component — внутренний архитектурный состав; Class — детальную конструкцию.
7. **Проверьте инструмент.** Нужны смысловые слои, шаблоны или трафареты, привязка и выравнивание, понятные линии/цвета и экспорт в требуемый формат. Функции редактора сами по себе не делают схему ясной.
8. **Проведите семантический lint.** Подпишите незнакомые сущности, сделайте связи видимыми, используйте стрелки для направления. В локальной конвенции сплошная линия означает синхронный, пунктир — асинхронный обмен; неочевидный знак получает пояснение прямо на схеме.
9. **Установите минимальный стандарт.** Оставьте только обозначения, помогающие целевому читателю. Разрешайте исключение, когда оно улучшает передачу конкретного дизайна и не разрушает общую последовательность.

## Матрица выбора

| Вопрос аудитории | Масштаб или слой | Что исключить |
|---|---|---|
| Кто использует систему и от чего она зависит? | C4 Context | Классы и внутренние компоненты |
| Где проходит deployment boundary? | C4 Container | Низкоуровневую бизнес-логику |
| Как устроена выбранная область? | C4 Component | Несвязанные детали всей системы |
| Как взаимодействуют объекты? | UML class/sequence либо C4 Class | Enterprise-ландшафт |
| Как связаны бизнес-области? | ArchiMate | Детали метода и протокола |
| Какие технологии реализуют связи? | Отдельный implementation layer | Смешение с базовой topology semantics |
| Где домен или транзакция? | Domain/transaction layer | Декоративное дублирование топологии |

## Антипаттерны

- Показывать все детали одновременно и называть это обзором.
- Переключать масштаб без общей границы или узнаваемого элемента.
- Смешивать протокол, домен и транзакцию в одном декоративном слое.
- Выбирать язык ради полноты стандарта, которого аудитория не знает.
- Использовать неподписанные фигуры как будто существует мировая нотация.
- Рисовать слабоконтрастные линии или стрелки с неясным направлением.
- Запрещать полезное исключение только ради единообразия.
- Принимать богатый редактор за доказательство понятной диаграммы.

## Связанные ограничения

- `actor-action-component-decomposition` формирует логические элементы до визуализации.
- `style-topology-fit` даёт топологию, которую схема должна передать, а не заменить.
- `decision-governance-last-moment` хранит причины выбора; диаграмма показывает результат, но не заменяет ADR.
- `architect-elastic-participation` определяет, с какой командой и в какой детализации обсуждать схему.
