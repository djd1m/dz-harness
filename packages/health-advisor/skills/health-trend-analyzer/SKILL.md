# Анализатор трендов здоровья

## Обзор

Анализатор трендов здоровья выполняет многомерный анализ данных о здоровье за определённый период, выявляя тренды, корреляции и значимые изменения. Навык охватывает вес/ИМТ, симптомы, приверженность приёму лекарств, результаты анализов, настроение и сон, формируя интерактивные HTML-отчёты с визуализацией на основе графиков ECharts.

## Зависимости

- **Read, Grep, Glob, Write** — Основные инструменты для чтения данных и формирования отчётов
- **data/profile.json** — Личный профиль (вес, рост, история ИМТ)
- **data/symptoms/\*\*/\*.json** — Записи симптомов
- **data/mood/\*\*/\*.json** — Записи настроения и сна
- **data/diet/\*\*/\*.json** — Записи о питании
- **data/medication-logs/\*\*/\*.json** — Журнал приёма лекарств
- **data/medical_records/\*\*/\*.json** — Результаты анализов
- **ECharts CDN** — Библиотека визуализации для интерактивных HTML-отчётов
- **data/health-reports/** — Директория сохранения сформированных отчётов

## Основные функции

### 1. Многомерный анализ трендов
- **Тренды веса/ИМТ**: Отслеживание изменений веса и ИМТ с течением времени, оценка трендов здоровья
- **Паттерны симптомов**: Выявление повторяющихся симптомов, изменений частоты, потенциальных триггеров
- **Приверженность приёму лекарств**: Анализ регулярности приёма, выявление паттернов пропусков и возможностей для улучшения
- **Тренды результатов анализов**: Отслеживание изменений биохимических показателей (холестерин, глюкоза крови, давление и др.)
- **Настроение и сон**: Корреляция эмоционального состояния с качеством сна, выявление трендов психического здоровья

### 2. Механизм корреляционного анализа
- **Корреляция лекарства-симптомы**: Определение связи нового препарата с изменением симптомов
- **Влияние образа жизни**: Корреляция питания/сна с симптомами и настроением
- **Оценка эффективности лечения**: Оценка того, привело ли лечение к улучшению
- **Корреляция цикла и симптомов**: Корреляция с менструальным циклом при отслеживании женского здоровья

### 3. Обнаружение изменений
- **Значимые изменения**: Предупреждения о быстром изменении веса, новых симптомах, смене лекарств
- **Паттерны ухудшения**: Раннее выявление снижения показателей здоровья
- **Выявление улучшений**: Подчёркивание положительных изменений здоровья
- **Пороговые оповещения**: Предупреждения при приближении к опасным уровням (радиация, экстремальные значения ИМТ)

### 4. Прогностические выводы
- **Оценка рисков**: Выявление факторов риска на основе трендов
- **Профилактические рекомендации**: Рекомендации по профилактическим мерам на основе паттернов
- **Раннее предупреждение**: Прогнозирование проблем до того, как они станут серьёзными

### HTML-отчёт с визуализацией (полная версия)

3. **График частоты симптомов**: Столбчатая диаграмма с цветовой кодировкой (высокая частота — красный/средняя — жёлтый/низкая — зелёный)

5. **График трендов результатов анализов**: Многосерийный линейный график + референсные линии
6. **Тепловая карта корреляций**: Отображение корреляций между переменными
7. **Площадная диаграмма настроения и сна**: Площадная диаграмма с двумя осями Y

**Особенности HTML-файла**:
- ✅ Полностью автономный (все зависимости через CDN)
- ✅ Интерактивные графики (масштабирование, экспорт, переключение легенды)

## Обработка ошибок

### Отсутствие данных
- **Нет данных**: Вывод «Данные отсутствуют, рекомендуется сначала записать [тип данных]»
- **Недостаточно данных**: Вывод «Данных недостаточно (для анализа трендов необходимо не менее 1 месяца данных)»
- **Узкий диапазон данных**: Использование имеющихся данных с пометкой «Рекомендуется продлить период записи для получения более точного тренда»

### Сбой анализа
- **Невозможно рассчитать тренд**: Вывод «Невозможно рассчитать тренд, недостаточно точек данных»
- **Сбой корреляционного анализа**: Вывод «Для корреляционного анализа необходимо больше данных»
- **Сбой отрисовки графиков**: Переход к текстовому отчёту

## Анти-паттерны

- **Постановка медицинских диагнозов** — Навык анализирует тренды данных, но не предназначен для диагностики заболеваний. Выявленные аномалии требуют подтверждения врачом.
- **Конкретные рекомендации по лекарствам** — Навык оценивает приверженность приёму и корреляцию с симптомами, но не должен рекомендовать изменение дозировки или замену препаратов.
- **Додумывание недостающих данных** — При отсутствии данных за период необходимо явно указать пробел, а не интерполировать или предполагать значения.
- **Оценка прогноза жизни** — Навык не предназначен для прогнозирования исходов заболеваний или оценки продолжительности жизни.
- **Передача данных во внешние сервисы** — Все данные хранятся и обрабатываются локально. Использование внешних API для анализа нарушает принцип конфиденциальности.
- **Формирование выводов на основе недостаточных данных** — Для анализа трендов необходимо не менее 1 месяца данных. Выводы на основе нескольких точек данных ненадёжны и не должны представляться как достоверные.

## Миграция на `sources/` (1.7.0) — КАНОНИЧЕСКИЙ layout первичных данных

С версии 1.7.0 у пакета ОДИН канонический layout первичных данных, и он определяется командой
`intake-archive` (см. `skills/intake-archive/SKILL.md`). Определение живёт в ОДНОМ машиночитаемом
месте — `lib/workspace-layout.js`; всё остальное его импортирует.

```
<workspace>/
  sources/
    raw/sha256-<64 hex>/    неизменяемые принятые архивы (только intake-archive)
    manifest.json           ИНДЕКС: строка на каждый принятый файл
    LOG.jsonl               append-only ЖУРНАЛ: строка на каждую попытку приёма, включая отказы
```

### Что во что переходит

| Было (этот документ, до 1.7.0) | Стало (канон 1.7.0) |
|---|---|
| `data/profile.json` | `profile.json` кейса — схема и гарантии у `case-state` (`skills/case-state/`) |
| `data/medical_records/**/*.json` | `sources/raw/sha256-<hex>/**` + строка в `sources/manifest.json` |

### Что канонического дома ПОКА НЕ ИМЕЕТ — сказано прямо, а не замазано

Остальные девять источников из таблицы выше (`data/symptoms/**`, `data/mood/**`, `data/diet/**`,
`data/medication-logs/**`, `data/cycle-tracker.json`, `data/pregnancy-tracker.json`,
`data/menopause-tracker.json`, `data/allergies.json`, `data/radiation-records.json`)
**канонического места в `sources/` пока не имеют**. Это честный незакрытый разрыв, а не недосмотр:
`sources/` спроектирован под НЕИЗМЕНЯЕМЫЕ первичные документы, а перечисленные — это
редактируемые пользователем временные ряды, и класть их в raw-зону значило бы соврать про их
природу. До отдельного решения они остаются там, где лежат.

### Принудительной миграции НЕТ

Ничего в 1.7.0 не читает, не переносит и не перезаписывает `data/**`. Воркспейс без `data/` ведёт
себя до и после 1.7.0 одинаково. Воркспейс С `data/` получает **громкое предупреждение**
`[LEGACY-LAYOUT]` — от `intake-archive` и от его отчёта `--verify`, и БОЛЬШЕ НИОТКУДА:
`ha check` остаётся без warn-режима по своей же доктрине («NO --warn mode and NO warn-only
outcome»), потому что warn внутри гейта — это то, как гейт тихо умирает.

`detectLegacyLayout()` делает `lstat`, а не `read`: чтобы обнаружить наличие старого дерева, файл
пациента открывать не нужно, и не открывать его — самая дешёвая из возможных позиций по приватности.
