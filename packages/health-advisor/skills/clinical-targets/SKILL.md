# Clinical Targets — цель ≠ референс

## Overview

Референсный интервал и клиническая цель отвечают на **разные вопросы**:

| | Референсный интервал | Клиническая цель |
|---|---|---|
| Вопрос | где находится бо́льшая часть популяции | где следует быть ИМЕННО этому пациенту при задокументированном состоянии |
| Источник истины | измеряющая лаборатория (зависит от анализатора и популяции) | названное руководство для названной группы пациентов |
| Меняется, когда | лаборатория сменила метод или популяцию | руководство пересмотрели |
| Что можно сказать | описательно: «внутри / ниже / выше интервала» | **клинически** — и только вместе с обоими числами, цитатой источника и рамкой «это не диагноз» |

Одно поле `status` не может нести оба чтения: второе молча затирает первое. Именно это и есть вред,
который скилл устраняет. Два примера из поля (**CLAIMED** — значения и пороги приведены так, как они
пришли в исходном обращении; ни один источник этим инструментом не открывался, поэтому обе цели
поставляются с классом доказательности `ASSERTED`. Арифметика этих пар — MEASURED, репродьюсер:
`cd packages/@dzhechkov/health-advisor && npm test`):

- **апоB 106 мг/дл** при референсе 66–133 мг/дл читается как «в норме», но при документированном
  атеросклерозе применимая цель — ниже 80 мг/дл: значение внутри интервала и при этом выше цели.
- **Насыщение трансферрина 53 %** (CLAIMED) при референсе `16–54 %` читается как «в норме», но у
  мужчин порог настороженности начинается с `45 %` (CLAIMED — из того же обращения).

Движок держит оба числа рядом навсегда и вычисляет их **расхождение** как поле, а не как фразу,
которую кто-то мог забыть написать.

## Как этим пользоваться

Движок лежит рядом со скиллом (`engine/`) и не требует ни одной внешней зависимости.

```bash
node engine/cli.js examples/apob-field-case.json   # готовый пример поля
node engine/cli.js input.json                      # свой файл
node engine/cli.js < input.json                    # или через stdin
```

Формат входа — ровно те строки, которые печатает `health-advisor-lab-results` (`coworker.py`),
плюс контекст пациента и, если он есть, референсный интервал из бумажного бланка лаборатории:

```json
{
  "rows": [
    { "test_name": "ApoB", "value": 106, "unit": "mg/dL",
      "reference_range": "-inf - inf", "status": "normal" }
  ],
  "patientContext": { "sex": "male", "conditions": ["documented_atherosclerosis"] },
  "labReport": { "ApoB": { "lo": 66, "hi": 133, "unit": "mg/dL" } }
}
```

Что вернётся (реальный вывод команды выше):

```text
апоB (аполипопротеин B): 106 mg/dL (1.060 g/L)
  Референс лаборатории: 66 – 133 mg/dL (источник: lab-report) → В ПРЕДЕЛАХ РЕФЕРЕНСА
  Цель из руководства: <80 mg/dL (<0.800 g/L) → ВЫШЕ ЦЕЛИ на 26 mg/dL
  Ваше значение выше цели: 106 mg/dL (1.060 g/L) против <80 mg/dL (<0.800 g/L).
  Порог: «…дословная цитата…» — организация, документ, раздел N, год [evidence: ASSERTED]
  Кому адресован порог: взрослые с документированным атеросклерозом. Ваш контекст сверен по полям:
  conditions — совпадение подтверждено.
  Это не диагноз. Референсный интервал приходит из вашей лаборатории; порог — из указанного
  источника для указанной группы пациентов. Решение о том, применим ли порог к вам, принимает врач.
  ⚠ РАСХОЖДЕНИЕ: значение внутри референсного интервала, но выше цели.
```

Три состояния, которые движок различает и НИКОГДА не сваливает в одно:

- **референс не указан** — лаборатория не дала интервала. Это не «в норме»: сравнивать не с чем.
- **контекст неизвестен** — цель существует, но данных, нужных чтобы понять, относится ли она к вам,
  нет. Движок называет недостающие поля и порог НЕ применяет.
- **на пороге в пределах точности** — |значение − порог| не превышает половины шага отчёта.
  Это не «выше» и не «ниже».

## Инструкция агенту (обязательная)

**Формулировки о цели берутся ТОЛЬКО из вывода движка: агент никогда не составляет фразу
«выше цели» / «ниже цели» сам.** Если движок не выдал такую строку — значит, у ситуации нет всех
трёх обязательных частей (оба числа + цитата источника + рамка «это не диагноз»), и утверждения
быть не должно. Пересказывать вывод можно; дописывать к нему вердикт — нельзя.

Дальше:

- показывайте оба числа рядом, в тех единицах, в которых они пришли, и в канонической единице;
- никогда не заменяйте референсный интервал целью и наоборот;
- если контекст пациента неизвестен — так и говорите, не подставляйте «обычно мужчина, обычно взрослый»;
- цитата источника и класс доказательности (`ASSERTED` / `LISTING_ONLY` / `FETCH_VERIFIED`) печатаются
  рядом с порогом всегда. `ASSERTED` означает, что источник никем в этом прогоне не открывался.

## Расширение реестра (только данными)

Новый показатель или новый порог — это JSON-файл, а не правка кода:

```text
engine/registry/
├── units.json                 единицы: {unit, dimension, factorToBase} — и ничего больше
├── analytes/<id>.json         единица хранения, шаг отчёта, молярная масса, синонимы
└── targets/<id>.json          порог, контекст применимости, ОБЯЗАТЕЛЬНАЯ цитата
```

Свой каталог подкладывается через `{"registryDirs": ["/путь"]}` во входном JSON. Списка разрешённых
показателей в коде нет: реестр принимает любой `analyteId`, который назвали данные.

Граница названа честно: данными расширяется то, что укладывается в существующую грамматику.
Порогу, которому нужен принципиально новый оператор применимости, или показателю, чьи единицы
пересекают неописанную размерность, нужна правка кода — и это правка кода, а не «добавь данные».

## Anti-Patterns

- ❌ **«В референсе — значит всё хорошо».** Референс — это популяция, а не цель.
- ❌ **Показать одно число.** Вывод без обоих чисел рядом — это потерянное чтение.
- ❌ **Порог без цитаты.** Конструктор упадёт: цель без цитаты — не «ухудшенная цель», а не цель.
- ❌ **Придумать правдоподобное название руководства**, чтобы цитата заполнилась. Это худший из
  доступных здесь отказов; класс доказательности для непроверенного порога — `ASSERTED`.
- ❌ **Применить порог к пациенту с несовпавшим или неизвестным контекстом.**
- ❌ **Подставить контекст по умолчанию** («считаем, что мужчина»): именно так молчаливое допущение
  превращается в утверждение о человеке.
- ❌ **Написать «выше цели» своими словами**, минуя движок.
- ❌ **Назвать отсутствие референса нормой** — состояние `NO_REFERENCE` существует ровно для этого.
- ❌ **Выдать вердикт или диагноз.** Словарь этого скилла: два числа, расхождение, цитата,
  контекст применимости, рамка «это не диагноз».

## Dependencies

- Node.js ≥ 18 — движок на CommonJS, **ноль внешних зависимостей**, запускается `node --test`.
- `health-advisor-lab-results` — источник входных строк (`coworker.py`). Читается как ДАННЫЕ:
  ни импорта, ни запуска чужого модуля из этого движка. Референсные интервалы принадлежат ему и
  бумажному бланку лаборатории; реестр целей их не хранит вовсе.
- Референсные интервалы из бланка пациента (необязательно) — они старше интервалов `coworker.py`.
- Класс доказательности используется тот же, что и в `references/evidence-levels.md` (только словарь,
  без импорта кода).

## Границы

Скилл не ставит диагноз, не назначает лечение и не выбирает между противоречащими порогами: если два
источника указывают в разные стороны, показываются оба и называется конфликт. Тренды во времени,
дозировки и «что делать» — вне области этого скилла.
