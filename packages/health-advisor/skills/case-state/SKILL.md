# Case State — профиль, факты и открытые вопросы

## Overview

Скилл закрывает один конкретный вред, который уже случался: **вывод был сделан на реальном числе
не того поколения**. Число было настоящим, корректно переписанным — и на полгода устаревшим. Снаружи
такой вывод неотличим от правильного, и ничто в пакете не могло увидеть разницу.

Три части, один модуль (`engine/`), один сеанс:

| Часть | Что даёт | Ключевое правило |
|---|---|---|
| **Профиль** | `labs` — плоский append-only список датированных наблюдений; `preanalytical_context`; указатель `open_questions` | «текущее» нигде не хранится — оно вычисляется `foldAsOf(profile, asOf)` |
| **Реестр фактов** | запись по ключу `(claim_hash, source_url)`, история `verifications[]` | повторная проверка ДОПИСЫВАЕТ запись, а не создаёт вторую |
| **Открытые вопросы** | долговечный журнал с `trigger_date` / `preconditions` | открытый блокирующий вопрос в области вывода делает вывод непостроимым |

### Несущее правило (ради него всё остальное)

> Ни один путь вывода не может использовать значение аналита, которое не было прочитано из профиля
> через `session.readAnalyte` в этом же вызове.

Механически это расписка: `openCase()` выдаёт сеанс, `readAnalyte()` чеканит `AnalyteReading` с
приватной для модуля меткой (`Symbol()`, никогда `Symbol.for()`), а `makeConclusion()` отвергает всё
остальное — голое число, объект-подделку и расписку ЧУЖОГО сеанса. Небезопасный вывод не запрещён —
он **непостроим**.

### Честная граница

Гарантия связывает выводы, построенные через `conclusion.js`. Свободная проза агента в ответе чату
не достижима ни для какого кода — и этот скилл этого не утверждает. Расписка доказывает, что чтение
БЫЛО, но не то, что прочитанное значение — именно то, которое затем пересказали словами.

## Порядок работы

1. Открыть сеанс на **явную** дату: `openCase({ profilePath, asOf })`. Нет профиля — нет сеанса;
   нет `asOf` — нет сеанса. Никакого неявного «сегодня».
2. Перечитать КАЖДОЕ значение перед КАЖДЫМ расчётом: `session.readAnalyte('triglycerides')`.
3. Построить вывод только из расписок: `makeConclusion({ session, readings, text })`.
4. Цитировать факт только через `makeCitedClaim({ fact, freshness, asOf, ttlTable })` — не-FRESH
   факт отказывается цитироваться, а обход требует непустой причины и печатает баннер, который
   нельзя отключить.
   - `asOf` и `ttlTable` **обязательны**: вердикт свежести — это ответ про ОДИН день и про ОДНУ
     TTL-таблицу. Вердикт, посчитанный на другую дату (или по другой таблице), отклоняется, а не
     принимается молча: иначе честный `FRESH` от января вечно ручается за апрельский отчёт.
   - Вердикт нельзя пересылать через воркер, IPC или сериализующий кэш: расписка — это идентичность
     объекта, и после JSON-раунда это уже обычный объект, который `makeCitedClaim` отклонит.
     Считайте свежесть там, где цитируете.
5. Кейс — это **одна директория**: и `open_questions.json` (через `$ref`), и `facts.json` лежат
   рядом с профилем. Область блокировки выводится из директории стора, поэтому стор в подпапке
   получил бы ОТДЕЛЬНУЮ блокировку — одна карточка с двумя областями. `$ref` с `/`, `\`, `..` или
   абсолютным путём отклоняется при загрузке профиля, с указанием причины.

## Output Conventions

Каждый отчёт называет путь профиля и дату свёртки:

```bash
node /path/to/@dzhechkov/health-advisor/skills/case-state/engine/cli.js profile validate /path/to/@dzhechkov/health-advisor/skills/case-state/engine/fixtures/profile.json 2026-01-01
node /path/to/@dzhechkov/health-advisor/skills/case-state/engine/cli.js profile diff /path/to/@dzhechkov/health-advisor/skills/case-state/engine/fixtures/profile.json 2026-04-15 2026-04-15
```

Коды возврата одинаковы у всех пяти глаголов: `0` — норма, `1` — ожидаемый отрицательный ответ
(профиль невалиден, есть расхождения, факт устарел или отсутствует, есть созревшие вопросы),
`2` — ошибка использования или нечитаемый вход.

## Anti-Patterns

| Антипаттерн | Почему это вред | Что делать |
|---|---|---|
| **BLOCK** — взять значение «из контекста разговора» | ровно тот дефект, ради которого написан скилл: число реальное, поколение чужое | `session.readAnalyte()` в этом же вызове |
| **BLOCK** — хранить поле `current` / `latest` рядом с историей | вторая копия истины расходится молча | свёртка `foldAsOf` на явную дату |
| **BLOCK** — процитировать факт, у которого `freshness ≠ FRESH`, без баннера | уверенная цитата на непроверённой копии | `makeCitedClaim` + непустая причина обхода |
| **BLOCK** — выпустить вывод, НАЗВАВ созревший блокирующий вопрос | «назвал, но не решил» — тихий обход, а не соблюдение | ответить на вопрос и записать ответ |
| **BLOCK** — записать в стор без `withCaseLock` | атомарная запись спасает от рваного файла, но не от потерянного обновления | обе мутации идут через один шов блокировки |
| Подставить дефолт вместо неизвестного | «мы не знаем» превращается в «мы знаем» | `FRESHNESS_UNKNOWN` и `usedDefault: true` — это состояния, а не отговорки |

## Dependencies

- **Node.js ≥ 18**, CommonJS, `node --test`.
- **Обязательных зависимостей нет.** Весь путь ЧТЕНИЯ (`openCase`, `readAnalyte`, `makeConclusion`,
  все пять глаголов CLI) синхронен и не требует ни одного пакета.
- **`@dzhechkov/harness-core` — необязательная зависимость**, нужна только двум МУТИРУЮЩИМ
  операциям (`facts.record`, `questions.answer`/`withdraw`): они берут общий `withStoreLock`. Если
  модуль не разрешается, запись **громко отказывается** (`CaseLockUnavailableError`) и не пишет
  ничего — в отдельной копии установленного скилла путь задаётся `HA_CASE_LOCK_MODULE`.
- Соседние скиллы (`preanalytical-guard`, `clinical-targets`, `goap-research-ed25519`,
  `lab-results`) — только для чтения; этот модуль ничего у них не импортирует и не дублирует.

## Данные, а не код

`engine/registry/recheck-ttl.json` (TTL по типу источника), `engine/registry/profile-required.json`
(обязательные секции — только ДОБАВЛЯЮТ к полу, зашитому в код) и
`engine/registry/derived-metrics.json` (формулы производных метрик). Новый тип источника — правка
данных; в `engine/*.js` нет ни одного имени типа источника и ни одного имени аналита.
