# Генератор экстренных медицинских карточек

## Обзор

Генератор экстренных медицинских карточек -- это навык для создания компактных сводок критически важной медицинской информации пациента для использования в экстренных ситуациях. Он извлекает данные об аллергиях, лекарствах, хронических заболеваниях и имплантатах из медицинских записей и формирует карточки в нескольких форматах (HTML с Tailwind CSS и Lucide-иконками, JSON, текст, QR-код) с приоритизацией по степени медицинской срочности.

## Основные функции

### 1. Извлечение экстренной информации
Извлечение наиболее критичной информации из данных о здоровье пользователя:
- **Тяжёлые аллергии**: приоритетное извлечение аллергий 4-го уровня (анафилактический шок) и 3-го уровня
- **Текущие лекарства**: названия, дозировки, частота приёма активных препаратов
- **Острые состояния**: медицинские состояния, требующие экстренного вмешательства
- **Имплантаты**: кардиостимуляторы, стенты и др. (влияют на обследования и лечение)
- **Контакты для экстренной связи**: информация о родственниках для быстрого контакта

### 2. Приоритизация информации
Сортировка информации по степени медицинской срочности:
1. **P0 -- Критическая информация**: анафилактический шок, тяжёлые лекарственные аллергии, угрожающие жизни заболевания
2. **P1 -- Важная информация**: текущие лекарства, хронические заболевания, имплантаты
3. **P2 -- Общая информация**: группа крови, возраст, вес, последние обследования

### 3. Многоформатный вывод
Поддержка нескольких форматов вывода для различных сценариев:
- **HTML-формат**: печатная веб-страница с Tailwind CSS и Lucide-иконками (рекомендуется)
- **JSON-формат**: структурированные данные для системной интеграции
- **Текстовый формат**: лаконичный и читаемый, подходит для печати и ношения с собой
- **PDF-формат**: профессиональная печать, долгосрочное хранение

#### HTML-формат (рекомендуемый)
Генерация автономного HTML-файла:
- Стили Tailwind CSS (через CDN)
- Иконки Lucide (через CDN)
- Адаптивный дизайн
- Оптимизация для печати
- Варианты размеров (A4, карточка для кошелька, крупный шрифт)
- Автоматическое определение типа карточки (стандартная, детская, для пожилых, для тяжёлых аллергий)

Использование:
```bash
# Генерация стандартной карточки (planned)
python scripts/generate_emergency_card.py

# Указание типа карточки (planned)
python scripts/generate_emergency_card.py standard
python scripts/generate_emergency_card.py child
python scripts/generate_emergency_card.py elderly
python scripts/generate_emergency_card.py severe

# Указание размера печати (planned)
python scripts/generate_emergency_card.py standard a4       # Стандарт A4
python scripts/generate_emergency_card.py standard wallet   # Карточка для кошелька
python scripts/generate_emergency_card.py standard large    # Крупный шрифт (для пожилых)
```

Выходной файл: `emergency-cards/emergency-card-{variant}-{YYYY-MM-DD}.html`

### 4. Автономная работа
- Сохранение на телефон (галерея, файлы)
- Печать для ношения с собой (кошелёк, сумка)
- Резервное копирование в облако (опционально)

### Порядок выполнения

#### Шаг 1: Чтение базовых данных пользователя
Чтение информации из следующих источников:

```javascript
// 1. Профиль пользователя
const profile = readFile('data/profile.json');

// 2. История аллергий
const allergies = readFile('data/allergies.json');

// 3. Текущие лекарства
const medications = readFile('data/medications/medications.json');

// 4. Записи о радиации
const radiation = readFile('data/radiation-records.json');

// 5. Хирургические записи (поиск имплантатов)
const surgeries = glob('data/surgical-records/**/*.json');

// 6. Выписные эпикризы (поиск острых состояний)
const dischargeSummaries = glob('data/discharge-summaries/**/*.json');
```

#### Шаг 2: Извлечение ключевой информации

#### 2.1 Базовая информация
```javascript
const basicInfo = {
  name: profile.basic_info?.name || "Не указано",
  age: calculateAge(profile.basic_info?.birth_date),
  gender: profile.basic_info?.gender || "Не указано",
  blood_type: profile.basic_info?.blood_type || "Неизвестно",
  weight: `${profile.basic_info?.weight} ${profile.basic_info?.weight_unit}`,
  height: `${profile.basic_info?.height} ${profile.basic_info?.height_unit}`,
  bmi: profile.calculated?.bmi,
  emergency_contacts: profile.emergency_contacts || []
};
```

#### 2.2 Тяжёлые аллергии (P0)
```javascript
// Фильтрация аллергий 3-4 уровня тяжести
const criticalAllergies = allergies.allergies
  .filter(a => a.severity_level >= 3 && a.current_status.status === 'active')
  .map(a => ({
    allergen: a.allergen.name,
    severity: `Аллергия ${getSeverityLabel(a.severity_level)} (${a.severity_level} уровень)`,
    reaction: a.reaction_description,
    diagnosed_date: a.diagnosis_date
  }));
```

#### 2.3 Хронические заболевания (P1)
```javascript
// Извлечение диагнозов из данных по хроническим заболеваниям
const chronicConditions = [];

// Гипертония
try {
  const hypertensionData = readFile('data/hypertension-tracker.json');
  if (hypertensionData.hypertension_management?.diagnosis_date) {
    chronicConditions.push({
      condition: 'Гипертония',
      diagnosis_date: hypertensionData.hypertension_management.diagnosis_date,
      classification: hypertensionData.hypertension_management.classification,
      current_bp: hypertensionData.hypertension_management.average_bp,
      risk_level: hypertensionData.hypertension_management.cardiovascular_risk?.risk_level
    });
  }
} catch (e) {
  // Файл не существует или ошибка чтения, пропускаем
}

// Диабет
try {
  const diabetesData = readFile('data/diabetes-tracker.json');
  if (diabetesData.diabetes_management?.diagnosis_date) {
    chronicConditions.push({
      condition: diabetesData.diabetes_management.type === 'type_1' ? 'Сахарный диабет 1 типа' : 'Сахарный диабет 2 типа',
      diagnosis_date: diabetesData.diabetes_management.diagnosis_date,
      duration_years: diabetesData.diabetes_management.duration_years,
      hba1c: diabetesData.diabetes_management.hba1c?.history?.[0]?.value,
      control_status: diabetesData.diabetes_management.hba1c?.achievement ? 'Хороший контроль' : 'Требуется улучшение'
    });
  }
} catch (e) {
  // Файл не существует или ошибка чтения, пропускаем
}

// ХОБЛ
try {
  const copdData = readFile('data/copd-tracker.json');
  if (copdData.copd_management?.diagnosis_date) {
    chronicConditions.push({
      condition: 'ХОБЛ',
      diagnosis_date: copdData.copd_management.diagnosis_date,
      gold_grade: `GOLD ${copdData.copd_management.gold_grade} степени`,
      cat_score: copdData.copd_management.symptom_assessment?.cat_score?.total_score,
      exacerbations_last_year: copdData.copd_management.exacerbations?.last_year
    });
  }
} catch (e) {
  // Файл не существует или ошибка чтения, пропускаем
}
```

#### 2.4 Текущие лекарства (P1)
```javascript
// Включение только активных препаратов
const currentMedications = medications.medications
  .filter(m => m.active === true)
  .map(m => ({
    name: m.name,
    dosage: `${m.dosage.value}${m.dosage.unit}`,
    frequency: getFrequencyLabel(m.frequency),
    instructions: m.instructions,
    warnings: m.warnings || []
  }));
```

#### 2.5 Медицинские состояния
Извлечение диагнозов из выписных эпикризов:
```javascript
const medicalConditions = dischargeSummaries
  .flatMap(ds => {
    const data = readFile(ds.file_path);
    return data.diagnoses || [];
  })
  .map(d => ({
    condition: d.condition,
    diagnosis_date: d.date,
    status: d.status || "На наблюдении"
  }));
```

#### 2.6 Имплантаты
Извлечение информации об имплантатах из хирургических записей:
```javascript
const implants = surgeries
  .flatMap(s => {
    const data = readFile(s.file_path);
    return data.procedure?.implants || [];
  })
  .map(i => ({
    type: i.type,
    implant_date: i.date,
    hospital: i.hospital,
    notes: i.notes
  }));
```

#### 2.7 Недавнее радиационное облучение
```javascript
const recentRadiation = {
  total_dose_last_year: calculateTotalDose(radiation.records, 'last_year'),
  last_exam: radiation.records[radiation.records.length - 1]
};
```

#### Шаг 3: Генерация карточки

Организация информации по приоритету:
```javascript
const emergencyCard = {
  version: "1.0",
  generated_at: new Date().toISOString(),
  basic_info: basicInfo,
  critical_allergies: criticalAllergies.sort(bySeverityDesc),
  current_medications: currentMedications,
  medical_conditions: [...medicalConditions, ...chronicConditions],
  implants: implants,
  recent_radiation_exposure: recentRadiation,
  disclaimer: "Данная карточка носит справочный характер и не заменяет профессиональную медицинскую диагностику",
  data_source: "my-his -- персональная система медицинской информации",
  chronic_conditions: chronicConditions
};
```

## Источники данных

### Основные источники
- **data/profile.json**: базовая информация пользователя, группа крови, контакты для экстренной связи
- **data/allergies.json**: история аллергий и классификация тяжести
- **data/medications/medications.json**: текущий план приёма лекарств и дозировки

### Данные по хроническим заболеваниям
- **data/hypertension-tracker.json**: данные по гипертонии (дата диагноза, степень, контроль АД, поражение органов-мишеней, сердечно-сосудистый риск)
- **data/diabetes-tracker.json**: данные по диабету (тип, HbA1c, контроль гликемии, скрининг осложнений)
- **data/copd-tracker.json**: данные по ХОБЛ (степень GOLD, оценка CAT, история обострений, функция лёгких)

### Вспомогательные источники
- **data/radiation-records.json**: записи о недавнем радиационном облучении
- **data/surgical-records/**/*.json**: информация об имплантатах из хирургических записей
- **data/discharge-summaries/**/*.json**: диагностическая информация из выписных эпикризов

### Опциональные источники
- **data/index.json**: глобальный индекс данных

## Принципы безопасности

### Обязательные требования
- Не добавлять рекомендации по лекарствам (только перечислять текущие препараты)
- Не предоставлять диагностические заключения (только перечислять известные диагнозы)
- Не давать рекомендаций по лечению (не заменяет врача)
- Включать отказ от ответственности (только справочная информация)

### Точность информации
- Извлекать только зафиксированную информацию (не предполагать и не делать выводов)
- Указывать источник информации и время обновления
- Рекомендовать регулярное обновление информации

### Защита конфиденциальности
- Конфиденциальная информация может быть скрыта по выбору
- Частичное сокрытие телефонных номеров (например: +7 (9**) ***-**-34)
- Все данные хранятся только локально

## Обработка ошибок

### Отсутствие данных
- **Нет данных об аллергиях**: вывод "История аллергий не зафиксирована"
- **Нет данных о лекарствах**: вывод "Текущие лекарства не зафиксированы"
- **Нет данных об имплантатах**: вывод "Имплантаты отсутствуют"

### Ошибки чтения файлов
- **Невозможно прочитать profile.json**: использование значений по умолчанию (ФИО: Не указано)
- **Невозможно прочитать allergies.json**: пропуск информации об аллергиях
- **Продолжение генерации остальной информации**: сбой одного файла не прерывает процесс

### Ошибка генерации QR-кода
- Переход на текстовый формат вывода
- Предложение пользователю записать информацию вручную

## Антипаттерны

- **Добавление медицинских рекомендаций**: карточка должна только перечислять факты (аллергии, лекарства, диагнозы), а не давать советы по лечению или корректировке препаратов.
- **Игнорирование приоритизации**: вывод всей информации одним списком без разделения по уровням срочности (P0/P1/P2), что затрудняет быстрый поиск критических данных в экстренной ситуации.
- **Неполное сокрытие персональных данных**: отображение полных номеров телефонов, адресов и других конфиденциальных данных без маскирования.
- **Генерация без отказа от ответственности**: каждая карточка обязана содержать предупреждение о справочном характере информации.
- **Остановка при ошибке одного источника**: сбой чтения одного файла данных не должен прерывать генерацию остальных разделов карточки.
- **Устаревшие данные без предупреждения**: генерация карточки на основе данных старше 3 месяцев без явного указания даты последнего обновления.

## Зависимости

- **Tailwind CSS v3.4** (CDN): используется для стилей HTML-карточек.
- **Lucide Icons v0.263** (CDN): используется для иконок в HTML-карточках.
- Внешние API и навыки не требуются. Генерация QR-кодов выполняется локально.
