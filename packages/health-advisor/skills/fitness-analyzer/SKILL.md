# Навык анализа физической активности

## Обзор

Навык анализа физической активности предназначен для комплексного анализа данных о тренировках, выявления паттернов и трендов, отслеживания прогресса и генерации персонализированных рекомендаций. Основные возможности включают корреляционный анализ физической активности с показателями здоровья (артериальное давление, глюкоза, вес), расчёт энергетического обмена и статистическую оценку трендов на основе руководств WHO/ACSM/AHA.

## Зависимости

- **Read, Grep, Glob, Write** — Основные инструменты для чтения и записи данных
- **data/fitness-logs/** — Журнал тренировок (JSON-файлы с записями тренировок)
- **data/fitness-tracker.json** — Профиль пользователя, фитнес-цели, статистика
- **data/hypertension-tracker.json** — Данные об артериальном давлении (для корреляционного анализа)
- **data/diabetes-tracker.json** — Данные об уровне глюкозы (для корреляционного анализа)
- **data/profile.json** — Вес, ИМТ и другие личные данные

## Интеграция с другими скиллами

- Данные о питании (nutrition-analyzer) используются для корреляции с результатами тренировок
- Показатели здоровья (lab-results, health-trend-analyzer) определяют ограничения по интенсивности
- При наличии реабилитационных данных → использовать rehabilitation-analyzer

## Функции

### 1. Анализ трендов физической активности
Анализ тенденций изменения объёма, частоты и интенсивности тренировок, выявление улучшений или областей, требующих корректировки.

**Аналитические измерения**:
- Тренды объёма нагрузки (продолжительность, расстояние, калории)
- Тренды частоты тренировок (количество тренировочных дней в неделю)
- Изменения распределения интенсивности (доля низкой/средней/высокой интенсивности)
- Изменения предпочтений по типам тренировок

**Выходные данные**:
- Направление тренда (улучшение/стабильность/снижение)
- Величина изменения и проценты
- Значимость тренда
- Рекомендации по улучшению

### 2. Отслеживание прогресса
Отслеживание прогресса в определённых видах физической активности, количественная оценка эффективности тренировок.

**Поддерживаемые виды отслеживания прогресса**:
- **Прогресс в беге**: Улучшение темпа, увеличение дистанции, улучшение пульса
- **Прогресс в силовых тренировках**: Увеличение веса, рост объёма, изменение RPE
- **Прогресс в выносливости**: Увеличение продолжительности, удлинение дистанции
- **Прогресс в гибкости**: Улучшение подвижности суставов

**Выходные данные**:
- Начальное значение vs текущее значение
- Процент улучшения
- Визуализация прогресса
- Достигнутые вехи

### 3. Анализ привычек физической активности
Определение привычек и паттернов физической активности пользователя.

**Содержание анализа**:
- Предпочтительное время тренировок (утро/день/вечер)
- Паттерн частоты тренировок (сколько дней в неделю)
- Предпочтения по типам тренировок
- Распределение дней отдыха
- Оценка последовательности тренировок

**Выходные данные**:
- Сводка по привычкам
- Оценка последовательности (0-100)
- Рекомендации по оптимизации
- Рекомендации по формированию привычек

### 4. Корреляционный анализ
Анализ взаимосвязей между физической активностью и другими показателями здоровья.

**Поддерживаемые виды корреляционного анализа**:
- **Тренировки ↔ Вес**: Связь расхода энергии при тренировках с изменением веса
- **Тренировки ↔ Артериальное давление**: Долгосрочное влияние тренировок на артериальное давление
- **Тренировки ↔ Уровень глюкозы**: Эффективность тренировок в контроле глюкозы крови
- **Тренировки ↔ Настроение/Сон**: Влияние тренировок на настроение и сон

**Выходные данные**:
- Коэффициент корреляции (от -1 до 1)
- Сила корреляции (слабая/средняя/сильная)
- Статистическая значимость
- Выводы о причинно-следственных связях
- Практические рекомендации

### 5. Генерация персонализированных рекомендаций
Генерация персонализированных рекомендаций по тренировкам на основе данных пользователя.

**Типы рекомендаций**:
- **Рекомендации по частоте тренировок**: Необходимо ли увеличить/уменьшить частоту тренировок
- **Рекомендации по интенсивности тренировок**: Рекомендации по корректировке интенсивности
- **Рекомендации по типам тренировок**: Предлагаемые виды тренировок для освоения
- **Рекомендации по времени тренировок**: Оптимальное время для тренировок
- **Рекомендации по восстановлению**: Рекомендации по отдыху и восстановлению

**Основания для рекомендаций**:
- Руководства WHO/ACSM/AHA по физической активности
- Историческая информация о тренировках пользователя
- Состояние здоровья пользователя
- Фитнес-цели пользователя

## Описание алгоритмов

### 1. Анализ трендов методом линейной регрессии

Использование линейной регрессии для анализа временных трендов данных о тренировках.

**Формула**:
y = a + bx

Где:
- y: Показатель тренировки (продолжительность, калории, расстояние и др.)
- x: Время
- a: Точка пересечения с осью
- b: Наклон (направление и скорость тренда)

**Интерпретация**:
- b > 0: Восходящий тренд
- b < 0: Нисходящий тренд
- b ≈ 0: Стабильность

**Псевдокод расчёта наклона линейной регрессии**:

```
Вход: массив точек (x[], y[]) длиной N
1. Вычислить средние: x̄ = сумма(x) / N,  ȳ = сумма(y) / N
2. Инициализировать числитель = 0, знаменатель = 0
3. Для каждого i от 0 до N-1:
     числитель += (x[i] - x̄) * (y[i] - ȳ)
     знаменатель += (x[i] - x̄)²
4. Если знаменатель = 0 → тренд не определён (все точки на одной дате)
5. b = числитель / знаменатель
6. a = ȳ - b * x̄
7. Вернуть {наклон: b, пересечение: a}
```

**Оценка значимости тренда**: Если количество точек данных < 4, пометить тренд как «ненадёжный». Для надёжной оценки рекомендуется ≥ 8 точек (2+ недели данных).

### 2. Коэффициент корреляции Pearson

Используется для анализа линейной корреляции между двумя переменными.

**Формула**:
r = Σ[(xi - x̄)(yi - ȳ)] / √[Σ(xi - x̄)² × Σ(yi - ȳ)²]

**Диапазон**: -1 ≤ r ≤ 1

**Интерпретация**:
- r = 1: Полная положительная корреляция
- r = -1: Полная отрицательная корреляция
- r = 0: Отсутствие линейной корреляции

**Оценка силы**:
- |r| < 0,3: Слабая корреляция
- 0,3 ≤ |r| < 0,7: Средняя корреляция
- |r| ≥ 0,7: Сильная корреляция

**Псевдокод расчёта коэффициента Pearson**:

```
Вход: массивы x[], y[] одинаковой длины N
1. Проверка предусловий:
     - N ≥ 5 (минимум для осмысленной корреляции)
     - Оба массива содержат числовые значения без NaN/null
2. Вычислить средние: x̄ = сумма(x) / N,  ȳ = сумма(y) / N
3. Инициализировать: sum_xy = 0, sum_x2 = 0, sum_y2 = 0
4. Для каждого i от 0 до N-1:
     dx = x[i] - x̄
     dy = y[i] - ȳ
     sum_xy += dx * dy
     sum_x2 += dx²
     sum_y2 += dy²
5. знаменатель = √(sum_x2 * sum_y2)
6. Если знаменатель = 0 → корреляция не определена (одна из переменных постоянна)
7. r = sum_xy / знаменатель
8. Вернуть r (округлить до 2 знаков)
```

**Проверка применимости**: Коэффициент Pearson предполагает линейную зависимость и нормальное распределение данных. Перед расчётом рекомендуется визуально оценить разброс данных. При явно нелинейной зависимости или наличии выбросов результат может быть недостоверным — в таких случаях рассмотреть коэффициент Спирмена.

### 3. Расчёт темпа

**Темп** = Продолжительность тренировки / Расстояние

Единицы: мин/км или мин/миля

**Пример**:
- 30 минут бега на 5 км
- Темп = 30 / 5 = 6 мин/км

### 4. Расчёт энергетического обмена по MET

**Расход калорий** = MET × Вес (кг) × Время (часы)

**Значения MET для распространённых видов активности**:
- Ходьба (3-5 км/ч): 3,5-5 MET
- Бег трусцой (8 км/ч): 8 MET
- Быстрый бег (10 км/ч): 10 MET
- Плавание: 6-10 MET
- Велосипед (прогулочный): 4 MET
- Силовые тренировки: 5 MET
- Йога: 3 MET

⚠️ **Важное заявление**
Данный анализ предоставляется исключительно в информационных целях и не является медицинской рекомендацией.

### Границы аналитических возможностей

✅ **Что может**:
- Статистика и анализ данных о тренировках
- Выявление и визуализация трендов
- Расчёт и интерпретация корреляций
- Общие рекомендации по физической активности

❌ **Что не может**:
- Диагностика заболеваний
- Оценка рисков при тренировках
- Составление конкретных тренировочных программ
- Диагностика и лечение спортивных травм

### Обнаружение тревожных сигналов

В процессе анализа обнаруживаются следующие тревожные сигналы:

1. **Аномальный пульс**
   - Пульс при тренировке > 95% максимального пульса
   - Пульс в покое > 100 bpm

2. **Аномальное артериальное давление**
   - Систолическое давление ≥ 180 мм рт.ст.
   - Диастолическое давление ≥ 110 мм рт.ст.

3. **Признаки перетренированности**
   - 7 дней подряд высокоинтенсивных тренировок
   - Постоянное ухудшение субъективных ощущений (RPE > 17)

4. **Быстрое снижение веса**
   - Потеря веса > 1 кг в неделю (может быть нездоровым)

**Level 1: Общие рекомендации**
- На основе руководств WHO/ACSM
- Применимы к общей популяции

**Level 2: Справочные рекомендации**
- На основе данных пользователя
- Необходимо учитывать индивидуальные особенности

**Level 3: Медицинские рекомендации**
- Связаны с управлением заболеваниями
- Требуют подтверждения врача

## Примеры использования

### Пример 1: Формирование отчёта по трендам тренировок

```bash
/fitness trend 3months
```

Вывод:
- Анализ трендов тренировок за 3 месяца
- Изменения объёма, частоты и интенсивности

- Практические рекомендации

## Анти-паттерны

- **Диагностика заболеваний на основе данных о тренировках** — Навык анализирует статистику тренировок, но не предназначен для постановки медицинских диагнозов. Аномальные показатели пульса или давления требуют консультации врача.
- **Составление конкретных тренировочных программ** — Навык предоставляет общие рекомендации по частоте и интенсивности, но не заменяет индивидуальную программу от сертифицированного тренера.
- **Игнорирование тревожных сигналов** — При обнаружении аномального пульса (>95% максимального), давления (≥180/110) или признаков перетренированности необходимо немедленно рекомендовать обращение к врачу, а не продолжать анализ.
- **Применение корреляций как причинно-следственных связей** — Корреляция между тренировками и показателями здоровья (например, r=-0,68 для давления) не означает прямую причинно-следственную связь. Всегда указывать это ограничение.
- **Анализ данных за слишком короткий период** — Для достоверного анализа трендов необходимо не менее 4 недель данных. Выводы на основе нескольких дней ненадёжны.

## Структура данных

### Схема записи тренировки (JSON)

Каждый файл в `data/fitness-logs/YYYY-MM/YYYY-MM-DD.json` содержит массив записей тренировок за день.

**Пример записи**:

```json
{
  "date": "2026-03-15",
  "type": "running",
  "duration_min": 35,
  "distance_km": 4.5,
  "intensity": "moderate",
  "hr_avg": 142,
  "hr_max": 168,
  "calories": 390,
  "rpe": 13,
  "exercises": null,
  "notes": "Лёгкий бег в парке, хорошее самочувствие"
}
```

### Обязательные поля

| Поле | Тип | Допустимые значения | Описание |
|------|-----|---------------------|----------|
| `date` | string (ISO 8601) | `"YYYY-MM-DD"` | Дата тренировки |
| `type` | string (enum) | `"running"`, `"strength"`, `"yoga"`, `"hiit"`, `"swimming"`, `"cycling"`, `"walking"`, `"other"` | Тип тренировки |
| `duration_min` | number (int) | 1–600 | Продолжительность в минутах |
| `intensity` | string (enum) | `"low"`, `"moderate"`, `"high"` | Уровень интенсивности |
| `calories` | number (int) | 0–5000 | Расход калорий (ккал) |

### Необязательные поля

| Поле | Тип | Допустимые значения | Описание |
|------|-----|---------------------|----------|
| `distance_km` | number (float) | 0.1–200 | Дистанция в км (для кардио) |
| `hr_avg` | number (int) | 40–220 | Средний пульс (bpm) |
| `hr_max` | number (int) | 40–230 | Максимальный пульс (bpm) |
| `rpe` | number (int) | 6–20 | Оценка воспринимаемой нагрузки по шкале Борга |
| `exercises` | array of strings | — | Список упражнений (для силовых тренировок) |
| `notes` | string | — | Произвольные заметки |

### Правила валидации

- `hr_avg` должен быть ≤ `hr_max` (если оба указаны)
- `hr_max` не должен превышать 230 bpm (физиологический предел)
- `duration_min` > 0
- `calories` должен быть положительным числом
- `date` не должна быть в будущем
- Файл должен содержать валидный JSON (массив объектов или один объект)

## Обработка ошибок

| Ошибка | Условие обнаружения | Действие |
|--------|---------------------|----------|
| Отсутствие директории `fitness-logs` | `Glob('data/fitness-logs/**/*.json')` возвращает пустой результат | Вывести сообщение: «Директория с журналом тренировок не найдена. Необходимо создать `data/fitness-logs/` и добавить записи тренировок.» Прервать анализ. |
| Недостаточно данных (<2 недель) | Количество уникальных дат тренировок < 4 или временной диапазон < 14 дней | Вывести сообщение: «Недостаточно данных для анализа трендов. Для надёжного анализа необходимо минимум 2 недели записей (рекомендуется 4+ недели). Текущих записей: {N}.» Предложить краткую сводку без трендов. |
| Некорректные значения пульса | `hr_avg` или `hr_max` вне диапазона 40–230, или `hr_avg` > `hr_max` | Пометить запись как содержащую аномалию. Исключить из расчётов средних значений пульса. Вывести предупреждение: «Обнаружены некорректные значения пульса в записях за {даты}. Эти записи исключены из анализа пульса.» |
| Отсутствие профиля пользователя | Файл `data/fitness-tracker.json` или `data/profile.json` не найден или не содержит `current_weight_kg` / `age` | Продолжить анализ без расчёта калорий по MET и без персонализированных зон пульса. Вывести предупреждение: «Профиль пользователя не найден. Расчёт калорий по MET и зон пульса невозможен. Создайте файл профиля для полного анализа.» |
| Повреждённые JSON-файлы | Ошибка парсинга JSON при чтении файлов из `fitness-logs` | Пропустить повреждённый файл. Вывести предупреждение: «Не удалось прочитать файл {путь}: ошибка формата JSON. Файл пропущен.» Продолжить анализ с оставшимися файлами. |
| Дублирующиеся записи | Несколько записей с одинаковыми `date` и `type` и `duration_min` | Оставить первую запись, игнорировать дубликаты. Вывести информацию: «Обнаружены дублирующиеся записи за {даты}. Использована первая запись.» |
| Значения вне допустимого диапазона | `duration_min` > 600, `calories` > 5000, `distance_km` > 200 | Пометить как выброс. Включить в отчёт с пометкой ⚠️. Не использовать в расчёте средних значений. |

## Справочные ресурсы

### Основные руководства

1. **WHO Guidelines on Physical Activity and Sedentary Behaviour (2020)**
   - Рекомендации: 150–300 мин/нед умеренной или 75–150 мин/нед интенсивной аэробной активности
   - Силовые тренировки: ≥ 2 раза в неделю
   - Ссылка: https://pubmed.ncbi.nlm.nih.gov/33239350/

2. **ACSM's Guidelines for Exercise Testing and Prescription (11th ed.)**
   - Стандарты нагрузочного тестирования, зоны пульса, классификация интенсивности
   - PMID: 29028741
   - Ссылка: https://pubmed.ncbi.nlm.nih.gov/29028741/

3. **Compendium of Physical Activities (Ainsworth et al., 2011)**
   - Справочник значений MET для всех видов физической активности
   - PMID: 21681120
   - Ссылка: https://pubmed.ncbi.nlm.nih.gov/21681120/

4. **Borg RPE Scale — Psychophysical bases of perceived exertion (Borg, 1982)**
   - Шкала воспринимаемой нагрузки (6–20), используется для оценки интенсивности тренировок
   - PMID: 7154893
   - Ссылка: https://pubmed.ncbi.nlm.nih.gov/7154893/

### Дополнительные источники

5. **AHA Scientific Statement: Physical Activity and Blood Pressure (2018)**
   - Влияние аэробных тренировок на снижение артериального давления (5–7 мм рт.ст.)
   - PMID: 29146534
   - Ссылка: https://pubmed.ncbi.nlm.nih.gov/29146534/

6. **ACSM Position Stand: Quantity and Quality of Exercise (2011)**
   - Рекомендации по объёму, частоте и интенсивности тренировок для взрослых
   - PMID: 21694556
   - Ссылка: https://pubmed.ncbi.nlm.nih.gov/21694556/

## Безопасность и конфиденциальность

### Обязательные правила

- ❌ Не ставить медицинские диагнозы на основе данных о тренировках
- ❌ Не составлять конкретные тренировочные программы (это компетенция сертифицированного тренера)
- ❌ Не давать рекомендаций по лекарствам на основе корреляций
- ❌ Не оценивать прогноз заболеваний
- ❌ Всегда включать отказ от ответственности (только для информационных целей)

### Точность информации

- ✅ Анализ только на основе записанных данных
- ✅ Не предполагать и не интерполировать недостающие значения
- ✅ Чётко указывать источник данных, временной диапазон и количество записей
- ✅ Корреляция не означает причинно-следственную связь — всегда указывать это ограничение
- ✅ Рекомендации должны быть проверены медицинским специалистом

### Защита конфиденциальности

- ✅ Все данные хранятся и обрабатываются локально
- ✅ Без вызовов внешних API и сервисов
- ✅ Результаты анализа сохраняются только на устройстве пользователя
- ✅ Данные пациентов не передаются третьим сторонам
- ✅ При формировании примеров и отчётов для демонстрации — использовать только анонимизированные данные
