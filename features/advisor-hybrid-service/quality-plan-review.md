## Candidate P1 — requires independent validation before owner-facing escalation

**C8/C6: Migration does not specify what happens to the second persistent ledger.** NFR-2 explicitly says reuse request/admission ledgers without resets. `preview-server.mjs:createPreview` owns `requestLedger.reserve()`; `liveAnswer()` does not. This is an ambiguity grounded in real call ownership, not a demand to add another limiter.

## P2 notes

- **C2/C8 — Writable state is a directory contract.** Read-only container root is compatible with existing admission only when its writable parent directory supports sibling `.lock`/temporary files and atomic rename/fsync. A file-only bind mount fails immediately or on reserve. Pin container UID, writable directory mount, state initialization outside startup, and absolute path mapping in the assembly/runbook; test with actual container filesystem restrictions.
- **C2/C3 — Crash restart differs from graceful restart.** Both current ledgers acquire exclusive persistent `.lock` files and remove them only on close. SIGKILL/OOM leaves a lock; automatic restart then fails. This is inherited fail-closed behavior, not a new security defect. Include an explicit operator recovery rule that verifies the prior owner stopped, never resets counts, and exercise forced-stop recovery if claiming restart support. Do not silently auto-delete a potentially live lock.
- **C2/C6 — Name the end-to-end time budget and cancellation owner.** Current proxy uses 65 s, selector uses an independent 60 s timeout. Adding embedding/search can exceed the old envelope; direct callback injection can also bypass proxy timeout entirely. Choose and test an overall deadline plus bounded retrieval, retain one-active admission until actual work stops, and avoid releasing reservation while a raced callback still makes paid calls. No need for a new scheduler.
- **C3 — Strengthen falsification of stated boundaries.** Include wrong-revision HTTP response with apparently valid IDs, unknown/duplicate IDs, malformed/nonfinite vectors, failed-build cleanup preserving the old generation, and denied origin/exhausted ledger asserting zero embedding *and* selector calls. Real Lance/container tests remain necessary; provider fakes are appropriate for deterministic failure/count checks. Existing frozen live semantic checks establish answer quality separately.
- **C8 — Make the cross-repository build reproducible.** TASK-4 says pinned source trees but expected targets omit the site handler, entrypoint, Dockerfiles/Compose, and source packaging recipe. Specify exact source inputs/commit recording and artifact assembly so a second operator can build without access to an author's incidental checkout or host paths. Explicit source packaging also makes no-host-source-mount/no-secret-image checks meaningful.
