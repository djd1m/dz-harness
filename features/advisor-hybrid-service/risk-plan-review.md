# Risk review of implementation plan

Read requirements, all three ADRs, architecture, plan, and actual site HTTP/admission implementation. Advice: architecture is viable; make these acceptance criteria explicit before implementation. These are concrete plan gaps, not claims that unwritten code already has defects.

1. **High — ledger mounts must support existing atomic writes.** `advisor-admission.mjs` creates sibling `.lock` and temporary files, renames over the state file, and fsyncs its directory. A single-file bind mount or read-only parent fails on first reservation; a fresh named volume can silently select a new trial. Mount the existing dedicated private state directory writable to advisor only, preserve exact files/format, preflight ownership for the nonroot UID, and fail if state is absent. Test a seeded nonzero ledger across container recreation and rejected writes; include the existing model/request ledger, not only admission.
2. **High — answer injection must retain ownership until work actually stops.** Current HTTP code releases admission in `finally` when its awaited upstream operation settles. A new `Promise.race` timeout around a callback can release while embedding/selection continues, allowing a second paid request and breaking one-active semantics. Pass one deadline/abort signal through embedding, search and selector; do not release the active reservation until callback termination is confirmed. Test slow provider, client disconnect, timeout followed by another request, and SIGTERM while active. Failed/aborted requests must retain already committed counts; no automatic retries or refunds.
3. **Medium — crash recovery is missing from the lock lifecycle.** `openAdmission` uses an empty exclusive `.lock` file deleted only on orderly close. SIGKILL/OOM leaves the next container unable to start. Keep fail-closed behavior, document explicit stale-lock recovery only after verifying the previous owner is stopped, and test SIGKILL/restart without resetting counters. Do not blindly delete locks on startup; that defeats mutual exclusion during overlapping replacements. Set stop grace longer than bounded provider drain or explicitly document forced-stop recovery.
4. **High — revision validation must cross the advisor/search boundary.** A self-consistent old snapshot can pass search startup while advisor uses the newly approved catalog after TASK-2. Require the advisor's independently computed expected revision/model/dimension/lexicalizer identity in every search request (or an equally strong startup handshake plus response binding), verify returned revision and IDs, and never attach old retrieval IDs to new records unnoticed. On mismatch use explicit current-catalog lexical fallback or fail startup. Test mismatched old/new containers, not just a corrupt local manifest.
5. **Medium — health checks must be free and compatible with API-only routing.** Existing `apiOnly` HTTP returns 404 for all GET routes and requires exact `Host: aicoding.space`; a default localhost root probe therefore makes a healthy advisor unhealthy. Add a bounded local health route that makes no provider call and consumes no admission, or an equivalent TCP/process probe. Search degradation must not make advisor restart endlessly when lexical fallback works. Test probes with exhausted quota and search unavailable; verify they leave both ledgers unchanged.

Existing strong controls worth retaining: admission persistence precedes paid work, failed persistence poisons admission, global one-active ownership, strict host/origin/body limits, closed static routing in API-only mode. Same-origin headers are intentionally not authentication; no additional authentication gate is required by the stated global pilot scope.

Isolation acceptance should inspect actual built images and network attachments: only search on the internal network with no published port; advisor also on the edge network; key mounted solely into advisor; neither website image nor website mounts receive the key, Lance addon or state directory. Use an unrelated outsider container, inspect mounts/env/image layers without printing credential contents, and exercise a second generic corpus through both tarball and HTTP. No public deployment or new key is needed.

## Cross-validation of request-ledger finding
Confirmed high severity: `preview-server.mjs:41` contains the persistent request-ledger reservation; `liveAnswer:51–59` does not. Direct answer injection bypasses that reservation and forgets previous attempts unless the new service wraps the raw answer with exactly one canonical reservation. Keep the existing preview path's guard unchanged to avoid double counting. Preflight that the existing request-ledger file exists: `request-ledger.mjs` otherwise automatically initializes absent state to zero. A container recreation test must seed different nonzero counts in admission and request ledger, then prove each increments exactly once for a paid attempt and still denies at its independent limit. Writable parent directory finding independently confirmed for both ledgers.
