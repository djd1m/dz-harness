# Owner-only browser preview: undeployed Caddy candidate

The adjacent Caddyfile is a candidate for a dedicated HTTPS hostname, using Caddy's built-in HTTP Basic authentication. It is not deployed. Supply `ADVISOR_PREVIEW_HOST` (DNS name pointing to this host, ports 80/443 reachable for ACME), `ADVISOR_PREVIEW_USER` and `ADVISOR_PREVIEW_PASSWORD_HASH` (bcrypt hash of a high-entropy password) through a protected deployment environment. Never put credentials in a URL, commit them, print them, or include them in logs. Use a unique strong password and remove access after the trial. Browsers cache Basic credentials; this has no server-side session or immediate individual session revocation, so rotate the credential or stop the service to revoke access.

The Caddy process must share the backend's network namespace so `127.0.0.1:8893` reaches the preview, which stays loopback-only. It authenticates all routes before proxying, rejects POSTs without the exact HTTPS Origin before rewriting Host and Origin to the values the loopback backend validates, and leaves the backend's CSP/noindex and no-store headers intact. Do not add request-body, authorization or prompt logging. Require HTTPS, preserve exact host routing, and disable any conflicting public listener. Only owner access is intended; this is not a multi-user identity or session system.

Before deployment, verify actual DNS, TLS and ACME setup, secret storage, network isolation, origin rejection, credentials on every route, host rewriting, no direct backend access, no prompt/credential logs, provider failures, one concurrent request and a persistent atomic trial-wide budget including restart/exhaustion. The gateway service MUST use `start-preview.py --gateway`, which refuses to start without an absolute ADVISOR_REQUEST_LEDGER path. The persistent ledger and HTTP failed-call/restart/exhaustion tests are implemented; ordinary loopback mode may still use the in-memory counter. Set a provider-side hard spending ceiling where available, set an expiry and record teardown. No live configuration was changed or public service started here.

The existing `/drafts/[token]` route is unrelated to this authentication; the historical Caddy snapshot is not a live configuration. HTTPS host, DNS and hash are deployment inputs, not reasons to invent an external identity provider.

## Backend service candidate

`advisor-preview.service` is an uninstalled template. Replace the checkout path if needed and create protected `/etc/aicoding/advisor-preview.env` with OPENROUTER_API_KEY, ADVISOR_REQUEST_LEDGER=/var/lib/aicoding/advisor-private-state/requests.json and optionally ADVISOR_FONTS_DIR. Create that state directory for the dedicated service account; the ledger file itself is created with mode0600. Keep backend on127.0.0.1; do not expose port8893. Configure the gateway separately with hostname/user/hash. No credentials are provided by this repository.

A normal shutdown releases the single-owner lock. SIGKILL or host failure can leave `<ledger>.lock`; startup then fails closed. Before manually removing ONLY this lock, stop the service and verify no owner process is running. Preserve `requests.json`: removing it resets the trial budget and must be a deliberate new-session decision. Corrupt state or a changed limit also fails closed. The ledger guarantees normal process-restart retention, not power-loss durability (no fsync claim). No automatic stale-lock deletion.

Deployment is a later explicit step: DNS/TLS/credentials, service-account filesystem permissions and actual firewall still need verification. Syntax and loopback gateway tests do not attest those conditions.
