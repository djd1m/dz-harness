# Private browser access: candidate design, not deployed

The existing site's `src/pages/drafts/[token].astro` creates static token-path drafts; `DRP/scripts/checks/109_drafts_headers.sh` verifies noindex, no-referrer and access-log treatment, not an authenticated paid API. Do not reuse a token URL as authentication. `DRP/caddy-live-snapshot.Caddyfile` is a historical snapshot, not proof of the live configuration. The existing loopback preview accepts one concurrent call and maintains a process-local request budget; restart resets it.

Candidate: dedicated HTTPS hostname with a trusted identity-aware access gateway. Authenticate an explicit allowlist before proxying any page, asset or API call. On successful login, gateway issues a short-lived Secure, HttpOnly, SameSite=Strict cookie, scoped to the dedicated host; no credential or bearer token in URL. Require exact expected Origin and a CSRF mechanism on POST; reject missing/cross-origin requests, cross-site forms and unauthorized requests before provider access. Browser holds no provider credential. Avoid requests or secrets in proxy/application logs; no request bodies in observability. Disable indexing and caching. Set an expiry and revoke access; stop the service after the trial.

Deploy only in a future isolated environment: firewall/private network prevents direct backend reachability; gateway forwards only to that backend and uses a deliberately configured trusted host and origin. The existing backend checks loopback host and origin, so an actual proxy must adapt or explicitly reconfigure those checks without trusting client-supplied forwarded headers. Define fixed request body limits, timeouts, one active provider call, a non-resettable trial-wide spend/call budget across restarts and a provider-side hard cap. Fail closed on missing auth, unavailable budget state or upstream error. This document does not select a vendor, create accounts, change site routing or expose a paid service.

Before any exposure, test unauthenticated and expired sessions, valid login/logout and revocation, cookie flags, hostile Origin and missing Origin, direct backend access, forged forwarding headers, concurrent requests, oversize bodies, budget persistence and exhaustion, upstream failure, log redaction, TLS and teardown. An independent security reviewer must verify actual deployed config and negative paths. No such test or deployment has been performed here.
