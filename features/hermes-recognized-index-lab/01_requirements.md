# Требования operator-only index lab

- FR-1: все verbs требуют synthetic workspace sentinel и явно заданный lab root; apply дополнительно требует `--execute --synthetic-confirm` и reviewed plan digest. CLI никогда не создаёт sentinel и защищает от случайного запуска на непомеченной карте; sentinel не является detector PHI.
- FR-2: по сохранённому core operation ID получить current `read/status` provenance, exact artifact SHA/bytes, source entry/hash/bytes, engine, `unverified`. Source/artifact drift, absent/incomplete/corrupt — отказ до index. Save/intake не вызываются ни при одном index outcome.
- FR-3: deterministic plan из exact immutable artifact path/bytes, core created_at UTC date, explicit bounded case slug, source anchor, `kind=machine-unverified`; expected `ha-doc-1` patterns/chunk hashes/plan digest. Не изменять и не копировать recognized artifact для индексирования.
- FR-4: существующий third-brain CLI whitelist не расширяется клиническим kind; lab вызывает проверенный JS `write.ingest` API напрямую. Apply не принимает `consultation|trend|synthesis|conclusion` для unverified текста. `kind=machine-unverified` есть в header каждого passage, presentation явно показывает `НЕПРОВЕРЕНО`.
- FR-5: полный readback через strict native readonly SQLite v2 snapshot с integrity/schema/size gates, без fail-open recall/JSON fallback. Exact multiset pattern/header/body/domain/type/reward, любые дубли и variants — conflict. Counters не равны receipt.
- FR-6: timeout/partial → unknown; reconcile вычисляет exact missing subset. Retry full deterministic ingest разрешён только когда existing records — строгий exact subset plan, нет extras/variants и observed source/artifact всё ещё valid; importer exact-pattern dedup проверен тестом. Иначе conflict/refusal без удаления чужих записей.
- FR-7: `search-known` выполняет реальный поиск по уникальному synthetic term, сверяет hit с expected pattern и current core provenance, выдаёт label `НЕПРОВЕРЕНО`; hit подтверждает только доступность известного фрагмента, не полноту/отсутствие других данных.
- FR-8: текущий `HealthTools.read` запрещает dot components; lab не расширяет blanket path access и не регистрирует Hermes tool. Возможный read-only adapter для exact `.machine-unverified/operations/<opid>/artifact.md` требует core status provenance и отдельной приёмки. Нет vector readiness, active revision, rollback/unindex, global transaction или production claim.
