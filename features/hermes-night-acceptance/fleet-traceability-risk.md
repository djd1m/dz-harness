## Границы, которые передаются risk/integration/regression ролям

1. **Restore → recognized rebind:** core fingerprint связывает workspace realpath/dev/ino. `c48c1a01` — snapshot до новых recognized операций; его 123/7 check не тестирует перенос `recognized/.machine-unverified` на другой inode/path. Нужен отдельный deliberate recovery/rebind contract и тест в изолированной среде до deployment. Не использовать простое копирование metadata как доказательство восстановимости.
2. **Consent transport:** adapter real ContextVars + fake/direct handler не доказывает получение `health-recognized-confirm` из Mattermost и передачу неизменного owner context. Production enable заблокирован до реальной транспортной приёмки.
3. **Index:** existing experiment PASS только для legacy synthetic doc и exact text multiset; parent FR-6 требует saved opid binding и managed retry. Новому lab нужен строгий readback backend; `dz recall --all` может дать `[]` при backend error. Его review pending, generic Hermes search hidden path запрещён.
4. **Cooperative locks:** новый core lock не включает legacy writers. Проверки source до/после обнаруживают наблюдаемый drift, но не ABA, постпроверочную гонку или глобальную транзакцию. Никакой автоматической promotion в `human_verified`/`indexed`.
5. **Parent process:** общий plan был дописан после отдельных административных проверок; index admission был после первого draft, что уже раскрыто в `06_implementation_plan.md`. Parent Step 9 четыре роли/синтез ещё не завершён; это один traceability вклад, а не «Fleet COMPLETE». Backlog add отказал из-за unreadable shared dz store; waiver в parent/adapter README, guard не ремонтировался. Финальный отчёт должен назвать это отклонение и точные HEAD/bytes каждого child.

## Решение этого вклада

Traceability для adapter synthetic slice достаточна для передачи на остальные роли Step 9. Parent имеет **open FR-6, FR-7, FR-8**, поэтому общий verdict остаётся **NEEDS_REMEDIATION / NOT YET ASSESSED AS FULL FLEET**. Я не провёл risk scoring 5×5, integration/regression execution или повторные тесты; эти части должны быть оформлены отдельно. Не выполнять production install, merge/publish или объявлять полную ночную приёмку на основании этого документа.
