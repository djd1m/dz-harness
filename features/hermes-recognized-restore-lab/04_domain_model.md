# Доменная модель restore lab

`ExportEvidence` — immutable synthetic snapshot + external descriptor/key; источник утверждения о старой операции, но не о человеке или полноте backup. `TargetWorkspace` — свежая private identity и exact source manifest/raw; один target принадлежит одному `RestoreBatch`. `OperatorAction` — explicit digest confirmation для нового действия, без заявленной внешней authority. `Mapping` — bijection old→new ID, зафиксированная до save. `CoreOperation` — новая unverified запись с новым tuple. `IntentEnvelope` — единственный durable журнал batch; `Seal` — проверяемая граница текущего offline readback.

Состояния item: `planned` (core вызов ещё невозможен) → `attempting` (вызов мог начаться) → `observed` (точные bytes/source + новый durability barrier подтверждены). `held` — неопределённость/отказ, без автоматического выхода. Batch: `planned` → `applying` → `sealed`; `held` блокирует seal. Transition пишет **весь envelope атомарно**; generation монотонна, immutable plan никогда не переписывается. `observed` не означает историческую durability прежнего core процесса.

Инварианты: (I1) каждый старый item имеет один новый ID и старые файлы остаются byte-identical; (I2) target identity и runtime closure одинаковы в plan, apply, reconcile, seal; (I3) save невозможен без durable attempting; (I4) observed невозможен без exact readback/fsync barrier; (I5) sealed требует observed всех items и повторной проверки; (I6) gateway receipt, index и activation отсутствуют во всех состояниях. Иной state, два batch, unknown generation или несоответствие digest — отказ, не repair.
