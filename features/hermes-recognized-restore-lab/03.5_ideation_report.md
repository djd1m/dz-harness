ADR-001, архитектура и план реализации текущей feature; сопоставлены замечания

что штатный core использует отдельный `.recognized-write` lock scope.
Код restore lab не проверялся и не запускался: эта оценка относится к дизайну.

**GO на реализацию ограниченного synthetic restore lab по текущей спецификации.**
Блокирующих пробелов W1–W5 в уточнённом контракте не осталось. Это не приёмка

## Закрытие замечаний и выбранные границы

| Замечание | Решение в текущем дизайне | Что обязательно подтвердить при QE |
| --- | --- | --- |
| W1: initial intent и неизвестный fsync | Immutable claim до initial intent, exclusive initial creation, fail-stop при неполном namespace; явный reconcile с тем же plan digest заново fsync-ит найденный intent и control directory, перечитывает их и проверяет items. | Crash и ошибка syscall до/после создания claim/intent; отсутствие доверенного intent не разрешает новый batch. При неизвестном результате не использовать прежнее in-memory состояние. |
| W2: recovered present без исторической durability | Для `attempting+present` отдельный reconcile делает exact readback, новый barrier core files/operation/parents и target sources, затем повторную проверку и durable observed. | Crash после core rename до parent fsync; observed невозможен без успешного нового barrier. Не называть этот барьер доказательством прежнего commit. |
| W3: target sources и копирование | Source-only target закрыт exact inventory, отличается identity, проходит no-follow/owner/mode/nlink и проверку совпадения bytes; file/directory/parent fsync до initial intent. | Подмена source, незавершённое копирование, aliases, чужой объект и изменение target identity вызывают отказ. Неподписанный marker не заменяет barrier. |
| W4: states/reconcile/idempotency | Полная матрица planned/attempting/observed/held/sealed; reconcile никогда не save; planned+present и attempting+absent дают held; sealed при drift не переписывается. | Все строки матрицы, прекращение batch после первой ошибки, отсутствие retry/нового ID, сохранность прежнего seal. |
| W5: схемы, mapping и атомарность | Exact schemas, явно перечисленные десять immutable fields, Python canonical JSON, big-endian length prefix, новые ID без reseed, воспроизведение projection из независимых входов при reopen. | Strict types/unknown fields/canonical bytes, mismatched mapping/runtime/source identity, overflow/count limits, ошибки atomic transition на каждом барьере. |

Локальная запись `actions` явно означает новый вызов apply/reconcile с
подтверждённым **полным plan digest**. Она не утверждает подпись, личность или
историческое согласие. Для этого synthetic scope отсутствие криптографической
подписи не является блокером. Старые gateway receipts остаются только исходным
свидетельством и не становятся рабочими квитанциями нового target.

## Единственность target lock

Замена произвольного external control root на фиксированный
`<target-realpath>/.restore-lab` закрывает возможность двух операторов одного
target выбрать независимые lock namespaces. Конкурент не должен продолжать
инициализацию root, созданного другим процессом: промежуточный root без готового
lock означает отказ. Lock имеет стабильный inode; flock удерживается на всём
apply/reconcile. Проверки claim/intent выполняются уже под этим lock. Создание
claim с `O_EXCL` предотвращает второй batch после crash до intent.

Это достаточная модель для cooperating offline процессов на выбранном local
filesystem. Same-UID hostile actor, произвольное перемещение roots и bind-mount
aliases исключены либо отказываются; lock сам по себе не доказывает production
freeze. При QE нужны два реальных процесса и паузы на mkdir/control fsync,
создании lock, получении flock и создании claim: один владелец либо безопасный
отказ, без второго save и без cleanup чужого namespace.

## Условия реализации, не новые разрешения

- Initial intent использует exclusive создание и не заменяет существующий файл.
  Замена разрешена только для проверенного существующего envelope под lock.
  Неполная первоначальная запись после crash остаётся отказом; её нельзя принять
  как «пустой новый batch» или автоматически дописать.
- При reopen наличие имени, generation или валидного JSON не доказывает исход
  предыдущего fsync. Неизвестное состояние принимается только отдельным новым
  reconcile и барьером; дальнейший apply не обходит это действие.
- При переходе первого item в attempting одновременно обновляются item и
  batch-state в одном envelope. Нельзя создавать промежуточную недопустимую
  комбинацию состояний или независимо писать mapping/seal.
- Source digest считается только по source inventory. Появление `.restore-lab`
  и разрешённого core scaffold не должно менять immutable source projection.
  При этом всё target дерево всё равно проверяется на лишние объекты.
- Source preflight до создания control root не исключает повторной проверки
  identity/source/namespace под полученным lock перед claim/intent/save.
- Для exact нового core tuple сравнивать ожидаемый request fingerprint и
  точные файлы/readback. Одного статуса present или совпавшего text hash мало.
- При потерянном барьере либо неизвестном результате subprocess прекращать
  batch. Невозможность durable записи held означает report unknown, а не
  разрешение запустить следующий item.
- Leftover temp, staging и core `store.lock` после crash — отказ для разбора.
  Наличие штатного scaffold после успешного save допускается только по точному
  профилю установленного runtime, без расширения разрешений на произвольные файлы.

Эти условия следуют из принятого здесь дизайна и должны быть проверены в коде;
документ не заявляет, что они уже реализованы. Для границ fault injection
достаточны process crash и отказы syscall в заявленной модели. Успех таких
тестов не доказывает физическую power-loss устойчивость оборудования.

## Итоговая граница GO

Разрешена дальнейшая реализация и последующая независимая QE синтетической
цепочки: подтверждённый новый план → новый target → новые ID → exact core
readback → новые durability barriers → локальный seal. До фактической проверки
нет утверждения, что данные уже восстановлены. Writer не активирует gateway,
индекс или карту; clinical verification, historical human approval,
production DRP и общий freeze живых stores остаются вне результата.
