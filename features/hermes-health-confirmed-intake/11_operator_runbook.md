# Эксплуатация подтверждаемого intake

## Состояние и согласие

HEALTH_INTAKE_STATE задаёт отдельный приватный каталог вне рабочей карты и Git. Он должен переживать перезапуск контейнера и входить в резервную копию вместе с ключом HMAC. Каталог принадлежит UID Hermes, права0700, файлы0600. Здесь временно сохраняются оригиналы, пакеты и receipts; это тоже медицинские данные.

HEALTH_INTAKE_WRITE_ENABLED=1 — явный флаг оператора. Без него confirm отказывает. Подготовка не требует включения записи. Ни флаг, ни receipt не заменяют проверку пользователя/канала: обработчик берёт их из ContextVars gateway. Из cron и процесса без связанного gateway-контекста подтверждение невозможно.

Попросите health_intake_prepare подготовить конкретное вложение. Точный дубль не создаёт receipt. Для новых файлов показываются хеши, пути, receipt_id и срок30мин. Для смешанного архива разделите старые и новые документы; автоматического частичного импорта нет.

Подтверждение — отдельная команда health-confirm с receipt_id, отмена health-cancel, состояние health-status. Эти операции не зарегистрированы как инструменты модели. В Mattermost стандартные slash могут перехватываться самим сервером; deployed adapter поддерживает сообщение с пробелом перед slash. В приватном канале dz-health проверен способ `@hermes-dz-health /health-confirm <receipt_id>`; префикс упоминания удаляется адаптером канала. Для DM этот способ не подтверждён. Доставку из конкретного клиента необходимо проверить до включения writer. Обычное сообщение «да» не подтверждает запись.

## Ограничения кандидата

- Оригиналы и manifest, без OCR, клинической проверки и автоматической индексации.
- Same-UID shell/root остаётся вне границы авторизации плагина.
- Любой неопределённый результат остаётся reconciliation_required; повтор не запускает новый intake.
- State quota ограничена64 receipts и256MiB. Очистка только оператором после проверки expired/cancelled/committed; неизвестные операции и их байты сохранять. Автоматического сборщика пока нет.
- Git push не сохраняет игнорируемые оригиналы, receipt state и индекс; требуется offsite backup.

## Обновление и откат

Перед заменой контейнера сохранить точный image ID, Compose и установленный каталог плагина в закрытом backup. Собрать health-advisor из исходников проверенного commit, сохранить SHA-256 tarball и image digest. Не подменять пакет ручными правками в публичном npm-зеркале.

После обновления: plugin doctor, validate, синтетическая офлайн приёмка, read-only сверка122 источников (число актуально на начало этой итерации), поиск и подтверждение фактического ответа через Mattermost. Только затем включать запись.

Откат конфигурации/образа отключает writer, но не удаляет принятые документы и не откатывает весь manifest. Если существует pending journal, старое ядро использовать для intake нельзя. Следуйте recovery runbook источника ядра; backup restore выполнять сначала в отдельный каталог.

Резервная копия должна включать releases с пакетом ядра, состоянием версии и плагином, а также скрипт backup. Локальный image ID не обеспечивает восстановление на другом хосте: нужен сохранённый образ или воспроизводимый доступный базовый образ.

## Архив точного образа медицинской установки

Для установленного кандидата сохранён закрытый архив
`/srv/hermes-dz-health/releases/confirmed-intake-20261109/image.tar.zst`
с соседним `image.tar.zst.sha256`. Архив содержит весь образ, включая базовые слои;
держать его вне Git, в зашифрованной резервной копии. Он не включает текущие тома
или runtime env — их восстанавливают из согласованного backup отдельно.

Проверенная последовательность загрузки (не запускает контейнер):

```bash
set -o pipefail
sha256sum -c image.tar.zst.sha256
zstd -t image.tar.zst
zstd -dc image.tar.zst | sudo docker image load
```

Ожидаемый ID:
`sha256:c872058e59ba94c4ee7af4389da04845b4ae029351fbd49da11492ba942e6961`.
Загрузка из архива проверена на текущем Docker daemon; чистый новый хост пока
не использовался. Compose запускать только после восстановления томов и секретов,
проверки прав и отсутствия второго писателя. Не запускать gateway тестовой копии
с рабочим Mattermost token.
