# ADR-001: Подтверждение снимка и явное восстановление незавершённой записи

## Status
Принято как проект; запуск записи не разрешается одним прохождением проектных проверок.

## Context
Preview0.2 не сохраняет долгоживущий пакет и не разрешает запись. Core intake1.10.8 дедуплицирует по логическому пути; raw rename и manifest rename раздельны. Hermes поддерживает зарегистрированные команды вне LLM, но Mattermost может перехватывать неизвестный slash на клиенте/сервере. Имя команды в документации не доказывает её доставку.

## Decision Drivers
Однозначное согласие пользователя, отсутствие новых дублей, сохранность оригиналов и статусов, явная неопределённость после сбоя, повторное использование ядра.

## Options
1. Добавить commit-tool с confirmed=true: отвергнуто, модель сама формирует аргументы.
2. После согласия запустить текущий CLI без дополнительных условий: отвергнуто, воспроизведены дубли и неконсистентный raw.
3. Сохранённый снимок + доверенное подтверждение gateway + условная запись ядра + reconciliation: выбрано.

## Decision
Подготовка сохраняет неизменный пакет и квитанцию. Команда подтверждения не является LLM-инструментом. Рандомный receipt_id — идентификатор, не право доступа. Один авторизованный пользователь и канал/профиль должны совпадать; fallback из произвольных process environment для identity запрещён. Привязка к thread не требуется, но ответ направляется в исходный тред; thread не заменяет user/chat.

Операции подтверждения сериализуются блокировкой квитанции, а операции записи карты — существующим lock ядра. Не держать дополнительный lock карты при вложенном захвате того же lock CLI. Состояние committing сохраняется и fsync выполняется до старта subprocess.

PDF получает стабильный путь documents/<полный_sha256>.pdf и детерминированный ZIP (дата, порядок, compression/attributes). Исходное имя сохраняется только как provenance. Для ZIP в первом выпуске разрешены лишь партии, полностью новые по хешам и логическим путям. All-duplicate — no-op с проверкой реальных источников, mixed/conflict — отказ целиком, без скрытого фильтрования архива.

У ядра нужен проверяемый условный write-контракт. Нынешний synchronous beforeCommit находится под lock перед raw rename, но пропускается idempotent fast path; он не может быть единственной проверкой прав или состояния операции. Публичный API ожидаемого manifest должен проверяться на всех ветках под lock. Финальную целостность подтверждать независимо от ok/idempotent.

Любое неопределённое завершение после старта записи блокирует автоматический повтор и переходит в reconciliation_required. Reconciliation под lock сравнивает manifest, raw и утверждённый список; допускает только доказанный committed либо доказанный no-change. Частичный raw без manifest сохраняется до ручного/журналируемого восстановления. Не удалять его автоматически.

Это контроль прикладного процесса, а не изоляция от агента с shell под тем же UID: такой агент способен обойти плагин и напрямую вызвать CLI. Для принудительного разграничения нужен отдельный writer service/UID с собственным approval endpoint. Это отдельное архитектурное изменение, а не скрытая гарантия плагина.

## Consequences
Нужны persistent receipts, защита места и сроков, проверка фактической доставки команды Mattermost и изменения общего ядра перед полным выпуском. Статусы verification не повышаются при совпадении хеша. Не обещаем ACID между raw и manifest без журнала восстановления.
