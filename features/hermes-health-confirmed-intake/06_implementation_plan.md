# План реализации

Текущий PR реализует только T1 и проект. T2–T6 — последовательная следующая разработка, не выполненные изменения.

- T1 (AC-1, ADR-001): воспроизвести контракты ядра синтетическим probe без сети и production mounts; сохранить результаты.
- T2 (FR-4, FR-5, FR-6, NFR-2): расширить source/release ядра проверкой expected manifest под общим lock на всех ветках, хеш-проверкой idempotency и явным журналом/сверкой частичной записи. Не менять tarballs публичного зеркала вручную.
- T3 (FR-1, FR-3, NFR-1): подготовка неизменного пакета, стабильные PDF-пути, exact duplicate/no-op, отказ mixed ZIP, persistent receipt с TTL/квотой.
- T4 (FR-2, AC-2): доверенный gateway confirm/cancel без LLM boolean; identity не берётся из tool args или environment fallback; проверить реальную доставку команды в Mattermost.
- T5 (FR-4, FR-5, FR-6, AC-2): commit orchestration, shared core lock, подтверждение результата, persistent unknown и reconciliation; повтор после перезапуска.
- T6 (AC-2, NFR-1, NFR-2): изолированная приёмка, rollback только версии адаптера; пилот технического документа с отдельным согласием, затем включение writer.

## Проверки до выпуска

| Сценарий | Требуемый результат |
|---|---|
| Другой user/chat/profile, cron, отсутствующий gateway context | Отказ до запуска ядра |
| Модель передала confirmed=true | Нет такой операции записи/tool |
| Просроченная/изменённая квитанция или пакет | Отказ и новая подготовка |
| PDF переименован при повторной загрузке | Точный дубль, без новых файлов |
| Mixed ZIP, одинаковый path с другими байтами | Отказ всей партии |
| Изменился manifest между prepare и confirm | Отказ под общим lock |
| Два confirm одной квитанции | Один write, одинаковый подтверждённый результат |
| Конкурирующий штатный CLI intake | Сериализация общей блокировкой |
| Сбой до raw rename | Доказано отсутствие новых raw/manifest |
| Сбой после raw rename или после manifest rename | unknown до сверки, без слепого повтора |
| idempotent=true при повреждении исходника | Drift, не успех |
| Перезапуск между committing и ответом | Состояние сохранено, выполняется сверка |
| Успешный commit | SHA-256, entry_id, ссылки и статусы проверены; --verify чист |
| OCR/индексирование не запускались | Это явно отражено в ответе |

Rollback отключает новую запись и возвращает предыдущую версию плагина. Принятые документы не удаляются, manifest целиком не заменяется старой копией. До pilot эти gates должны быть выполнены, а не только перечислены.
