# Извлечение текста и черновики: архитектура кандидата

## Решение

Оригинал разрешается по entry_id через manifest, читается без symlink и проверяется
по размеру/SHA-256. Модель не выбирает путь, движок, image или параметры запуска.
Парсер работает в одноразовом контейнере без сети, capabilities, томов и секретов;
ограничены память, CPU, число процессов, размер входа/выхода и время.

Hermes не получает Docker socket. Узкий host broker слушает только приватный Unix
socket; принимает только ограниченные PDF-байты. Он запускает один закреплённый
образ и возвращает JSON. Broker имеет доступ к Docker и потому относится к
доверенной административной части; это не граница защиты от администратора хоста.
Одновременная обработка последовательная, чтобы ограничить расход ресурсов.

Альтернативы: парсер в процессе Hermes (отвергнут: доступ к секретам и карте);
bubblewrap внутри рабочего контейнера (не выбран: зависит от user namespaces и
профиля контейнера); прямой Docker socket в Hermes (отвергнут: полномочия хоста).

После ответа broker адаптер валидирует схему и повторно сверяет оригинал.
MD/HTML создаются в приватном постоянном каталоге черновиков вне карты; тексты
экранируются/оформляются как данные. Каждый документ содержит entry_id и SHA-256,
версию движка и явную отметку «не проверено человеком». Клинические статусы,
recognized и индекс не меняются. Пустой текст не считается распознанным сканом.

## Проверки до установки

Синтетические PDF: русский текст, смешанные страницы, шифрование, повреждение.
Отказы: лимиты, timeout, неверный broker payload, подмена/изменение исходника,
symlink в пути черновиков. Реальный контейнер: network=none, readonly, no mounts,
nonroot, NNP и cgroup limits. Проверить уничтожение контейнера при timeout.
До независимого QE кандидат не устанавливается в рабочий Hermes.
