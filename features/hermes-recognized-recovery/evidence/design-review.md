# Независимая проверка дизайна

2026-11-10. Проверена версия дизайна `08f73fe`: требования, ADR-001,
архитектура, план реализации и отчёт о проработке решений. При предыдущей
проверке изучены фактические core `recognized-store.js` и adapter
`recognized_confirm.py`. Незавершённый исполняемый код здесь не проверялся,
тесты реализации не запускались.

**GO для указанного синтетического проверяющего инструмента только для чтения.
Блокирующих пробелов дизайна в этих границах не выявлено. HOLD на инструмент
записи при миграции и активацию сохраняется.**

| Граница | Оценка дизайна |
| --- | --- |
| B1 | Внешний дескриптор закрепляет точные байты inventory, идентификатор снимка, независимый digest ключа и ожидаемые owner/runtime. Отдельный защищённый вход с исходным ключом и явные ограничения утверждений о происхождении дают достаточную модель доверия для синтетического эксперимента. При отсутствии ключа обходного пути нет; общий отказ целостности для неверного ключа/MAC консервативен. |
| B2 | Допускается только завершённое состояние `saved_unverified` с булевым `artifact_observed=true`, при взаимно однозначном соответствии операций и квитанций. Канонические байты core и кортеж запроса отделены от канонического содержимого HMAC adapter. Явно связаны историческая идентичность workspace, логический путь manifest и адрес raw, байты source/artifact и engine. TTL не даёт новых полномочий. |
| B3 | Дизайн явно определяет ограниченный экспорт, а не полную резервную копию хранилищ. Исключённые объекты key/lock/pending/staging/draft/LOG вызывают отказ, а не очистку. Создание тестовых данных без работающих процессов записи задано как допущение; одновременная остановка записи в production не заявляется. |
| B4 | Обход относительно файловых дескрипторов без следования по ссылкам, доверенные родительские каталоги, проверки owner/mode/nlink, закрытый набор с учётом каталогов и ограниченные вход/выход соответствуют выбранной модели угроз чтения. Враждебное изменение другим процессом с тем же UID исключено из модели. Отказ от target и mapping предотвращает преждевременные утверждения о владении целевым деревом или защите от повторного применения. |

Независимая проверка реализации должна подтвердить дизайн, а не выводить
корректность реализации из наличия документа:

- Проверить строгие типы и полные фактические схемы manifest/receipt/sidecar,
  включая вычисление entry ID, конечные числовые значения времени и допустимые
  временные метки core.
- Использовать строки artifact/metadata с символами вне ASCII и точные байты
  переводов строк для проверки сериализации JS и кодирования adapter на Python;
  неподдерживаемые формы JSON должны вызывать отказ без скрытой нормализации.
- Пересчитывать inventory, доверенный digest и при необходимости HMAC для
  семантических негативных примеров, чтобы тесты доходили до нужной проверки связей.
- Проверить недостающие и лишние каталоги и файлы, альтернативные пути к тем же
  корневым и родительским каталогам, небезопасные специальные файлы и каждое
  запрещённое состояние или значение флага квитанции.
- Доказать отсутствие вызовов записи, adapter status/reconcile, дочерних процессов
  и сети; проверить неизменность входных байтов, состава деревьев, режимов доступа
  и mtime. Не заявлять неизменность atime без отдельной политики файловой системы.
- Подтвердить ограниченный размер каждого результата и отсутствие чувствительных
  данных при обязательном `executable:false`; некорректный вход не должен раскрывать
  текст, пути, owner, key/MAC или частичный план применения.

Неблокирующее замечание к формулировке: ADR-001 сначала описывает поля записи
без перечисления `type`, но сразу требует явный тип, а архитектура задаёт полные
точные наборы полей. Архитектура устраняет неоднозначность; это не блокер.

Это текстовая оценка дизайна, не машинная контрольная проверка и не результат QE
реализации. Проверка не устанавливает K1. B5 — долговечность записи и seal,
production DRP, историческое подтверждение человеком и остановка записи во все
живые хранилища — остаются недоказанными.
