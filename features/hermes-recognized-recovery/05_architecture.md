# Архитектура read-only verifier

`CLI → private fd reader → trusted descriptor/key → strict inventory closure → actual core/adapter formats → semantic bindings → sanitized validation report`.

## Trust boundary и namespace

Три обязательных аргумента указывают export directory, external trusted descriptor file и external original key file. Все absolute paths; никакой path из snapshot не используется до проверки relative grammar. Descriptor/key не находятся в export, roots не вложены и не alias по `dev/ino`. Путь от filesystem root до private boundary проходит только через no-follow directories, которые либо принадлежат trusted system и не доступны для записи посторонним, либо принадлежат effective UID и не доступны для записи группе/прочим; ниже boundary private directories `0700`, owned effective UID, files `0600`, regular, `nlink=1`. Все компоненты открываются `dir_fd` без follow. Нужна проверка фактического fd, не одна `Path.resolve`; subtree обходится fd-relative. Открытый fd читается один раз до лимита, size сравнивается с `fstat`, digest считается на прочитанных bytes. Структура сверяется с inventory в обе стороны, включая пустые directory entries. No same-UID adversary guarantee.

Descriptor exact fields и строгие формы определены ADR-001. SHA-256 exact `inventory.json` bytes равен `inventory_sha256`, SHA-256 32 key bytes равен `key_sha256`. Эти сравнения идут до доверия к entries. Descriptor и key никогда не ищутся внутри export. `snapshot_id` должен совпасть descriptor/inventory; он не выводится как идентификатор нового target.

## Inventory и limits

Inventory — strict UTF-8 JSON, без duplicate/unknown keys, NaN/Infinity, surrogate/NUL и чрезмерной глубины. Closed object `{schema,snapshot_id,entries}`, entries — sorted unique list с явным `type` (`dir` или `file`). File `{type,path,bytes,sha256,mode}`, dir `{type,path,mode}`; mode — integer `384` (`0600`) для file и `448` (`0700`) для dir. `inventory.json` исключён из entries, но обязан быть фактическим файлом root; root directory имеет неявную membership и проверенный mode. Каждая промежуточная directory обязана иметь entry. Path — slash-separated POSIX relative, ASCII-safe canonical components (буквы/цифры/`._-`), без `.`, `..`, пустого компонента, leading/trailing slash, backslash или control; reserved names не принимаются. Exact export profile из ADR-001 дополнительно ограничивает допустимые имена; arbitrary safe-looking extra file запрещён.

Пределы ADR-001 применяются **до выделения больших структур**. JSON nesting до 32, суммарно JSON parse input до соответствующего file limit; report до 4 KiB, `refusal_codes` до 8 уникальных кодов. При превышении — один фиксированный limit refusal. Total listed bytes до 128 MiB, 1–32 operations. Никакого текста документа, абсолютного пути, owner/runtime/key/MAC в JSON, stdout или stderr; исключения преобразуются в фиксированные коды. Exit 0 только `valid=true`.

## Семантическая проверка

1. Parse `sources/manifest.json` с exact schema `ha-intake-manifest-1`, closed rows для выбранного профиля. Для каждой строки есть один raw file по `stored_at`, и наоборот; canonical location под `workspace/sources/raw/`. `row.path` — логический путь, `row.stored_at` — физическое относительное расположение. Уникальны `entry_id`, logical path и stored_at. Содержимое raw совпадает с `row.sha256/bytes`.
2. Для каждой `rc-<32 lowercase hex>` операции есть exact directory и `artifact.md`, `metadata.json`, одна receipt `<id>.recognized.json`; иных операций/receipt нет. Metadata строго совпадает с JS `JSON.stringify(meta)+'\n'` (insertion order, compact), имеет exact core keys/schema `ha-recognized-operation-1`, tuple из 14 элементов и `request_sha256=SHA256(JSON.stringify(tuple))`. JS serializer нужно воспроизвести для допустимого подмножества JSON, включая number/string encoding; noncanonical/unsupported forms отказываются. Artifact — nonempty valid UTF-8 без NUL, SHA/byte count равны tuple[10:12], engine равен sidecar и ровно `pypdf/7.0.0`. Core `verification_status=unverified`, `content_trust=untrusted_document`; created_at соответствует core timestamp grammar.
3. Receipt envelope имеет exact `payload/mac`; duplicate/unknown fields отвергаются. MAC — lowercase hex HMAC-SHA256(key, Python adapter `encode(payload)`) с `ensure_ascii=False`, sorted keys, compact separators; constant-time compare. Payload имеет exact adapter fields/schema, `proposal_id=operation_id=id`, `state=saved_unverified`, `artifact_observed=true`, exact owner/runtime external descriptor, finite clock fields и exact sidecar schema. Sidecar draft hash/bytes равны artifact; sidecar workspace равен receipt workspace и tuple `[2:5]`; engine равен tuple `[12:14]`.
4. Tuple `[6]` равен source `entry_id`, `[7]` равен **manifest `row.path`** и sidecar `source.logical_path`; sidecar `source.path` равен **manifest `row.stored_at`** (без export prefix; это workspace-relative адрес). Tuple `[8:10]`, sidecar source sha/bytes и raw bytes равны row. `row.path` и `stored_at` не подменяют друг друга. Все IDs, source bindings и workspace identity сопоставляются как exact values, без нормализации исходного historical path.

Verifier не вызывает core CLI, Hermes, subprocess, network или writers. `valid=true` и `executable:false` вместе; выход не содержит target или mapping. Copied snapshot на новом inode проходит при тех же bytes, но старый core direct-read на новом workspace остаётся неприменимым. Межstore freeze и B5 seal этим не доказаны.
