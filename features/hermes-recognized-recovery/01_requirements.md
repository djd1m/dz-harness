# Требования

FR-1: Read-only проверка закрытого синтетического snapshot на новом пути с внешним ожидаемым SHA-256 inventory и отдельно переданным исходным HMAC ключом. Никаких загрузок, сети или запуска core save.
FR-2: Полная проверка набора файлов, размеров и SHA-256 с ограничениями ресурсов; неизвестные версии, лишние/недостающие объекты, symlink/hardlink, unsafe permissions и traversal отвергаются.
FR-3: Проверять реальные форматы core metadata/tuple и adapter receipt/HMAC, exact source/artifact/sidecar/workspace/operation binding. Принимать только saved_unverified + artifact_observed=true. Все остальные состояния отвергать, TTL не превращать в новое согласие.
FR-4: Выдавать только ограниченный отчёт с digest и счётчиками; без текста документов, абсолютных путей, владельца, HMAC или ключа. Успех не означает право записи, активацию, медицинскую достоверность или историческое доказательство согласия человеком.
FR-5: Проверка на реальном синтетическом формате и негативных fixtures: подмена inventory, MAC, tuple, source, смешение состояний, неизвестные/повторные поля и нарушение пути. Все snapshot байты остаются неизменными.
NFR-1: Offline fixture без writers; hostile same-UID, историческая полнота backup и общий freeze production не доказаны. Проверка не меняет provenance старых операций и не создаёт новую квитанцию.
AC-1: Повтор на скопированном snapshot проходит при сохранённых байтах независимо от нового inode, но старый core direct-read остаётся привязан к старому workspace. Результат verifier — информационный, не executable plan.
