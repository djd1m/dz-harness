# Медицинские инструменты Hermes — версия 0.1

Нативный плагин предоставляет три инструмента чтения и навык `hermes-health:health-read`.
Это первая итерация: intake, запись карты, распознавание PDF, клиническая верификация и
отправка вложений остаются функциями рабочего агента/CLI, а не этого плагина.

Каталог находится вне `packages/`: опубликованные npm tarballs и MIRROR-MANIFEST не меняются.
Это предложение отдельной интеграции для публичного зеркала, не опубликованный npm-пакет.
Существующий `adapter-hermes` можно использовать для переноса остальных навыков;
он не реализует регистрацию этих инструментов. Общее ядро health-advisor не меняется.

## Проверенная конфигурация

Linux, Python 3.14 (unit-тесты также Python 3.12), Hermes 0.22.2, Node 22.23.4,
health-advisor 1.10.8, harness-cli 0.7.5, harness-core 0.5.4, better-sqlite3 11.10.0.
Другие сочетания требуют повторной интеграционной проверки. Нативный SQLite binding
должен быть собран под тот Node, который задан в HEALTH_NODE.

## Установка в тестовую среду

Скопируйте **этот каталог**, включая skills, в `$HERMES_HOME/plugins/hermes-health/`.
Используйте отдельный HERMES_HOME, тестовую карту и отдельного бота; токен production не копируйте.

```bash
export HEALTH_WORKSPACE=/absolute/path/to/test-medical
export HEALTH_NODE=/opt/health-node22/bin/node
export HEALTH_RUNTIME=/opt/health-advisor-runtime
hermes plugins doctor "$HERMES_HOME/plugins/hermes-health"
hermes plugins validate "$HERMES_HOME/plugins/hermes-health" --json
hermes plugins enable hermes-health
```

HEALTH_RUNTIME содержит node_modules/@dzhechkov/health-advisor,
node_modules/@dzhechkov/harness-cli и собранный node_modules/better-sqlite3.
Устанавливайте зависимости заранее: плагин не скачивает пакеты и не обновляет их.
После включения запустите новую сессию Hermes. При явных списках toolsets добавьте
`hermes_health` в конфигурацию соответствующего интерфейса и проверьте видимость трёх инструментов.

Настройки задаёт оператор через окружение процесса, они не принимаются как аргументы инструмента.
Директория workspace и её родительские каталоги должны находиться под управлением оператора.
Для отката отключите `hermes-health` и перезапустите соответствующий процесс; том карты сохраняется.

## Контракты

- `health_search(query, limit=5)` — полнотекстовый CLI-поиск только по `.health-brain`.
  Перед выдачей passages сверяется хеш текущего документа. Устаревший источник даёт ошибку.
  DB+WAL читаются дважды и должны совпасть; SQLite Backup API и CLI работают на приватной
  временной копии. При активном изменении индекса возвращается `index_busy_retry`.
- `health_source_get(entry_id=...)` либо `health_source_get(path=...)` — оригинал из manifest
  или документ разрешённого каталога. Для manifest обязательно совпадение размера и хеша.
  Текст ограничен 12000 символами; для бинарного оригинала возвращаются только метаданные.
- `health_validate()` — размеры и SHA-256 **перечисленных** записей manifest. Не заменяет
  полную `health-advisor intake-archive --verify`: не ищет неучтённые raw-файлы и не проверяет
  клиническую интерпретацию или достоверность самого manifest.

Все ответы содержат `ok`; ошибки — стабильный код без содержимого stderr.
`human_verification=not_established`: хеш никогда не превращает результат в проверенный человеком.
Даты и клинические статусы следует брать из самого документа/структурированного профиля.
Документный текст недоверенный: инструкции внутри документов не исполняются.

Лимиты: файл 32 MiB, manifest 8 MiB/10000 строк, суммарная проверка 512 MiB/20 секунд,
DB и WAL по 128 MiB, subprocess 25 секунд/2 MiB stdout+stderr, 10 поисковых результатов
по 6000 символов. Превышение даёт ошибку, не неполный успешный отчёт. Проверка времени
между файловыми чтениями не прерывает блокирующее чтение неисправного файлового устройства.
Поиск временно хранит до нескольких копий индекса, требуется запас RAM и локального tmp.
Конкурирующая враждебная замена родительского workspace и изменения ядра CLI вне закреплённого
окружения не входят в модель защиты; symlink в запрашиваемых путях запрещены.

## Проверки

```bash
python3 -m unittest discover -s integrations/hermes-health/tests -v
# В подготовленном изолированном health runtime, без сети и production volumes:
python3 /plugin/tests/integration_check.py
```

Интеграционный тест создаёт синтетический документ и индекс через настоящий CLI, находит источник,
сверяет SHA-256, проверяет отказ при изменении источника и неизменность исходного workspace.
Дополнительно запускаются настоящий `hermes plugins doctor` и `hermes plugins validate`.
Все фикстуры генерируются во временных каталогах. Медицинские данные и credentials не включены.
