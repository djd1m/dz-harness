# Независимый QE: изолированный PDF → текст

Дата: 2026-11-09. Вердикт: **PASS только для автономного эксперимента на синтетических PDF**. Разрешение на production, регистрацию инструмента или работу с медицинским хранилищем этот обзор не даёт. Implementation QE не менял; найденные проблемы исправил кодер.

## Исправленные замечания

1. **Блокирующее: уязвимый pypdf 6.1.1.** Официальный [GHSA-j543-4vmf-qm7v](https://github.com/py-pdf/pypdf/security/advisories/GHSA-j543-4vmf-qm7v) описывает расход памяти при извлечении текста и затрагивает версии до 6.12.2. Более свежий [GHSA-59jv-x5x2-gg4c](https://github.com/py-pdf/pypdf/security/advisories/GHSA-59jv-x5x2-gg4c) затрагивает версии до 7.0.0. Итоговый requirements закрепляет 7.0.0, worker отвергает другую версию до разбора PDF. Соответствие [официальному релизу 7.0.0](https://github.com/py-pdf/pypdf/releases/tag/7.0.0) проверено. Лимиты ресурсов не были приняты как замена обновлению. Это не полный аудит всех зависимостей и не утверждение об отсутствии неизвестных уязвимостей.
2. **Нарушение лимита ответа.** В исходном варианте entry_id из 128 NUL давал JSON 1057 байт при лимите 1024 даже после status=output_limit. Итоговый ASCII allowlist отвергает такой идентификатор; регрессионный тест проходит.
3. **Ложная полнота смешанного документа.** Первоначальный ok при наличии текста только на части страниц заменён на partial_text; каждая страница имеет text_status. README явно ограничивает смысл ok: непустой текст на каждой странице не доказывает полноту или точность извлечения.

## Независимая проверка

Финальный запуск `.venv/bin/python -m unittest -v test_probe.py`: **16/16 PASS**, 1,645 с. Покрыты русский текст, две страницы, происхождение по SHA-256, повторное чтение без изменения содержимого/mtime, пустая страница, изображение без текста, смешанные страницы, шифрование, повреждение, смена источника, лимиты входа/страниц/вывода/времени, отсутствие движка, symlink, валидация параметров и HTML escaping.

Дополнительные независимые проверки без изменения implementation:

- При memory_bytes=1 и 16 МиБ возвращается resource_limit, а не ok.
- Максимальный разрешённый entry_id длиной 128 ASCII символов с коротким синтетическим текстом даёт JSON 528 байт при лимите 1024.
- Строка `</pre><img src=x onerror=alert(1)>` не выходит из экранированного блока render_html.
- В отдельном процессе подмена объявленной версии движка на 6.1.1 даёт unsupported_engine_version с пустыми pages до чтения PDF. Это проверка ветки контроля версии, не установка старой зависимости.

Все PDF для проверок созданы синтетически. Медицинские файлы и секреты не читались. Файлы окружения .venv рекурсивно не просматривались. Проверка поведения при малой памяти не заменяет стресс-тестирование всех вариантов PDF-бомб; нагрузочные PoC известных CVE не запускались.

## Границы результата

Оригинал открывается read-only; парсер получает ограниченный снимок через memfd после проверки ожидаемого SHA-256. Provenance относится к этому снимку. entry_id и ожидаемый хеш поступают от вызывающей стороны и сами по себе не подтверждают владельца или авторизацию. Результат остаётся draft/unverified, страницы нумеруются, PDF-инструкции обрабатываются как данные; весь JSON экранируется в HTML.

Ограничения CPU/адресного пространства/вывода и родительский таймаут уменьшают ущерб от ресурсоёмкого разбора. Это **не ОС-песочница**: права пользователя, сеть и файловая система не изолированы. Таймаут не охватывает чтение оригинала родителем; проверка числа страниц происходит после разбора их дерева. CLI допускает произвольный обычный файл и промежуточные symlink, поэтому не является границей доступа. Эти ограничения явно описаны в README и приемлемы только в заявленном синтетическом эксперименте.

no_text не отличает скан от пустой страницы; OCR отсутствует. ok не удостоверяет порядок чтения, таблицы, единицы, скрытый/пропущенный текст или медицинскую точность. Гарантия неизменности относится к содержимому и mtime, чтение может обновлять atime. Тест отсутствия движка зависит от текущего состояния /usr/bin/python3.

Полный feature-adr workflow здесь не проверялся. По сообщению координирующего агента, dz recall получил UNREADABLE sharedstore, name-check завершился exit 2 без сканирования workspace; эти проверки не имеют статуса PASS. Регистрация инструмента запрещена; обзор касается только файлов эксперимента.
