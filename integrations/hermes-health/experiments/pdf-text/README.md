# Изолированный прототип PDF → текст

Эксперимент не зарегистрирован как инструмент Hermes, не подключён к intake, не читает медицинское хранилище, не выполняет OCR и не записывает результаты в профиль. Все тестовые PDF синтетические и создаются внутри каталога эксперимента. Проверены 16 тестов на Linux / Python 3.12.

## Запуск

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m unittest -v test_probe.py
.venv/bin/python probe.py ./synthetic.pdf --entry-id synthetic-entry --sha256 <SHA-256>
```

CLI предназначен только для автономной проверки синтетических файлов. Путь и ожидаемый хеш передаёт оператор. Это не авторизация по entry_id: будущая интеграция обязана самостоятельно разрешать entry_id через доверенный реестр, проверять владельца и разрешённый корень, не принимать произвольный путь или хеш от модели. Сейчас в интеграции такой endpoint отсутствует.

## Контракт и ограничения

Результат JSON содержит entry_id, expected_sha256, source_sha256 (если удалось прочитать ограниченный снимок), engine/name/version (если движок был запущен), pages с number/text/text_status, status, derived_status=draft и human_review=unverified. При ошибке частичный текст отбрасывается. SHA относится к байтам снимка, переданного процессу; последующие изменения оригинала требуют новой сверки. Повтор не меняет содержимое и mtime оригинала, но обычное чтение ОС может обновлять atime.

Статусы: ok, partial_text, no_text, encrypted, invalid_pdf, engine_unavailable, unsupported_engine_version, source_error, source_changed, input_limit, page_limit, output_limit, timeout, resource_limit, worker_error. no_text не позволяет доказать, что страница — скан; пустой PDF даёт тот же статус. Наличие текста на одной странице не означает наличие текста на остальных; пустые страницы явно присутствуют в pages с text_status=no_text. partial_text означает смешанные страницы с текстом и без текста. ok означает непустой текст на каждой странице, но не полноту или точность извлечения. entry_id ограничен 128 символами ASCII: буквы, цифры, точка, подчёркивание, двоеточие, дефис; управляющие символы запрещены, чтобы служебный JSON укладывался в минимальный лимит.

По умолчанию: вход 8 МиБ, 50 страниц, JSON-результат 1 МиБ, дочерний процесс 5 секунд wall-time, 256 МиБ адресного пространства, 5 секунд CPU. Значения Limits управляются вызывающим кодом и должны оставаться доверенной конфигурацией. Лимит страниц проверяется после чтения дерева страниц; его разбор и распаковка потоков ограничены CPU/памятью. Wall-time относится к дочернему процессу, не к чтению обычного файла родителем. Сигнальное завершение классифицируется как resource_limit без утверждения о конкретной причине. Отсутствующий движок не считается повреждением PDF.

Родитель открывает только обычный файл, отклоняет конечную символьную ссылку и специальные файлы, читает не больше input_bytes+1 и сверяет SHA-256. Промежуточные символьные ссылки не запрещены: CLI не является файловой границей безопасности. В дочерний процесс передаётся снимок через Linux memfd без пути оригинала. Вывод читается с жёстким ограничением; таймаут завершает процесс. RLIMIT_AS/CPU/FSIZE/CORE ограничивают ресурсы. stderr подавлен, диагностические исключения с содержимым PDF не возвращаются. Временных файлов с PDF нет. render_html экранирует весь JSON; найденные инструкции остаются обычным текстом.

Это не ОС-песочница: процесс работает с правами пользователя, не изолирует сеть и файловую систему; RLIMIT_FSIZE=0 не запрещает все мутации (например, открытие с усечением). Код прототипа ничего не пишет кроме stdout, но защита от эксплуатации уязвимости парсера требует отдельного непривилегированного контейнера с read-only rootfs, отсутствием сети/секретов, seccomp и внешними лимитами. Не запускать на недоверенных реальных документах как production-сервис.

## Движок

pypdf 7.0.0 закреплён и проверяется самим worker: другая версия даёт unsupported_engine_version. Выбран официальный [релиз 7.0.0 от 6 ноября 2026](https://github.com/py-pdf/pypdf/releases/tag/7.0.0), включающий исправления безопасности. Ранний проверочный pin 6.1.1 отклонён после независимого обзора: [GHSA-j543-4vmf-qm7v](https://github.com/py-pdf/pypdf/security/advisories/GHSA-j543-4vmf-qm7v) затрагивает извлечение текста до 6.12.2. Ограничение ресурсов не заменяет обновление. Полный аудит всех advisories не выполнен; отсутствие уязвимостей не заявляется. В базовом локальном Python pypdf отсутствовал. Пакет установлен только в .venv эксперимента, production-образ не изменён.

[Официальная документация pypdf 6.1.1](https://pypdf.readthedocs.io/en/6.1.1/user/extract-text.html) подтверждает интерфейс extract_text(), отсутствие OCR и риск большого расхода памяти на распаковку контента. Поэтому предусмотрен отдельный ограниченный процесс. Прототип не гарантирует порядок чтения сложной вёрстки, корректность таблиц, единиц или медицинскую точность. Шифрованные документы отклоняются без попытки подобрать пароль.

## Проверки

Русский Unicode через синтетическую ToUnicode-таблицу, две страницы, SHA provenance, повтор и неизменность оригинала, изображение без текста, пустая страница, шифрование, повреждение, изменённый источник, лимиты входа/страниц/вывода/времени, отсутствие движка, отклонение symlink, невалидные лимиты и экранирование HTML. Тест отсутствия движка использует /usr/bin/python3 без pypdf; при изменении системного окружения его потребуется адаптировать. OCR, индексация, вложения MD/HTML, сетевое и производственное подключение не реализованы.
